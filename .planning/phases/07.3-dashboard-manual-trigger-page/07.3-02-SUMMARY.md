# Phase 07.3 Plan 02: Delivery Buffer + Source-Agnostic Header Redaction Summary

Stand up the in-memory webhook delivery ring buffer plus the source-agnostic header sanitizer that the dashboard's "Recent webhook deliveries" panel (UI-02) consumes, and extend `receiver.Deps` with two optional fields so the per-request pipeline records every delivery without coupling to the events broadcaster.

### Two-step RedactHeaders sanitization

`RedactHeaders` applies BOTH transformations in order:

**Step 1 — header NAME sanitization (M4 XSS defense-in-depth):** Compile-once regex `^[A-Za-z0-9-]+$` validates each header name against the RFC 7230 token charset (subset). Names containing `<`, `>`, `"`, `/`, space, or any non-token byte are dropped entirely. A malicious webhook with header name `X-<script>alert(1)</script>: bad` cannot reach the SSE payload.

**Step 2 — header VALUE redaction:** For surviving (well-formed-named) headers, the lowercased name is substring-matched against `{authorization, secret, token, key, signature}`. Match → value replaced with `<redacted>`. No match → value joined via `, ` if multi-valued, then truncated by `TruncateValue` (80 chars + ellipsis).

Source-agnostic by design — no provider-specific strings in the substring list.

### `recordDelivery` wiring in handler.go

| `PayloadSummary` | `deliveries.SummarizePayload(r.Header.Get("Content-Type"), bodyBytes, 200)` |

| `WorkflowIDs` | `append([]string(nil), rec.workflowIDs...)` (defensive copy) |

### TestSourceAgnosticRenderer firewall (active)

Walks every `.go` file under `pkg/cli/server/web/` (excluding `_test.go`) and scans for these banned strings:
- `X-GitHub-Event`
- `X-GitHub-Delivery`
- `X-Hub-Signature-256`
- `X-Hub-Signature`
- `Stripe-Signature`
- `X-Slack-Signature`
- `x-amz-sns-message-signature`

Comments (`//` lines) are allowed (so package docs may reference banned names for context). Code references trigger `require.Empty(violations, ...)` failure with `file:line:` precision via `fmt.Sprintf("%d", lineNo+1)` — NO hand-rolled `itoa` helper.

**Non-vacuous defense:** A second walk over `examples/http-github-webhook/extensions/github/` (the github source factory's real location) asserts at least one banned literal exists where allowed. If the github factory ever moves and zero banned literals remain in that tree, the firewall fails loudly instead of silently passing. `filesScanned > 0` defends against an empty `web/` tree producing a vacuous pass.
