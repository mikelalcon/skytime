### Task 2 — Strict SSE shutdown-frame assertion

`TestServerCmd_DrainOnSIGTERM` was extended with a subscribe-then-shutdown flow:

1. Before SIGTERM is dispatched, the test captures the OS-resolved listener addr via the new `testListenerAddrFn` seam (since `--addr=127.0.0.1:0` is used) and opens an in-process HTTP GET against `/api/events`.
2. A goroutine scans the response body line-by-line via `bufio.Scanner`, extracts `event: <name>` frames into a channel, and signals `__closed__` on EOF.
3. The first frame is asserted to be `snapshot` (D-7.3-05 spec).
4. SIGTERM is sent.
5. The test polls the channel for up to 5 seconds. If `event: shutdown` arrives, `sawShutdownFrame` flips true and the assertion succeeds. If `__closed__` arrives FIRST, `require.Fail` triggers with a diagnostic naming `D-7.3-07 + B3` and the `grep -n 'webResult.Shutdown|srv.Shutdown' pkg/cli/server.go` debugging hint.

The earlier permissive `OR __closed__` clause is REMOVED — a connection close without a shutdown frame is now an explicit failure, catching the regression mode where a future reorder breaks B3.

The supporting `pkg/cli/server.go` change adds `testListenerAddrFn` (package-private) that fires right after `net.Listen` succeeds and before the `listener_started` hookStage. Mirrors the `testDrainHook` / `testForceExit` / `testWorkerOptions` seam pattern (production nil, tests assign).

### Task 3 — `dashboard-smoke.sh` (10 checks)

`docs/walkthroughs/dashboard-smoke.sh` is a 319-line bash smoke gated by `SKYTIME_RUN_DASHBOARD_SMOKE=1` (matches Phase 7.2's `SKYTIME_RUN_CRON_SMOKE=1` convention). Default invocation prints `[dashboard-smoke] skipped (set SKYTIME_RUN_DASHBOARD_SMOKE=1 to run)` and exits 0. With the env var set + `temporal server start-dev` running on `localhost:7233`, it executes 10 checks:

1. **extbin builds** — `go build -o /tmp/skytime-dashboard-smoke-extbin ./examples/http-github-webhook/cmd/extbin`.
2. **`GET /` returns dashboard HTML** — title `Skytime Dashboard`, `id="triggerForm"`, dropdown option `value="public_repo_check"`.
3. **`GET /api/events` SSE headers + first frame** — `Content-Type: text/event-stream`, body starts with `event: snapshot`.
4. **`POST /api/trigger` valid** — 200 with `workflow_id` matching `manual/public_repo_check/[0-9a-f]{32}`.
5. **`POST /api/trigger` unknown flow** — 400.
6. **`POST /api/trigger` bad JSON** — 400, body does NOT echo the malformed input (Pitfall 10 defense).
7. **`POST /api/trigger` `Origin: http://evil.com`** — 403 (M3 JSON-strict same-origin gate).
8. **Workflow surfaces in dashboard data** — `event=flow_start [^ ]*flow_name=public_repo_check` appears in the server log within 8 seconds.
9. **SIGINT → SSE `event: shutdown` frame** — a long-lived background SSE subscriber receives the literal `event: shutdown` line before EOF (D-7.3-07 + B3 strict at the script level too).
10. **`--replay-history-threshold=-1` rejection** — server exits non-zero with a flag-named diagnostic on stderr (m3 negative-value rejection).

Check 10 runs BEFORE the long-lived server starts so it cannot contaminate live-server state. Per-process-group cleanup mirrors the cron-schedules-smoke pattern; macOS falls back to direct PID kill since `setsid` is Linux-only.

**Live verification:** `SKYTIME_RUN_DASHBOARD_SMOKE=1 bash docs/walkthroughs/dashboard-smoke.sh` was run against the local `temporal server start-dev` cluster during Task 3 execution and printed `[dashboard-smoke] all checks PASSED` on the first try.
