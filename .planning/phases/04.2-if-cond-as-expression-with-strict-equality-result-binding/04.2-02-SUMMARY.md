## Decisions Made

- **Pre-exec source rewriting over runtime kwarg defer** — Starlark eagerly evaluates kwarg expressions at builtin call time, so `result(value={"x": ctx.helper})` hits "undefined: ctx" before `builtinResult` runs. Solution: at parse time scan AST for `result(...)` calls, build `*dag.Result` upfront, rewrite each call's value=dict-literal range to a length-preserving `0`-sentinel (preserves line/col positions everywhere — newlines preserved verbatim, non-newline bytes replaced with spaces except first byte = `0`). Original bytes stay cached at `p.fileBytes[filename]` for AST re-parse paths and lambda IDs; rewritten bytes go only to `starlark.ExecFileOptions`.
- **Compile-fallback for opaque value lambdas** — synthesized `lambda ctx: <expr>` bodies that reference user-defined helpers or extension factories error at Starlark's compile-time resolver with "undefined: <name>". The fallback compiles a `lambda ctx: None` placeholder so parse succeeds; Phase 3 worker re-parse provides the authoritative Fn at workflow start (Option B), so the fallback is semantically safe — runtime never executes the parse-time Fn directly.
- **validateResultPlacement plan-02 placement gate (Rule 2 deviation)** — `TestResult_RejectedOutsideExpressionMode` (a plan-02 RED test) demands an early reject with `output_alias` hint when `result()` appears outside an expression-mode if_cond branch. The plan task didn't explicitly mandate this finalize pass, but the test's existence in plan 02 and the placement check's narrow scope justify landing it now (vs deferring to plan 03's branch-equality validator). Keeps plan 03 focused on D4.2-09 cases.
- **`ctx_walk.go` `dot.NamePos` → `dot.Name.NamePos` (Rule 1 deviation)** — go.starlark.net's `*syntax.DotExpr.NamePos` field is consistently `<invalid>` in the current pinned version (verified empirically against multiple sources). The Ident's NamePos (`dot.Name.NamePos`) is properly populated. Latent bug previously masked by tests asserting only `ve.Msg`, never `ve.Pos.Filename`. The new `TestCheckLambdaCtx_RemapsResultPrefix` is the first test to assert `Pos.Filename` and surfaces the bug.
- **Dual-name fail registration** — `fail` is the sole sanctioned overlap between parse-time and lambda-time predeclared envs (D4.2-05). `TestParseAndLambdaGlobalsAreDistinct` updated with an explicit `fail` exception comment; `TestFailBuiltinDualEnv` pins both env entries are `*starlark.Builtin` with same `Name()` but distinct `*Builtin` instances; `TestFail_LambdaTime_StillRaises` (in `pkg/bridge`) is the regression guard against accidental rewiring of the lambda-time surface.
- **Empty schema for plan-02 type inference** — `builtinResult` invokes `inferType` against `newStateSchema()` (empty) for the per-key Types map. This is a best-effort first cut; plan 04.2-03's branch-equality validator re-runs inference against the proper branch-fork stateSchema before applying strict-equality. Documented as an intentional limitation; the per-key Types map carries Wave-1 best-effort signals (literal scalars typed correctly, ctx.X collapses to opaque without the proper schema context).
