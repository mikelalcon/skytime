## User Constraints (from CONTEXT.md)

### Locked Decisions

**State binding shape**

- **D4.2-01:** `dag.IfCond` gains an optional `OutputAlias string` field (mirrors `Script.OutputAlias`). Setting `if_cond(output_alias="X", ...)` triggers expression mode. Empty string = procedural mode (today's behavior). The corresponding parser builtin `builtinIfCond` accepts an optional `output_alias` kwarg; presence detection mirrors the `hasKwarg` pattern used for `task_queue` (D3-19).

**`result(...)` builtin**

- **D4.2-02:** New top-level `result(value={...})` builtin in `parser.newParseTimeGlobals`. Emits a new `*dag.Result` node. Kwarg-only signature (`value=`); positional rejected. The `value=` argument MUST be a Starlark dict-literal at the call site — anything else (a variable reference, a lambda, a function call) is a parse error: `"result.value must be a dict literal"`.
- **D4.2-03:** Static keys, expression values. Every dict KEY must be a string literal at parse time (computed keys → parse error). Each dict VALUE is captured as a per-key `*dag.CapturedLambda` via the same synthesized-source desugaring infrastructure as D4.1-01 interpolation. The `*dag.Result` node carries: `Pos syntax.Position`, `Keys []string` (insertion order), `Values map[string]*CapturedLambda`, `Types map[string]TypeInfo`.
- **D4.2-04:** `result(...)` is a LEAF — it has no body, no children. It is only legal as the LAST node of a `then` or `else_` body inside an `if_cond` whose `output_alias` is set. The parser rejects `result(...)` everywhere else with a clear hint pointing to the missing `output_alias`.

**`fail(...)` builtin**

- **D4.2-05:** New top-level `fail("msg")` builtin in `parser.newParseTimeGlobals`. Emits a new `*dag.Fail` node. SAME NAME as the lambda-time `fail` (D-20) — predeclared environments are mutually exclusive (top-level vs lambda body). Both produce the same observable surface: a NonRetryableErr with the user's message at the .star callsite.
- **D4.2-06:** `*dag.Fail` shape mirrors `Step.Name`/`Step.NameFn` from D4.1-15: `Pos syntax.Position`, `Message string` (literal template, preserves `${...}` markers verbatim), `MessageFn *CapturedLambda` (synthesized lambda set when interpolation is present; nil otherwise). Interpolation supported via D4.1-01 desugarer.
- **D4.2-07:** `fail(...)` is allowed anywhere a body accepts nodes — both procedural-mode `if_cond` branches (procedural guard) and as the last node of an expression-mode branch.

**Coexistence**

- **D4.2-08:** Additive, opt-in. `output_alias == ""` → procedural mode (TODAY's behavior preserved exactly; `result(...)` REJECTED with hint; `fail(...)` ALLOWED). `output_alias != ""` → expression mode rules (D4.2-09).

**Expression-mode parse-time rules**

- **D4.2-09:** When `output_alias` is set:
  1. Both `then` AND `else_` are present (`else_` cannot be omitted).
  2. The LAST node of each branch is `*dag.Result` or `*dag.Fail`.
  3. At least ONE branch's last node is `*dag.Result` (both-fail rejected: hint suggests removing `output_alias`).
  4. Across branches that end in `*dag.Result`: KEY SETS must be identical (sorted-string-equality compared). Mismatch → `*dag.ValidationError` with both branches' positions and symmetric-difference of keys in message.
  5. For each shared key: PER-BRANCH VALUE TYPES compared best-effort (D4.2-10).
  Validation lives in a new finalize-pass step (e.g., `validateIfCondExpressionShape`) ordered AFTER `validateLambdaCtxAccesses`.

**Type inference**

- **D4.2-10:** Best-effort static type inference, defer-to-runtime-via-no-check for opaque expressions. Parser walks each result-value AST and derives `TypeInfo`: literals (int/float/bool/string/none/dict-recursive/list-homogeneous/tuple-positional); `ctx.X` references via typed state schema; operators per Starlark per-operand-type rules; locked 20-key lambda-time builtins by known return-type rules; `a if c else b` recursive arm-equality (equal → that type, else opaque); anything else → `Opaque`.
- **D4.2-11:** Branch equality check (per shared key): both typed → STRICT (no widening: `int` ≠ `float` ≠ `bool`; mismatch → `*dag.ValidationError` with cast hint). One typed + one Opaque → DEFER (no error). Both Opaque → DEFER (no error).
- **D4.2-12:** "Strict equality" intentionally means strict — no LUB rules in v1. Explicit casts (`float(x)`, `int(x)`, `str(x)`) are the widening mechanism. Loosening requires a new ADR.

**State-schema upgrade**

- **D4.2-13:** `pkg/parser/state_schema.go`'s `stateSet` (today: `map[string]struct{}`) widens to TYPED schema. Likely shape: `type stateSchema map[string]TypeInfo`. Visibility-only D4-02 ctx-access check continues to work (membership unchanged); the new type-info field is consulted by the result-inference pass. Flow inputs seed from `flow(inputs={"name": "type"})`. Script `output_alias` adds entries with the inferred type of `fn=...` body. When `if_cond(output_alias="X")` is reached, branch-result types determine post-if-cond type for `X` (unambiguous after strict-equality check).
- **D4.2-14:** `TypeInfo` is a sealed sum (Go interface with unexported marker, mirroring `dag.Node` and `dag.ActionResult`). Concrete kinds: `TypeScalar{Kind: int|float|bool|string|none}`, `TypeDict{Fields map[string]TypeInfo}`, `TypeList{Element TypeInfo}` (homogeneous; mismatched → `TypeOpaque`), `TypeTuple{Elements []TypeInfo}`, `TypeOpaque{}`.

**Renderer / interpreter**

- **D4.2-15:** Runtime interpreter changes are minimal. `walkIfCond` extended:
  - Last-node `*dag.Result` AND `n.OutputAlias != ""`: walk body normally (renderer indented children unchanged), then evaluate each `Values[k]` lambda in `Keys` order, assemble Starlark dict, assign to `ctx[OutputAlias]`. Emit single `result_bound` event (`event=result_bound`, `alias=<OutputAlias>`, `keys=[...]`, `path=<branch path>`).
  - Last-node `*dag.Fail`: walk preceding nodes, then raise NonRetryableErr with `n.Message` (or `n.MessageFn` evaluated against state) via `temporal.NewNonRetryableApplicationError` carrying `n.Pos`. Emit `step_complete` with `status=err`, `kind=fail`, `summary=<resolved message>`.
  - Procedural mode: walkBody continues exactly as today; `*dag.Result` and (top-level) `*dag.Fail` not present in well-formed procedural-mode bodies.
- **D4.2-16:** Renderer shape: `*dag.Result` renders as leaf row inside active branch scope (`[depth] ✓ result → ctx.<alias>` with key list visible in `--verbose`). `*dag.Fail` renders as leaf row with error marker (`[depth] ✗ fail "<resolved message>"`). Pre-existing block-scope rendering reused.

**Interaction**

- **D4.2-17:** Interpolation extends to fail messages. Does NOT extend to `result(value={...})` value expressions (already first-class Starlark expressions captured as lambdas).
- **D4.2-18:** Step kwargs and other interpolation surfaces unchanged. Typed state schema means interpolation lambdas referencing `ctx.X` after expression-mode if_cond can be type-checked with post-if-cond type. Forward leverage; no Phase 04.2 task required.
- **D4.2-19:** `for_each_parallel` and `call_flow` unchanged. Nesting expression-mode `if_cond` inside `for_each_parallel.steps` works mechanically; branch-equality validation per-flow-static.

## Summary

Phase 04.2 promotes `if_cond` from purely procedural to OPTIONALLY expression-shaped. When the user passes `output_alias="X"`, the parser switches into a strict mode where each branch must end in `result(value={...})` (binds a typed dict to `ctx.X`) or `fail("msg")` (terminates the workflow). All implementation is parser-side except a minimal extension to `walkIfCond` for the two new last-node cases. Runtime semantics — INTRP-03's zero-history-events property — are preserved verbatim.

The work decomposes cleanly into seven research domains: (1) **TypeInfo sealed sum** for static type inference of Starlark expressions; (2) **AST-level dict-literal recognition** for the `result(value=...)` strict shape rule; (3) **state-schema widening** from `map[string]struct{}` to `map[string]TypeInfo` without breaking the D4-02 walker; (4) **branch-equality validator** in finalize, mirroring `walkBodyForCtxValidation` shape; (5) **runtime walker extension** for `*dag.Result` (binds value) and `*dag.Fail` (raises NonRetryableErr); (6) **renderer surface** for the new `result_bound` slog event; (7) **dry-run differential corpus** verification. Every primitive needed by 04.2 already exists in the codebase — no novel patterns are required.

**Primary recommendation:** Add three node files (`pkg/dag/result_node.go` for `Result`, `pkg/dag/fail.go` for `Fail`; `pkg/parser/type_info.go` for `TypeInfo`), extend `pkg/parser/builtins.go` with `builtinResult` + `builtinFail`, widen `pkg/parser/state_schema.go::stateSet` → `stateSchema map[string]TypeInfo`, add `pkg/parser/ifcond_expr_validate.go` (new finalize pass), extend `pkg/interpreter/walk_ifcond.go` for the two last-node cases. Test infrastructure: unit tests per file co-located, integration tests in existing `tests/differential_test.go` corpus + new Wave-0 fixtures. NO version bumps; NO new dependencies.

### Pattern 1: Sealed Node + parser builtin (used for `Result` and `Fail`)

**What:** Every dag node type implements `Kind() string`, `Position() syntax.Position`, `nodeMarker()`. The parser builtin returns `wrapNode(&dag.X{...})` so the value lives inside a `*starlark.List` (e.g., `then=[...]`).

**When to use:** ALWAYS for new dag node types — the seal forces compile-time exhaustiveness in interpreter type switches.

**Example:**
```go
// Source: pkg/dag/control.go (IfCond) + pkg/dag/step.go (Step)
package dag

import "go.starlark.net/syntax"

type Result struct {
    Pos    syntax.Position
    Keys   []string                       // insertion order from source dict-literal
    Values map[string]*CapturedLambda     // per-key value lambdas
    Types  map[string]TypeInfo            // per-key inferred type (TypeOpaque when unknown)
}

var _ Node = (*Result)(nil)
func (*Result) Kind() string                { return "Result" }
func (n *Result) Position() syntax.Position { return n.Pos }
func (*Result) nodeMarker()                 {}
```

```go
// pkg/dag/fail.go
type Fail struct {
    Pos       syntax.Position
    Message   string             // literal template ("repo ${ctx.repo} not found")
    MessageFn *CapturedLambda    // synthesized lambda when interpolation present
}

var _ Node = (*Fail)(nil)
func (*Fail) Kind() string                { return "Fail" }
func (n *Fail) Position() syntax.Position { return n.Pos }
func (*Fail) nodeMarker()                 {}
```

### Pattern 2: Sealed sum with unexported marker (used for `TypeInfo`)

**What:** Interface with one unexported method (`isTypeInfo()`); concrete types implement it; type switches at consumption sites.

**When to use:** Closed set of variants you want to enforce at compile time. Mirrors `dag.ActionResult`, `dag.Credential`, `dag.Node`.

**Example:**
```go
// pkg/parser/type_info.go
package parser

// TypeInfo is the sealed sum of statically-inferable Starlark types
// (D4.2-14). The unexported isTypeInfo() seal forbids external types
// from satisfying the interface — adding a kind requires editing this
// file (deliberate API-evolution gate).
type TypeInfo interface {
    isTypeInfo()
}

// TypeScalar covers int, float, bool, string, none.
type TypeScalar struct {
    Kind string // "int" | "float" | "bool" | "string" | "none"
}
func (TypeScalar) isTypeInfo() {}

// TypeDict is a homogeneous-key dict whose Fields map declares per-key types.
// Recursive: a dict-of-dict is fine.
type TypeDict struct {
    Fields map[string]TypeInfo
}
func (TypeDict) isTypeInfo() {}

// TypeList is a homogeneous list. Mismatched-element lists collapse to TypeOpaque.
type TypeList struct {
    Element TypeInfo
}
func (TypeList) isTypeInfo() {}

// TypeTuple is a positional tuple.
type TypeTuple struct {
    Elements []TypeInfo
}
func (TypeTuple) isTypeInfo() {}

// TypeOpaque is the "cannot statically infer" sentinel.
type TypeOpaque struct{}
func (TypeOpaque) isTypeInfo() {}

// Equal compares two TypeInfo values by deep structural equality.
// Strict: TypeScalar{int} ≠ TypeScalar{float} (no LUB). One side
// TypeOpaque returns true ONLY when both are TypeOpaque (the
// branch-equality validator separately defers when one side is opaque
// and the other is concrete — it does not call Equal in that case).
func Equal(a, b TypeInfo) bool {
    switch ax := a.(type) {
    case TypeScalar:
        bx, ok := b.(TypeScalar)
        return ok && ax.Kind == bx.Kind
    case TypeDict:
        bx, ok := b.(TypeDict)
        if !ok || len(ax.Fields) != len(bx.Fields) {
            return false
        }
        for k, av := range ax.Fields {
            bv, has := bx.Fields[k]
            if !has || !Equal(av, bv) {
                return false
            }
        }
        return true
    case TypeList:
        bx, ok := b.(TypeList)
        return ok && Equal(ax.Element, bx.Element)
    case TypeTuple:
        bx, ok := b.(TypeTuple)
        if !ok || len(ax.Elements) != len(bx.Elements) {
            return false
        }
        for i, av := range ax.Elements {
            if !Equal(av, bx.Elements[i]) {
                return false
            }
        }
        return true
    case TypeOpaque:
        _, ok := b.(TypeOpaque)
        return ok
    }
    return false
}
```

### Pattern 5: Finalize-pass walker mirroring `walkBodyForCtxValidation`

**What:** New finalize step is a recursive method on `*Parser`, walks `flow.Body`, descends into `IfCond.Then`, `IfCond.Else`, `ForEachParallel.Steps`. First error wins. Returns `error`.

**When to use:** ALWAYS for new finalize lints — every existing pass (resolveCallFlows, lintMixedIdempotency, lintBlockFnIdempotency, lintBlockSize, lintEmptyTaskQueue, validateLambdaCtxAccesses, validateActionRefKwargs) follows this shape. Adopt it for grep-friendly recursion.

**Example:**
```go
// pkg/parser/ifcond_expr_validate.go
package parser

import (
    "fmt"
    "sort"

    "github.com/mikelalcon/skytime/pkg/dag"

// validateIfCondExpressionShape implements D4.2-09 + D4.2-11. Runs in
// finalize() AFTER validateLambdaCtxAccesses (so structural state errors
// surface first; same ordering rule as D-11 cross-validate).
func (p *Parser) validateIfCondExpressionShape() error {
    for _, flow := range p.flows {
        if err := p.walkValidateIfCondExpression(flow.Name, flow.Body); err != nil {
            return err
        }
    }
    return nil
}

func (p *Parser) walkValidateIfCondExpression(flowName string, body []dag.Node) error {
    for _, node := range body {
        switch n := node.(type) {
        case *dag.IfCond:
            if n.OutputAlias != "" {
                if err := p.checkIfCondExpression(flowName, n); err != nil {
                    return err
                }
            }
            if err := p.walkValidateIfCondExpression(flowName, n.Then); err != nil {
                return err
            }
            if err := p.walkValidateIfCondExpression(flowName, n.Else); err != nil {
                return err
            }
        case *dag.ForEachParallel:
            if err := p.walkValidateIfCondExpression(flowName, n.Steps); err != nil {
                return err
            }
        }
    }
    return nil
}

// checkIfCondExpression enforces D4.2-09 cases 1-5 on a single
// expression-mode if_cond.
func (p *Parser) checkIfCondExpression(flowName string, n *dag.IfCond) error {
    // Case 1: both branches present
    if len(n.Then) == 0 || len(n.Else) == 0 {
        return &dag.ValidationError{
            Pos: n.Pos, Flow: flowName,
            Msg: "if_cond expression mode (output_alias set): both then and else_ branches must be present",
        }
    }
    thenLast := n.Then[len(n.Then)-1]
    elseLast := n.Else[len(n.Else)-1]

    // Case 2: each last node is *dag.Result or *dag.Fail
    thenRes, thenIsRes := thenLast.(*dag.Result)
    _, thenIsFail := thenLast.(*dag.Fail)
    elseRes, elseIsRes := elseLast.(*dag.Result)
    _, elseIsFail := elseLast.(*dag.Fail)
    if !(thenIsRes || thenIsFail) {
        return &dag.ValidationError{
            Pos: thenLast.Position(), Flow: flowName,
            Msg: "if_cond expression mode: then-branch last node must be result(...) or fail(...)",
        }
    }
    if !(elseIsRes || elseIsFail) {
        return &dag.ValidationError{
            Pos: elseLast.Position(), Flow: flowName,
            Msg: "if_cond expression mode: else_-branch last node must be result(...) or fail(...)",
        }
    }

    // Case 3: at least one branch is *dag.Result (both-fail rejected)
    if !thenIsRes && !elseIsRes {
        return &dag.ValidationError{
            Pos: n.Pos, Flow: flowName,
            Msg: "if_cond expression mode: at least one branch must end in result(...); both-fail is procedural-guard territory — remove output_alias",
        }
    }

    // Case 4 + 5: when both branches are Result, key-set + per-key type equality
    if thenIsRes && elseIsRes {
        if err := compareResultBranches(flowName, n.Pos, thenRes, elseRes); err != nil {
            return err
        }
    }
    return nil
}

// compareResultBranches enforces D4.2-09 case 4 (sorted key-set equality)
// and D4.2-11 (per-key TypeInfo strict equality with Opaque-defers).
func compareResultBranches(flowName string, ifCondPos syntax.Position, then, els *dag.Result) error {
    thenKeys := append([]string(nil), then.Keys...)
    sort.Strings(thenKeys)
    elseKeys := append([]string(nil), els.Keys...)
    sort.Strings(elseKeys)
    if !equalStringSlices(thenKeys, elseKeys) {
        thenSet := keySet(thenKeys)
        elseSet := keySet(elseKeys)
        diff := symmetricDiff(thenSet, elseSet)
        return &dag.ValidationError{
            Pos: then.Pos, Flow: flowName,
            Msg: fmt.Sprintf("if_cond expression mode: branches disagree on result keys (then=%v, else=%v, symmetric-difference=%v); also see else-branch result at %s",
                thenKeys, elseKeys, diff, els.Pos),
        }
    }
    for _, k := range thenKeys {
        tt := then.Types[k]
        et := els.Types[k]
        if _, isOpaque := tt.(TypeOpaque); isOpaque {
            continue
        }
        if _, isOpaque := et.(TypeOpaque); isOpaque {
            continue
        }
        if !Equal(tt, et) {
            return &dag.ValidationError{
                Pos: then.Pos, Flow: flowName,
                Msg: fmt.Sprintf("if_cond expression mode: branches disagree on key %q: then=%s, else=%s; wrap one side with float(x)/int(x)/str(x) to widen explicitly (else-branch result at %s)",
                    k, typeInfoString(tt), typeInfoString(et), els.Pos),
            }
        }
    }
    return nil
}
```

### Pattern 6: Static AST type inference of Starlark expressions

**What:** Walk a `*syntax.Expr` and produce `TypeInfo`, deferring to `TypeOpaque` when the expression's shape isn't in the locked vocabulary. NO evaluation; parse-tree pattern matching only.

**When to use:** New for Phase 04.2 (no existing precedent in the codebase). The closest analogue is `pkg/parser/block_fn_lint.go::classifyBlockFn` — both walk an `*syntax.Expr` and pattern-match against a known vocabulary.

**Decision table:** see §"Type Inference Decision Table" below.

**Example:**
```go
// pkg/parser/infer_expr.go
package parser

import (
    "go.starlark.net/syntax"
)

// inferType statically infers the TypeInfo of a Starlark expression
// against the lexically-visible state schema. Unknown shapes return
// TypeOpaque{}; D4.2-11 makes this a soft signal (defer to runtime),
// not a hard error.
//
// firstParam is the lambda parameter name (always "ctx" by convention)
// — used to recognize ctx.<name> chains.
func inferType(e syntax.Expr, schema stateSchema, firstParam string) TypeInfo {
    switch n := e.(type) {
    case *syntax.Literal:
        switch n.Token {
        case syntax.INT:
            return TypeScalar{Kind: "int"}
        case syntax.FLOAT:
            return TypeScalar{Kind: "float"}
        case syntax.STRING:
            return TypeScalar{Kind: "string"}
        }
        return TypeOpaque{}
    case *syntax.Ident:
        // True / False / None are *syntax.Ident with reserved names.
        switch n.Name {
        case "True", "False":
            return TypeScalar{Kind: "bool"}
        case "None":
            return TypeScalar{Kind: "none"}
        }
        return TypeOpaque{}
    case *syntax.DotExpr:
        // ctx.<name>: look up the typed schema. Multi-hop ctx.a.b is
        // handled iteratively by recursing into n.X.
        if id, ok := n.X.(*syntax.Ident); ok && id.Name == firstParam {
            t, has := schema[n.Name.Name]
            if !has {
                return TypeOpaque{} // free var — D4-02 walker would have errored already
            }
            return t
        }
        // ctx.a.b: recurse into n.X to get TypeDict/TypeOpaque, descend Fields.
        inner := inferType(n.X, schema, firstParam)
        if td, ok := inner.(TypeDict); ok {
            if t, has := td.Fields[n.Name.Name]; has {
                return t
            }
        }
        return TypeOpaque{}
    case *syntax.UnaryExpr:
        innerType := inferType(n.X, schema, firstParam)
        switch n.Op {
        case syntax.MINUS, syntax.PLUS:
            return innerType // sign preserves arithmetic type
        case syntax.NOT:
            return TypeScalar{Kind: "bool"}
        }
        return TypeOpaque{}
    case *syntax.BinaryExpr:
        return inferBinary(n, schema, firstParam)
    case *syntax.CondExpr:
        // a if c else b — recursive arm-equality
        tt := inferType(n.True, schema, firstParam)
        ft := inferType(n.False, schema, firstParam)
        if Equal(tt, ft) {
            return tt
        }
        return TypeOpaque{}
    case *syntax.ListExpr:
        // homogeneous element type; mismatched → TypeOpaque
        if len(n.List) == 0 {
            return TypeList{Element: TypeOpaque{}}
        }
        elt := inferType(n.List[0], schema, firstParam)
        for _, ent := range n.List[1:] {
            t := inferType(ent, schema, firstParam)
            if !Equal(elt, t) {
                return TypeOpaque{}
            }
        }
        return TypeList{Element: elt}
    case *syntax.TupleExpr:
        elts := make([]TypeInfo, 0, len(n.List))
        for _, ent := range n.List {
            elts = append(elts, inferType(ent, schema, firstParam))
        }
        return TypeTuple{Elements: elts}
    case *syntax.DictExpr:
        fields := make(map[string]TypeInfo)
        for _, ent := range n.List {
            de := ent.(*syntax.DictEntry)
            keyLit, ok := de.Key.(*syntax.Literal)
            if !ok || keyLit.Token != syntax.STRING {
                return TypeOpaque{} // computed key — defer
            }
            keyStr := keyLit.Value.(string)
            fields[keyStr] = inferType(de.Value, schema, firstParam)
        }
        return TypeDict{Fields: fields}
    case *syntax.CallExpr:
        return inferCall(n, schema, firstParam)
    case *syntax.IndexExpr:
        // lst[i] / dict[k] — depends on lhs type; opaque key/value mostly defer
        lhs := inferType(n.X, schema, firstParam)
        if tl, ok := lhs.(TypeList); ok {
            return tl.Element
        }
        return TypeOpaque{}
    case *syntax.SliceExpr:
        // lst[a:b] returns same type as lhs
        return inferType(n.X, schema, firstParam)
    case *syntax.ParenExpr:
        return inferType(n.X, schema, firstParam)
    case *syntax.Comprehension:
        return TypeOpaque{} // out of scope for v1
    }
    return TypeOpaque{}
}

// inferBinary handles + - * / // % < > == != >= <= and or
func inferBinary(n *syntax.BinaryExpr, schema stateSchema, firstParam string) TypeInfo {
    lt := inferType(n.X, schema, firstParam)
    rt := inferType(n.Y, schema, firstParam)
    switch n.Op {
    case syntax.LT, syntax.GT, syntax.LE, syntax.GE, syntax.EQL, syntax.NEQ:
        return TypeScalar{Kind: "bool"}
    case syntax.PLUS:
        // int+int=int, float+float=float, string+string=string, list+list=list
        ls, lok := lt.(TypeScalar)
        rs, rok := rt.(TypeScalar)
        if lok && rok && ls.Kind == rs.Kind {
            return ls
        }
        ll, lLok := lt.(TypeList)
        rl, rLok := rt.(TypeList)
        if lLok && rLok && Equal(ll.Element, rl.Element) {
            return ll
        }
        return TypeOpaque{}
    case syntax.MINUS, syntax.STAR, syntax.SLASH, syntax.SLASHSLASH, syntax.PERCENT:
        ls, lok := lt.(TypeScalar)
        rs, rok := rt.(TypeScalar)
        if !lok || !rok {
            return TypeOpaque{}
        }
        // Per Starlark / Python: int op int = int, float op anything-numeric = float, / always float
        if n.Op == syntax.SLASH {
            return TypeScalar{Kind: "float"}
        }
        if ls.Kind == "float" || rs.Kind == "float" {
            return TypeScalar{Kind: "float"}
        }
        if ls.Kind == "int" && rs.Kind == "int" {
            return TypeScalar{Kind: "int"}
        }
        return TypeOpaque{}
    case syntax.AND, syntax.OR:
        // short-circuit: result is one of the operands; arm-equality
        if Equal(lt, rt) {
            return lt
        }
        return TypeOpaque{}
    }
    return TypeOpaque{}
}

// inferCall handles the locked 20-key lambda-time builtins (D-20) and
// type-construction calls (int(...), float(...), str(...), list(...),
// dict(...), bool(...), tuple(...)).
func inferCall(n *syntax.CallExpr, schema stateSchema, firstParam string) TypeInfo {
    id, ok := n.Fn.(*syntax.Ident)
    if !ok {
        return TypeOpaque{}
    }
    switch id.Name {
    case "int":
        return TypeScalar{Kind: "int"}
    case "float":
        return TypeScalar{Kind: "float"}
    case "str":
        return TypeScalar{Kind: "string"}
    case "bool":
        return TypeScalar{Kind: "bool"}
    case "len":
        return TypeScalar{Kind: "int"}
    case "abs":
        // abs(int)→int, abs(float)→float — uses arg type
        if len(n.Args) > 0 {
            return inferType(n.Args[0], schema, firstParam)
        }
        return TypeOpaque{}
    case "sum":
        // sum(iter, start=0) - returns same type as start (int|float)
        if len(n.Args) >= 2 {
            return inferType(n.Args[1], schema, firstParam)
        }
        return TypeScalar{Kind: "int"}
    case "min", "max":
        // min/max return same type as elements
        if len(n.Args) > 0 {
            arg := inferType(n.Args[0], schema, firstParam)
            if tl, isList := arg.(TypeList); isList {
                return tl.Element
            }
            return arg
        }
        return TypeOpaque{}
    case "any", "all":
        return TypeScalar{Kind: "bool"}
    case "sorted", "reversed":
        // sorted(list[T])→list[T]
        if len(n.Args) > 0 {
            return inferType(n.Args[0], schema, firstParam)
        }
        return TypeOpaque{}
    case "list":
        return TypeOpaque{} // converting from arbitrary iterable — element type unknown
    case "dict":
        return TypeOpaque{} // dict({"a": 1}) → TypeDict{}, but full inference is future work
    case "tuple":
        return TypeOpaque{}
    case "enumerate":
        return TypeOpaque{} // list of (int, T)
    case "zip":
        return TypeOpaque{}
    case "range":
        return TypeOpaque{} // a `range` object — not in our TypeInfo vocabulary
    }
    return TypeOpaque{}
}
```

### Anti-Patterns to Avoid

- **Hand-building `*syntax.LambdaExpr` AST nodes.** D4.1-01 RESEARCH §Pattern 1 already chose the synthesized-source path (build a string + parse via `(*syntax.FileOptions).Parse`). The hand-built AST path is more complex AND must replicate Starlark's resolver semantics. Use the source-string path verbatim.
- **`reflect.DeepEqual(a, b)` for TypeInfo equality.** Works in the trivial case but bypasses the seal — adding a new TypeInfo kind would silently allow inconsistencies. The `Equal()` method (Pattern 2) is exhaustive.
- **Walking the entire .star file twice for dict-literal recognition.** Re-parse `fileBytes[callPos.Filename()]` inside `builtinResult` once via the existing D4-02 / D4.1-11 idiom. Don't add a second AST scan in finalize — the position-keyed lookup is the established seam.
- **Using `for k := range Values` to assemble the result dict at runtime.** Go map iteration is randomized. Always iterate `Result.Keys` (a `[]string` in source order) and look up `Values[k]` per iteration. workflowcheck flags map iteration; the stable-sort-via-Keys-slice mirrors how `pkg/dag/marshal.go::ActionRef.UnmarshalJSON` already preserves dict ordering.
- **Conflating top-level `fail()` with lambda-time `fail()`.** They share a NAME but live in distinct predeclared environments. The parser-side `fail()` builtin returns a `*nodeValue{Node: &dag.Fail{...}}` — never call `starlark.Universe["fail"]` (which raises EvalError). Pin this behavior with a test.
- **Custom MarshalJSON on `dag.Result` that emits `Pos`.** `pkg/dag/marshal.go` deliberately omits `Pos.Filename` (machine-absolute, breaks cross-machine golden stability). Mirror that exclusion. Same applies to `dag.Fail`.
- **Assuming `result(value=x)` where `x` is a variable resolves to a dict-literal.** It does NOT — the user assigned a variable, the AST shows a `*syntax.Ident`, the parser must reject. Inspect the AST at the call site, not the runtime-evaluated `*starlark.Dict`.

## Common Pitfalls

### Pitfall 1: `result(...)` accepted outside an expression-mode `if_cond` body silently builds a dangling node

**What goes wrong:** `result(value={...})` returns a `*nodeValue{Node: &dag.Result{...}}` regardless of where it appears. If the parser does NOT separately validate that every `*dag.Result` is the LAST node of a `then` or `else_` body of an `if_cond` whose `OutputAlias != ""`, users can write `flow(steps=[result(value={"x": 1})])` and the parse succeeds but the runtime walker has no path to evaluate it.

**Why it happens:** The builtin pattern in `pkg/parser/builtins.go` is "build node, return it; let the body walker decide where it lives." This works for Step / IfCond / Script because they self-contain; Result is positional.

**How to avoid:** Add a finalize-pass case in `validateIfCondExpressionShape` that walks every body and rejects `*dag.Result` and (top-level) `*dag.Fail` outside their permitted positions. Mirror the if_cond.OutputAlias check in `checkIfCondExpression`. Add a fixture `result_outside_ifcond.star` to pin.

**Warning signs:** A test that constructs `flow(steps=[result(...)])` parses without error.

### Pitfall 2: Re-parse cache miss when validating dict-literal at the call site

**What goes wrong:** `builtinResult` runs at Starlark execution time; by then, `fileBytes[callPos.Filename()]` should already be cached from the outer `parse()` call. But `load()`-resolved files have their bytes cached lazily — and a `result()` call inside a `load()`-imported flow will see the cache populated at a different point in the parse cycle.

**Why it happens:** `pkg/parser/parser.go::parse` populates `fileBytes` before `ExecFileOptions`; `pkg/parser/load.go` populates `fileBytes` for each loaded file before its own ExecFileOptions. The call sequence is correct in the happy path, but cross-file `result()` calls need a sanity check.

**How to avoid:** In `builtinResult`, defensively check `if _, ok := p.fileBytes[callPos.Filename()]; !ok { return error }`. The same defensive check already exists in `pkg/parser/lambda_capture.go::captureLambda` ("internal: file bytes for %q not cached") — copy that pattern verbatim.

**Warning signs:** A multi-file fixture (`a.star` loads `b.star` which uses `result`) panics or returns "file bytes not cached" error.

### Pitfall 3: Per-key value-lambda position attribution leaks `<result:...>` to user errors

**What goes wrong:** Per-key value lambdas live in synthetic files (`<result:<file>:<line>:<col>:<key>>`). When the D4-02 walker finds a `ctx.typo` inside the value-lambda body, it uses the synthetic file's position by default. Users see `<result:tests/fixtures/foo.star:42:5:count>:1:23: ctx.typo not in...` — confusing.

**Why it happens:** Same as D4.1-01's Pitfall 1. The fix is in `checkLambdaCtx` — when the access position has the synthetic filename prefix, remap to `captured.Pos` (user attribution).

**How to avoid:** The existing `checkLambdaCtx` (in `state_schema.go`, lines 217-225) already handles `<interp:` prefix with `if strings.HasPrefix(errPos.Filename(), "<interp:") { errPos = captured.Pos }`. **Extend this to also handle `<result:` prefix.** A test fixture with `result(value={"x": ctx.typo})` should produce a ValidationError pointing at the user's source, not at `<result:...>`.

**Warning signs:** Test message contains `<result:` as filename in error output.

### Pitfall 4: Top-level `fail` and lambda-time `fail` confused at the wrong stage

**What goes wrong:** A user writes `step(action_fn=lambda ctx: fail("nope"))`. Question: is this the parse-time builtin (which would return a `*dag.Fail` node) or the lambda-time builtin (which raises EvalError at workflow execute)? Answer: lambda-time, because `fail` inside a `lambda` body resolves against the lambda-time env. But during PARSE, the parser-time globals dict is what the outer `step(...)` call sees. The DSL builtin `fail("msg")` at the top of the .star file IS parse-time; the same name inside a `lambda` body is lambda-time.

**Why it happens:** Two predeclared environments use the same name. Starlark resolves names per the active env. This is correct by design but confusing.

**How to avoid:** Add a sanity test `TestFailBuiltinDualEnv` that asserts BOTH:
- `parser.newParseTimeGlobals(p, thread)["fail"]` is a `*starlark.Builtin` whose call returns `*nodeValue{Node: &dag.Fail{...}}`.
- `bridge.LambdaTimeGlobals()["fail"]` is `starlark.Universe["fail"]` (raises EvalError).

Document this in `pkg/parser/doc.go` and add a comment block in `pkg/parser/globals.go::newParseTimeGlobals` explaining the dual semantics. The RESEARCH.md user-facing doc also requires a callout in the corpus README.

**Warning signs:** A parse fixture `step(action_fn=lambda ctx: fail("nope"))` produces a `*dag.Fail` node (it should NOT — should produce a normal Step with action_fn that raises at runtime).

### Pitfall 5: Replay determinism violation in dict assembly

**What goes wrong:** The runtime walker at the `*dag.Result` last-node case assembles a Starlark dict from `Values[k]` lambda results. If iteration is `for k := range n.Values`, Go map iteration is randomized — replay produces a different dict on the second run.

**Why it happens:** Phase 3's `pkg/interpreter/state.go::sortedKeys` exists for exactly this reason; D3-23 prohibits naked `for k := range m` loops. workflowcheck flags them.

**How to avoid:** ALWAYS iterate `n.Keys` (the `[]string` slice in source insertion order) and look up `n.Values[k]` per iteration. The order is fixed at parse time per D4.2-03. Add a unit test that constructs a `dag.Result` with three keys and verifies the assembled dict's `Items()` order matches `Keys` order across two evaluations.

**Warning signs:** workflowcheck flag on `walkIfCond.go` after the change. Or: a replay-twice test that diffs Temporal histories shows divergent activity inputs.

### Pitfall 6: Type inference too aggressive — unfixable false rejection

**What goes wrong:** `inferType` infers `TypeOpaque` for an expression the user thinks should be typed. Branch-equality validator sees one side typed (the other branch's expression that DID infer) and one side opaque, defers — no error, silent acceptance. User wrote `result(value={"count": ctx.config.batch_size})` in one branch and `result(value={"count": 5})` in the other; inference for `ctx.config.batch_size` is `TypeOpaque` (multi-hop dict descent unsupported in v1); validator defers. Reasonable, intentional, but documented gap.

**Why it happens:** D4.2-10's permissive policy IS the design discipline ("best-effort static, defer to runtime via no check"). This is a feature, not a bug.

**How to avoid:** Document explicitly in `pkg/parser/infer_expr.go::inferType` doc comment: "TypeOpaque is a strong signal — if you see this in test output, the validator's strict-equality path is bypassed for that key. Consider expanding inference (filed as v1.x scope) or wrapping the side with `int(x)` / `float(x)` to force a known type." Add a `TestInferType_ProducesOpaqueForCtxMultiHop` fixture that pins this is intentional.

**Warning signs:** Test failure where a known-mismatched-type fixture passes branch-equality. The mitigation is to expand `inferType` to handle the case.

### Pitfall 7: New `*dag.Fail` accidentally breaks existing procedural-mode if_cond fixtures

**What goes wrong:** D4.2-07 ALLOWS `fail()` in procedural-mode if_cond branches (the procedural guard pattern). Existing `simple_check.star`-style fixtures don't use it, but a future hand-written test that writes `if_cond(cond=..., then=[fail("invalid")])` (no `output_alias`) should parse and run as expected. If the new finalize pass treats every `*dag.Fail` as needing expression-mode validation, the test breaks.

**Why it happens:** Easy to write `walkValidateIfCondExpression` that validates EVERY `*dag.Fail` it finds.

**How to avoid:** Validation runs only when `n.OutputAlias != ""` (per D4.2-09's explicit gate). The check is "if expression-mode, then enforce last-node = Result|Fail; otherwise allow Fail anywhere a body accepts nodes." Pin with a fixture `procedural_fail_in_then.star` that uses `if_cond(cond=..., then=[fail(...)], else_=[step(...)])` (no output_alias) and parses cleanly.

**Warning signs:** A previously-green fixture starts failing on the parse pass after Phase 04.2 lands.

### Pitfall 8: Custom MarshalJSON drift across `dag.Result` / `dag.Fail` in golden tests

**What goes wrong:** Golden tests in Phase 1 / Phase 04.1 marshal `dag.Flow` recursively; the embedded `dag.Result` / `dag.Fail` nodes use Go's default MarshalJSON, which includes `Pos` (with absolute filename) — golden output drifts across machines.

**Why it happens:** Plan 03-01 noted this as a "recurring retrofit pattern." Every dag node type with `Pos` needs a custom MarshalJSON that omits it.

**How to avoid:** Add `func (n *Result) MarshalJSON() ([]byte, error)` and `func (n *Fail) MarshalJSON() ([]byte, error)` mirroring `ifCondJSON` shape — emit `kind`, omit `Pos`, omit `Values` (not stable; lambda IDs and Fn pointers don't roundtrip), include `Keys` (string slice, stable) and `Types` (TypeInfo doesn't natively marshal — convert to a JSON-friendly shape per kind, or keep marker `Opaque` placeholder). For `Fail`, emit `kind`, `message`, optional `message_lambda_id`. Test the byte-stability across two marshals (Phase 1 plan 02 pattern).

**Warning signs:** Diff in golden file reveals `Pos.Filename` containing `/Users/...` absolute path.

```go
// Source pattern: /Users/mikel/dev/ai/temporero/pkg/interpreter/walk_script.go (the binding seam)
// /Users/mikel/dev/ai/temporero/pkg/interpreter/walk_ifcond.go (the if_cond walker)

// pkg/interpreter/walk_result.go
package interpreter

import (
    "go.starlark.net/starlark"
    "go.temporal.io/sdk/workflow"

    "github.com/mikelalcon/skytime/pkg/bridge"
    "github.com/mikelalcon/skytime/pkg/dag"
)

// bindResultToState assembles the per-key value lambdas of n into a
// Starlark dict (frozen for replay-determinism), then writes it under
// outputAlias in workflow state. n.Keys provides source-insertion order;
// dict iteration is via the slice, NOT `for k := range n.Values` (D3-23
// determinism rule + replay-twice equality).
//
// Emits a single `result_bound` slog event for renderer visibility.
func (i *interpreter) bindResultToState(ctx workflow.Context, outputAlias string, n *dag.Result) error {
    logger := workflow.GetLogger(ctx)

    out := starlark.NewDict(len(n.Keys))
    for _, k := range n.Keys {
        captured := n.Values[k]
        val, err := i.evalLambda(ctx, captured.ID)
        if err != nil {
            return err
        }
        if err := out.SetKey(starlark.String(k), val); err != nil {
            return err
        }
    }
    out.Freeze() // replay-deterministic; subsequent Items() iteration is byte-stable

    goVal, err := bridge.FromStarlarkValue(out)
    if err != nil {
        return err
    }
    i.state.setOutput(outputAlias, goVal)

    logger.Info("skytime",
        "event", "result_bound",
        "alias", outputAlias,
        "keys", n.Keys,
        "path", i.currentPath(),
    )
    return nil
}
```

```go
// pkg/interpreter/walk_fail.go
package interpreter

import (
    "fmt"

    "go.starlark.net/starlark"
    "go.temporal.io/sdk/temporal"
    "go.temporal.io/sdk/workflow"

    "github.com/mikelalcon/skytime/pkg/dag"
)

// raiseFail resolves n's message (literal or lambda-evaluated) and returns
// a non-retryable application error carrying the source position. The
// caller (walkIfCond) returns this; the named-return + defer in walkIfCond
// emits step_complete with status=err, kind=fail, summary=<resolved message>
// for renderer visibility.
//
// Fail message resolution mirrors stepDisplayLabel (walk_step.go) — eval
// errors fall back to the literal Message template (display-only attribute
// must not crash the workflow over a label, but failure semantics ARE
// preserved: the error still raises).
func (i *interpreter) raiseFail(ctx workflow.Context, n *dag.Fail) error {
    msg := n.Message
    if n.MessageFn != nil {
        val, err := i.evalLambda(ctx, n.MessageFn.ID)
        if err == nil {
            if s, ok := val.(starlark.String); ok {
                msg = string(s)
            }
        }
        // err or wrong type: fall back to literal Message (with `${...}` markers
        // still present; renderer can show them or strip).
    }
    return temporal.NewNonRetryableApplicationError(
        fmt.Sprintf("fail %s: %s", n.Pos, msg),
        "FailNode", nil,
    )
}
```

```go
// pkg/interpreter/walk_ifcond.go (extended)
func (i *interpreter) walkIfCond(ctx workflow.Context, n *dag.IfCond) (err error) {
    // ... existing cond eval + branch selection unchanged ...

    if len(branch) == 0 {
        return nil
    }

    // ... existing stepPath save/restore unchanged ...

    // NEW: split branch into "leading body" and "last node" so we can
    // walk the body normally then handle Result/Fail specially.
    if n.OutputAlias != "" && len(branch) > 0 {
        last := branch[len(branch)-1]
        leading := branch[:len(branch)-1]
        if werr := i.walkBody(ctx, leading); werr != nil {
            return fmt.Errorf("if_cond at %s: %w", n.Pos, werr)
        }
        switch lastNode := last.(type) {
        case *dag.Result:
            if berr := i.bindResultToState(ctx, n.OutputAlias, lastNode); berr != nil {
                return fmt.Errorf("if_cond at %s: %w", n.Pos, berr)
            }
            return nil
        case *dag.Fail:
            return i.raiseFail(ctx, lastNode)
        }
        // else: parse-time validator should have rejected — defensive fallthrough
    }

    // EXISTING procedural-mode path unchanged
    if werr := i.walkBody(ctx, branch); werr != nil {
        return fmt.Errorf("if_cond at %s: %w", n.Pos, werr)
    }
    return nil
}
```

## Type Inference Decision Table

| `*syntax.Literal` Token=BYTES | `b"data"` | `TypeOpaque` | MEDIUM | Bytes type not in our v1 vocabulary — punt. |

## Open Questions

1. **Should `dag.Result.Types` survive JSON round-trip in golden tests?**
   - What we know: `TypeInfo` is a Go-only sealed sum; JSON marshaling needs a per-kind discriminator.
   - What's unclear: do golden tests actually marshal Result nodes? Phase 1 plan 03-01 marshals every Node type — IfCond's then/else_ already marshals via `[]Node` element discriminator.
   - Recommendation: `dag.Result.MarshalJSON` emits `{kind: "Result", keys: [...], types: {<key>: {kind: "scalar", scalar: "int"}, ...}}` with an explicit discriminator; if the planner finds golden tests don't cover this, defer.

2. **Should the `result_bound` slog event become part of the live-block renderer's scope footer or stay as a leaf row?**
   - What we know: the existing if_cond block scope renders header (on `branch`) + indented children + footer (on `step_complete`). The result is a leaf inside the branch, so a leaf row reads naturally.
   - What's unclear: does the renderer render `result_bound` ALONGSIDE `step_complete{kind: if_cond}`, or as a third event between them?
   - Recommendation: emit `result_bound` BEFORE the if_cond's `step_complete` (same way `branch` is emitted before nested step events). The renderer's static path adds a `renderResultBound` case in `renderBazelLine`; the live block adds a `case "result_bound"` in `buildProgressEvent`'s switch.

3. **Per-key result-value lambda capture: should free-var validation run?**
   - What we know: `captureLambdaAtPosition` (used by interpolation) explicitly skips free-var validation: `freeVars := starlark.StringDict{}; freeVars.Freeze()`. The synthetic file mis-attributes module-level binding lookup.
   - What's unclear: result-value lambdas reference user-bound variables (e.g., `result(value={"x": ctx.repo, "y": gh.endpoint("admin")})` would close over `gh`). The interpolation lambdas don't have this issue (only `ctx.<expr>` syntax).
   - Recommendation: skip free-var validation for result-value lambdas (mirror interpolation). The D4-02 ctx walker handles `ctx.<name>` typos; module-level extension references like `gh.endpoint(...)` resolve via the parser-time globals dict at synthesis time. If a future case shows a free-var concern, add it then.

4. **Should `inferType` recurse into `ctx.a.b.c` multi-hop dot expressions?**
   - What we know: stateSchema is `map[string]TypeInfo`; if `ctx.input` is `TypeDict{Fields: {repo: string}}`, then `ctx.input.repo` should infer `string` — but ONLY if the schema actually populates `Fields`.
   - What's unclear: how does `flow(inputs={"input": "dict"})` populate the dict's `Fields`? Currently `Inputs` is `map[string]string` with type-hint strings ("dict", "list", etc.) — there's no nested-shape declaration.
   - Recommendation: v1 supports single-hop only (`ctx.<name>` → schema lookup). Multi-hop returns Opaque. v1.x: extend `flow(inputs=)` to accept nested dict-typed schemas (e.g., `{"input": {"repo": "string", "title": "string"}}`).

5. **What's the renderer indent depth for `result(...)` inside an if_cond branch?**
   - What we know: the existing path convention is `<idx>a` (then) / `<idx>b` (else); branch entry renders with depth+1.
   - What's unclear: result is a leaf inside the branch — does it render at the branch's depth or one deeper?
   - Recommendation: result renders at branch depth (same as nested step inside the branch). The live-block + static renderers indent leaves with `pathDepth(path)` per `pkg/cli/progress.go::pathDepth`.

6. **How do we register the new requirement IDs?**
   - What we know: Plan 04.1-07 added 7 IDs via a registrar plan (DSL-11/12/13, VAL-04, CLI-06/07, EX-FIX-01).
   - What's unclear: Does the planner add a similar registrar plan for DSL-14, DSL-15, VAL-05?
   - Recommendation: Yes — plan a registrar task as the LAST plan in Phase 04.2 (after implementation lands), mirroring 04.1-07's shape. It updates REQUIREMENTS.md (3 new IDs, count 62→65) and the Traceability table.
