## Decisions Made

- **Symmetric post-branch OutputAlias propagation in both walkers** — both `walkBodyForCtxValidation` (D4-02 ctx walker) and `walkValidateIfCondExpression` (branch-equality validator) need the same `schema.addUntyped(n.OutputAlias)` after both branches walk. Without it, downstream consumers fail validation; the symmetry mirrors how `script.OutputAlias` is added by both walkers. The alias is unconditionally added even on asymmetric branches (one fail) — the static schema cannot know which runtime branch ran; the fail path raises before any read at runtime.
- **`raiseFail` reused for procedural-mode dispatch** — plan 04's `raiseFail(ctx, n)` is location-agnostic: it resolves the message (literal or MessageFn) and returns NonRetryableApplicationError. Adding `case *dag.Fail: return i.raiseFail(ctx, n)` to walkNode makes it a single dispatch point for both procedural-mode leaves AND expression-mode last-position fails (the latter handled by walkIfCond's switch, not walkNode). One implementation, two call sites.
- **Defensive `case *dag.Result` in walkNode** — Result is only legal as the last node of an expression-mode if_cond branch. The validator (plan 03) rejects orphan Results at parse time. But if the validator regresses, walkNode now surfaces a deterministic OrphanResultNode error instead of "unknown node kind" or silent panic. Same defense-in-depth pattern as walk_ifcond.go's fallthrough on non-Result/Fail expression-mode terminators.
- **Fixture cond fix is a logic correction, not a workaround** — `lambda ctx: ctx.validation` returns the script's output dict, which is always truthy. The intended semantic was "branch on whether repo is set" — `ctx.validation.has_repo` evaluates the inner bool. Same bug shape consultants writing real flows would hit; fixing it in the example sets the right pattern.
- **expectedErrFlows lives at package level (not inside TestDifferentialCorpus)** — the plan's exact diff suggested either local or package-level; package-level is more discoverable for future fixture additions and matches the existing `corpusExtensions` helper's package-level shape.
