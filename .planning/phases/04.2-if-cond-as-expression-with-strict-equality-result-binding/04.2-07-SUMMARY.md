## Phase-Level Retrospective

**What went smoothly:**
- The synthesized-source path established by Phase 04.1's D4.1-01 desugarer was reused VERBATIM for both `${ctx.expr}` interpolation in fail() messages (plan 02) AND per-key value lambda synthesis in result() (plan 02). Zero new infrastructure for lambda capture; only new call sites. This is the cleanest reuse pattern across phases in the project so far.
- The state-schema widening from `stateSet` (name set) to `stateSchema` (typed map) preserved the D4-02 walker's API surface (has/clone/sortedKeys) verbatim — every existing TestFinalize_CtxAccess_* test stayed GREEN through the rename. The visibility-only callers continued to work via `addUntyped`, and only the new typed callers used the typed `add`.
- Plans 04 and 05 ran in parallel during Wave 3 with zero coordination friction (different file scopes — pkg/interpreter vs pkg/cli; the parallel-plan-05 agent's work integrated cleanly with plan 04's interpreter walker). The slog-attribute-name contract (event=result_bound, alias, keys, path) was the loose-coupling seam.
- The registrar plan (this one) followed Phase 04.1-07's shape verbatim, demonstrating that the registrar pattern is now a stable phase-finalization pattern.

**What was harder than expected:**
- The per-key value-lambda capture across plan-02-vs-plan-03 ownership took more iteration than expected. Plan 02 builds Result.Types best-effort against an empty schema (because the proper per-branch schema isn't available until the validator pass runs); plan 03's branch-equality validator re-runs inferType against the proper schema via reinferResultTypes. The two-tier (best-effort then authoritative) pattern is documented as a phase-internal pattern but adds complexity.
- Plan 04's eventCapturingLogger over slog.Handler was a Rule 1 deviation that cost ~5 minutes of debugging — workflow.GetLogger routes through testsuite.SetLogger (Temporal log.Logger interface), NOT slog.SetDefault. Future test scaffolds in pkg/interpreter should look at walk_step_namefn_test.go::captureLogger first before rolling a slog handler.
- Plan 06 surfaced the post-branch OutputAlias propagation gap (Rule 2 deviation): both D4-02 walker AND branch-equality validator walker needed the alias added after both branches walked. Symmetric mutation in two different walker call sites; mirrored from how script.OutputAlias is added by both walkers.
- Plan 02's pre-exec source rewriting for `result(value=dict-literal)` was an unanticipated workaround for Starlark's eager-evaluation semantics. The original plan assumed runtime kwarg defer; the actual implementation needed a pre-exec scan + AST validation + length-preserving sentinel rewrite to keep line/col positions stable. The pattern is documented and reusable for any future builtin whose kwargs need AST-only validation.

**What's deferred to v1.x (per CONTEXT.md deferred section):**
- Subtype/LUB rules for branch-equality (e.g., int as a subtype of float) — v1 requires explicit `float(x)` casts; future versions can introduce LUB widening with documented promotion rules.
- Optional fields in result dicts (e.g., `result(value={"id": ..., "tier"?: ...})`) — v1 requires structural equality on the full key set; future versions can introduce optional-field semantics.
- Cross-phase state typing exploitation — Phase 04.2's typed stateSchema is currently used only for branch-equality validation; future phases (Phase 5 E2E test harness, Phase 6 example project) can exploit the typed schema for additional static checks (e.g., type-aware kwarg validation, type-aware mock dispatch).
- A `match`/`switch` primitive — multi-branch expression-mode dispatch beyond binary if_cond. v1 sticks with binary if_cond + chained nesting; v1.x can add a match primitive that desugars to nested if_cond or stays first-class.
