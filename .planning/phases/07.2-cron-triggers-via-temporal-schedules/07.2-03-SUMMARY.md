## --cron-reconcile Boot Order (D-7.2-16)

```
RunE entry
├── 1. drain-timeout range validate
├── 2. setupServerLogging
├── 3. credfile sanity
├── 4. connectClient(cfg)
├── 5. NewWorker → w
├── 6. printStartupBanner (cron triggers render `cron @ {sched} ({tz})`)
├── 7. signal.Notify
├── 8. w.Start() → hookStage("worker_started")
├── 8a. IF --cron-reconcile:
│       ├── sc := cfg.scheduleFactory(c) OR c.ScheduleClient()
│       ├── plan, err := schedules.ReconcileCronSchedules(apply=true)
│       ├── err != nil → stderr "cron-reconcile failed: …" → return errSilent (NO hookStage)
│       ├── logger.Info("cron-reconcile applied", creates, updates, deletes)
│       └── hookStage("cron_reconcile_complete")
├── 9. receiver.Mount + http.NewServeMux
├── 10. net.Listen → ln
├── 11. srv.Serve(ln) goroutine → hookStage("listener_started")
└── 12. <-sigCh → drain (existing path)
```

The reconcile block sits between worker.Start (so the worker is live to pick up workflows fired by newly-created Schedules) and listener bind (so failed reconcile keeps K8s readinessProbe unready).

## Decisions Made

See `key-decisions` frontmatter. Highlights:

1. **`loadRegistries` lives in pkg/cli, not pkg/worker.** The public worker.LoadRegistries wrapper is a one-line addition to expose existing functionality; pkg/cli's `loadRegistries` is the thin CLI adapter that adds the empty-rootdir check and error-wrapping context.
2. **Cron banner format `cron @ {schedule} ({timezone})` keeps the operator-facing line readable at-a-glance.** Full ScheduleOptions are accessible via `skytime cron-plan` which streams every field.
3. **cron-plan subcommand position is between server and info** to reflect the operator workflow: `server --cron-reconcile` applies; `cron-plan` previews. They're paired.
4. **Parse-then-connect order in cron-plan.** Parse errors surface in <50ms without paying the network round-trip cost for an unreachable Temporal.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Test fixture .star content needed map= and idempotency_key= kwargs**
- **Found during:** Task 2 (TestServerCmd_CronReconcileFailureExitsNonZero compile + run)
- **Issue:** The plan's behavior block showed a minimal `trigger(flow=, source=core.cron(...))` fixture, but `pkg/parser/builtins.go::builtinTrigger` requires both `map=` and `idempotency_key=` as non-optional kwargs (only `credential=` is optional). Without them the parser rejects with `trigger: missing argument for map` before any reconcile logic runs.
- **Fix:** Added `map = lambda req: {}` and `idempotency_key = lambda req: str(req.scheduled_time)` to the test fixture's trigger declaration. Used the cron source's ReqSchema (`scheduled_time`) for the idempotency key — semantically deterministic for cron firings.
- **Files modified:** pkg/cli/server_test.go (makeCronServerTestDir), pkg/cli/cron_plan_test.go (makeCronPlanTestDir)
- **Verification:** All 5 server tests + 3 cron-plan tests parse the fixture successfully and exercise the downstream reconcile path.
- **Committed in:** e0d6658 (Task 2), 067b713 (Task 3)

**2. [Rule 3 — Blocking] worker.LoadRegistries public wrapper extracted from bootRegistry**
- **Found during:** Task 3 (cron-plan parse-side seam implementation)

- **Fix:** Added a one-line public wrapper `LoadRegistries(rootDir, exts) (*FlowRegistry, *TriggerRegistry, error)` in `pkg/worker/boot.go` that delegates to `bootRegistry`.
