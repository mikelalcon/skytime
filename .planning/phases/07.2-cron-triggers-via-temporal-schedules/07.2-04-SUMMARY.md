## Mid-UAT Deviations (UAT-Surfaced Defects)

**1. [UAT - Rule 2 Missing Critical] cron-plan output rendered in terraform-plan style**
- **Found during:** Task 4 UAT, Terminal 2 dry-run (criterion #3)
- **Issue:** The CLI's `cron-plan` subcommand emitted raw slog `level=info msg=... key=value` records — operator-hostile and unreadable next to the `temporal` CLI's own output. Plan 03's plan template assumed "paraphrase from RESEARCH lines 260-269" was sufficient; in practice operators expect a terraform-plan-style summary.
- **Fix:** Render `Plan: N to add, M to change, K to destroy` header + `+`/`~`/`-` markers per Schedule, mirroring `terraform plan`'s shape.
- **Files modified:** `pkg/cli/cron_plan.go`
- **Verification:** Manual UAT re-run — output is now operator-readable.
- **Commit:** `0465225` (fix(07.2-03): render cron-plan output in terraform-plan style)

**2. [UAT - Rule 2 Missing Critical] cron-plan output annotated with plain-English schedule descriptions**
- **Found during:** Task 4 UAT (follow-up to defect #1)
- **Issue:** Even with terraform-style markers, the cron expression `0 9 * * 1` is opaque to non-experts. The plan never required this; UAT surfaced it as essential operator UX.
- **Fix:** Added `pkg/cli/cron_describe.go` to annotate each plan entry with a `(Every Monday at 09:00)` / `(Every weekday at 09:00)` / `(Daily at HH:MM)` / `(Monthly on day D at HH:MM)` plain-English suffix. Includes unit tests.
- **Files modified:** `pkg/cli/cron_describe.go` (new), `pkg/cli/cron_describe_test.go` (new), `pkg/cli/cron_plan.go`
- **Verification:** Tests + UAT re-run.
- **Commit:** `242dbdf` (fix(07.2-03): annotate cron-plan output with plain-English schedule descriptions)

**3. [UAT - Rule 1 Bug + Rule 1 Bug, paired] SDK + workflow lifecycle logs were invisible AND cron-fired workflows crashed on missing scheduled_time**
- **Found during:** Task 4 UAT, criterion #5 attempt
- **Issue (a):** `skytime server`'s `buildSDKSlogLogger` routed all SDK + workflow logs to `io.Discard` unless `--verbose` was set. Operators saw no `workflow start`, no `step_complete`, no `flow_complete` lines — UAT criterion #5 could not be verified visually.
- **Issue (b):** Per the deferred D-7.2-20 decision, cron-fired workflows received `InitState: nil`. Every fire failed on missing `ctx.scheduled_time` (and `ctx.actual_time`) because the cron source's `ReqSchema=[scheduled_time, actual_time]` expects those keys to be present. The flow's first script step crashed before producing any output.
- **Fix:** (a) reassign `cfg.sdkLogger = logger` in `server.go` after `setupServerLogging` so the SDK uses the configured handler. (b) Add `pkg/interpreter/cron_input.go::extractScheduledTime` — regex over the WorkflowID's `-<RFC3339>` suffix (per RESEARCH.md Pitfall 2: Temporal Schedules appends a UTC RFC3339 timestamp to the action's WorkflowID for uniqueness). Inside `NewWorkflow`, when the workflow was Schedule-fired AND `scheduled_time`/`actual_time` are absent from InitState, auto-inject both. Updated the comment on `pkg/extension/schedules/schedules.go:291` to point at this new recovery path.
- **Files modified:** `pkg/cli/server.go`, `pkg/interpreter/cron_input.go` (new), `pkg/interpreter/cron_input_test.go` (new), `pkg/extension/schedules/schedules.go`
- **Verification:** UAT re-run produced the full lifecycle log block quoted under UAT Outcomes above. Unit tests in `cron_input_test.go` cover the regex's happy/sad paths.
- **Commit:** `5270f86` (fix(07.2): surface cron-fired workflow events + auto-inject schedule context)

**4. [UAT - Rule 2 Missing Critical] Demo cadence flipped to per-minute with Production note**
- **Found during:** Task 4 UAT, criterion #5 (visibility step)
- **Issue:** The original `0 9 * * 1` (Mondays at 09:00) schedule produced a Schedule that wouldn't fire during any reasonable UAT/walkthrough reading window. Section 7 ("Optional: Watch a schedule fire") required the reader to manually edit the .star file to `* * * * *` and restart. Friction without payoff — and the optional flag meant most readers never saw the criterion #5 lifecycle.
- **Fix:** Flip the example's default schedule to `* * * * *` with an inline code comment + walkthrough "Production note" subsection directing operators to weekly/daily cadences in real deployments. Add a `log_digest` script step at the end of `weekly_digest.star`'s body using `print() or {"logged": True}` so each fire emits a `[skytime/print] weekly digest complete: scheduled=... actual=... authors=1` line in server stdout. Walkthrough section 7 restructured from "(Optional) Watch a schedule fire" → "Watch a fire" (the default schedule fires within 60s, no edit needed). Sample cron-plan and startup banner outputs updated to match.
- **Files modified:** `examples/http-github-webhook/weekly_digest.star`, `docs/walkthroughs/cron-schedules.md`
- **Verification:** UAT walkthrough now reaches a visible fire within the natural reading window.
- **Commit:** `a359259` (docs(07.2): keep weekly_digest on per-minute demo cadence)

**5. [UAT - Backlog Capture] Structured logging step builtin (Phase 999.1)**

- **Commit:** `f199f8a` (docs: add backlog item 999.1)
