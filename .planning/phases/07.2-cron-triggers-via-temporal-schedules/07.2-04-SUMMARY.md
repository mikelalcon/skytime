**2. [Rule 3 — Blocking] Add map= + idempotency_key= identity lambdas to the cron trigger**
- **Found during:** Task 1 (initial `validate` run before `output_alias` fix)
- **Issue:** The plan's template `.star` block shipped a `trigger(flow=, source=core.cron(...))` declaration omitting `map=` and `idempotency_key=` per D-7.2-15 spec. But `pkg/parser/builtins.go::builtinTrigger` still requires both (only `credential=` is optional). Same issue Plan 03 already documented in its Deviation #1.
- **Fix:** Added `map = lambda req: {"scheduled_time": req.scheduled_time, "actual_time": req.actual_time}` and `idempotency_key = lambda req: req.scheduled_time` — identity lambdas reflecting the cron source's `ReqSchema=[scheduled_time, actual_time]`.
- **Files modified:** `examples/http-github-webhook/weekly_digest.star`, `docs/walkthroughs/cron-schedules.md` (the inspect-the-flow code block matches the real fixture), `docs/walkthroughs/cron-schedules-smoke.sh` (smoke fixture)
- **Verification:** `go run ./examples/http-github-webhook/cmd/extbin validate examples/http-github-webhook/weekly_digest.star` exit 0; `TestFlows_ParseAll` passes.
- **Committed in:** `57e6b9e` (Task 1 commit)

**3. [Rule 1 — Bug] Replace step(output_alias=) with script(output_alias=) for step output capture**
- **Found during:** Task 1 (first `validate` run)
- **Issue:** The plan's template `.star` block called `step(name=..., action_fn=..., output_alias="repo")`, but `output_alias` is only a valid kwarg on `script` and `if_cond` — NOT on `step` (`pkg/parser/builtins.go` searches show `output_alias` defined for those two primitives only). Validation failed with `step: unexpected keyword argument "output_alias"`. Compounding issue: even if `step()` accepted it, "Skytime v1 does not auto-bind step outputs into ctx" (public_repo_check.star comment line 39-40), so `ctx.repo.full_name` in the downstream script would not resolve.
- **Fix:** Restructured the flow to: (a) a `script(id="seed_authors", output_alias="grouped")` to seed the iteration list from a parse-time constant, (b) a `step(name="fetch repo info", action_fn=gh.get_repo(...))` that exercises the github extension call without capturing its output, (c) a `for_each_parallel(items=lambda ctx: ctx.grouped.authors)` doing the per-author summary line. The digest text is composed from `ctx.scheduled_time` + constant strings rather than `ctx.repo.full_name`. This preserves the `step_seq + for_each_parallel + script` primitives required by `TestFlows_CoverageMatrix`'s expected map for `weekly_digest`.
- **Files modified:** `examples/http-github-webhook/weekly_digest.star`
- **Verification:** `extbin validate examples/http-github-webhook/weekly_digest.star` exit 0; `TestFlows_CoverageMatrix` per-flow subtest for `weekly_digest` passes.
- **Committed in:** `57e6b9e` (Task 1 commit)

**4. [Rule 1 — Bug] Use --address (real flag) instead of --temporal (planning shorthand) in all documented commands**
- **Found during:** Task 2 (walkthrough authoring)
- **Issue:** The plan template's command examples used `--temporal=localhost:7233` throughout. The actual `extbin` binary's persistent global flag is `--address` (env: `SKYTIME_TEMPORAL_ADDRESS`); there is no `--temporal` flag. Documented commands that don't actually run would be a quality bug — users copy-pasting from the walkthrough would hit `unknown flag: --temporal`.
- **Fix:** Replaced every `--temporal=...` with `--address=...` in `docs/walkthroughs/cron-schedules.md`, `examples/http-github-webhook/README.md` Cron section, and `docs/walkthroughs/cron-schedules-smoke.sh`.
- **Files modified:** `docs/walkthroughs/cron-schedules.md`, `examples/http-github-webhook/README.md`, `docs/walkthroughs/cron-schedules-smoke.sh`
- **Verification:** `extbin server --help` and `extbin cron-plan --help` both show `--address` as the global persistent flag.
- **Committed in:** `57e6b9e` (Task 1 commit, README) + `3269e07` (Task 2 commit, walkthrough) + `b8ddf29` (Task 3 commit, smoke)
