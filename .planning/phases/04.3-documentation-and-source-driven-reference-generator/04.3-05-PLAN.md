## Operations Map (verbatim from pkg/extension/builtin/http/http.go::Operations)

| Op | Idempotent | KwargsType | Default Timeout |
|----|------------|------------|-----------------|
| get | **true** | GetArgs (path, headers) | 30s |
| head | **true** | GetArgs (path, headers) | 30s |
| post | **false** | BodyArgs (path, body, headers) | 30s |
| put | **false** (D4-14 override; RFC-7231 says true) | BodyArgs (path, body, headers) | 30s |
| delete | **false** (D4-14 override; RFC-7231 says true) | GetArgs (path, headers) | 30s |

## endpoint() factory — usage pattern

```python
# Top-level: bind a base URL + (optional) credential to a namespace.
gh = http.endpoint(base_url = "https://api.github.com", credential = "github_token")

# Then call operations on the namespace.
flow(
    name = "fetch_user",
    inputs = {"user_id": "string"},
    steps = [
        step(
            name = "Fetch ${ctx.user_id}",
            action = gh.get(path = "/users/${ctx.user_id}"),
        ),
    ],
)
```

`http.endpoint(...)` returns a credential-aware sub-Module whose attributes (`get`, `head`, `post`, `put`, `delete`) are *starlark.Builtin closures over `base_url` and `credential`. Each operation invocation produces an `*ActionRef` whose Kwargs Dict embeds `base_url` so the activity-side `OperationFunc` can reconstruct the full URL.

## GetArgs / BodyArgs Go structs (cite verbatim from pkg/extension/builtin/http/http.go)

```go
type GetArgs struct {
    Path    string            `star:"path,required"`
    Headers map[string]string `star:"headers"`
}

type BodyArgs struct {
    Path    string            `star:"path,required"`
    Body    string            `star:"body"`
    Headers map[string]string `star:"headers"`
}
```
The `star:` tags drive `extension.UnpackOperationKwargs` reflection. `path` is required; `body` and `headers` are optional. The `base_url` injection happens at parse time inside `endpointFactory` — not exposed to flow authors as a per-call kwarg.

## 4xx/5xx classification (quick-260502-onc)

- 2xx → OkResult with status summary in Output
- 3xx → followed automatically by Go's net/http (within timeout)
- 4xx → wraps `extension.ErrNonRetryable` → workflow's RetryPolicy is bypassed; surfaces as a NonRetryableErr → workflow fails (renderer prints "flow failed step I/M (reason)" with red marker)
- 5xx → plain error wrap → Temporal's RetryPolicy fires (default 3 attempts with exponential backoff unless step overrides retry=...)

The error message includes the HTTP status and the response body (truncated if >1KB) for diagnostic clarity.

## Credential Handling

The `credential=` kwarg on `http.endpoint(...)` accepts a string ID. The ID is recorded on every `*ActionRef.CredentialID` produced by ops on this namespace. At workflow-execute time, the activity invokes the registered `CredentialHandler.Resolve(ctx, id)` JIT to get the live `extension.Credential` value. The credential never enters workflow state.

Empty `credential=""` (or omitted) ⇒ anonymous endpoint — no resolver call (per pkg/activity empty-CredentialID bypass, Phase 4 quick).

    **`## Idempotence Policy (D4-14)` section:**
    ```
    ## Idempotence Policy (D4-14)

    | Operation | Idempotent | Notes |
    |-----------|------------|-------|
    | `get`    | **true**  | Matches RFC-7231 |
    | `head`   | **true**  | Matches RFC-7231 |
    | `post`   | **false** | Matches RFC-7231 |
    | `put`    | **false** | **Diverges** from RFC-7231 (which considers PUT idempotent) |
    | `delete` | **false** | **Diverges** from RFC-7231 (which considers DELETE idempotent) |

    ### Why diverge?

    PUT and DELETE are technically idempotent per the HTTP spec, but in
    practice (consultant flows hitting GitHub, Slack, internal APIs) the
    consequences of an accidental retry of a PUT/DELETE are usually
    worse than the cost of executing them one-action-per-activity. The
    v1 stance is the conservative one: treat them as side-effecting.

    Consultants writing their OWN extensions (Phase 6: GitHub, Slack,
    etc.) declare `Idempotent *bool` per operation in their
    `OperationSpec` map; nothing forces them to follow the bundled
    HTTP extension's choice. See
    [docs/for-extension-developers/README.md](../../for-extension-developers/README.md).

    ### Mixed-idempotency batches reject

    Batching a non-idempotent op with an idempotent one in the same
    `step(block=[...])` is rejected at parse time (Policy D, D2-05) so
    the activity layer never sees a mixed batch. Workaround: split into
    two `step(...)` calls.
    ```

    ## Credentials

    The `credential=` kwarg on `http.endpoint(...)` accepts a string ID:

    ```python
    gh = http.endpoint(
        base_url = "https://api.github.com",
        credential = "github_token",  # ID, not the secret itself
    )
    ```

    workflow-execute time, the generic activity invokes the registered
    `CredentialHandler.Resolve(ctx, id)` to fetch the live secret —
    just-in-time, inside the activity stack frame. The resolved
    `extension.Credential` value never escapes the activity; the
    operation receives it via parameter and never returns it.

    See [docs/architecture.md#no-context-bleed](../../architecture.md#no-context-bleed)
    for the architectural rationale, and
    [docs/cli-binary.md](../../cli-binary.md) for how to wire your own
    `CredentialHandler` (vault lookup, env vars, etc.).

    ### Empty / omitted credential

    `http.endpoint(base_url = "...", credential = "")` (or just
    `http.endpoint(base_url = "...")`) is an anonymous endpoint — no
    resolver call. The activity short-circuits the empty-ID lookup and
    passes `nil` to the operation's `cred` parameter. Useful for public
    APIs (e.g., open GitHub APIs that don't need a token).
    ```

                then = [step(action = gh.get(path = "/repos/${ctx.repo}"))],
                else_ = [fail("repo input is required")],
            ),
        ],
    )
    ```
