## User Constraints (from CONTEXT.md)

### Locked Decisions

**Surface shape (Area 1)**

- **D-7.2.1-01: Parser-time global `log` exposing four attributes.** `log.info`, `log.warn`, `log.error`, `log.debug`. Registration: `newParseTimeGlobals` (`pkg/parser/globals.go`) adds `"log": <module>` where `<module>` is a `*starlarkstruct.Module` (or equivalent attribute-bearing value) carrying four `starlark.NewBuiltin` factories. No `log.fatal` per roadmap.
- **D-7.2.1-02: Call signature `log.<level>(msg, attrs=lambda ctx: dict)`.** First positional arg is the msg string literal (may carry `${ctx.expr}` interpolation). Optional `attrs=` kwarg is a `lambda ctx: dict` evaluated at workflow time against `lambdaTimeGlobals` + ctx. No other kwargs in v1 (no `retry=`, no `timeout=`).
- **D-7.2.1-03: Empty msg ALLOWED.** `log.info("")` is legal; emits an empty slog message.
- **D-7.2.1-04: Multi-line msg ALLOWED.** `log.info("""line one\nline two""")` works. Surrounding literal may span lines.
- **D-7.2.1-05: Attrs-dict to slog attrs mapping.** Iterate via `*starlark.Dict.Items()` (insertion order). Scalars → typed slog attrs (`slog.String`, `slog.Int64`, `slog.Float64`, `slog.Bool`). `starlark.None` → `slog.Any(key, nil)`. Non-scalar values (lists, dicts, tuples) → `slog.Any(key, goValue)` after `bridge.FromStarlarkValue` conversion.
- **D-7.2.1-06: Reserved attr keys rejected at workflow time.** Keys in `{"level", "msg", "time", "source"}` abort with `NonRetryableErr` carrying the attrs-lambda position and the offending key name.
- **D-7.2.1-07: Hard cap of 32 attrs per call.** Greater than 32 → `NonRetryableErr` with attrs-lambda position.
- **D-7.2.1-08: Attr keys must match `^[a-zA-Z_][a-zA-Z0-9_]*$`.** Reject at workflow time with `NonRetryableErr`.

**print() builtin fate (Area 2)**

- **D-7.2.1-09: `print()` STAYS AS-IS.** D3-22 routing through `workflow.GetLogger.Info` with `[skytime/print]` tag is PRESERVED unchanged. No deprecation, no removal, no warning.
- **D-7.2.1-10: `print()` remains usable INSIDE ANY lambda.** No scoping restriction.
- **D-7.2.1-11: Audit corpus + docs for surviving `print() or {...}` shapes.** Grep `examples/`, `docs/`, and `pkg/parser/testdata/`. Migrate every occurrence to `log.info(...)`.

**Walker noise + tag (Area 3)**

- **D-7.2.1-12: Walker emits THREE structured slog records per call.** `step_dispatch kind=log label=<id_or_pos>` → user message at matching slog level → `step_complete kind=log status=ok|err duration_ms=N`.
- **D-7.2.1-13: Human-mode CLI renderer SUPPRESSES `kind=log` dispatch/complete frames.** Per-fire impact: ONE extra line in stdout per log call. The user-message record passes through, decorated with `[skytime/log]` prefix. Step counter `[N/M]` denominator EXCLUDES log steps.
- **D-7.2.1-14: JSON-log mode emits ALL THREE records verbatim.**
- **D-7.2.1-15: `kind="log"` on slog events.** Single discriminator (NOT `kind="log.<level>"`).
- **D-7.2.1-16: `log.<level>` is a SIDE-CHANNEL step in the author's mental model.** Failures inside attrs lambda or msg interpolation eval → `NonRetryableErr` with attrs-lambda position.

**Validation + docs scope (Area 4)**

- **D-7.2.1-17: First positional msg arg = STRING LITERAL only.** Non-literal → parse-time `*dag.ParseError`.
- **D-7.2.1-18: `log.<level>` at module scope is a parse-time error.** `"log.<level>: only valid as a step inside flow(...)"` mirrors how `step(...)` outside a flow is rejected. **(See "Open Questions" — no such precedent currently exists; the plan must add the check.)**
- **D-7.2.1-19: Docs = auto-gen markers + `cron-schedules.md` swap.** `// skytime:doc` markers on `builtinLogInfo/Warn/Error/Debug`; `go generate ./...` regenerates `docs/reference/builtins.md`. Update `docs/walkthroughs/cron-schedules.md` excerpt. NO new dedicated logging.md page.
- **D-7.2.1-20: Test coverage minimum.** Parser unit tests (4 levels × {literal, interpolated, with attrs, without attrs}) + rejection cases + interpreter walker test (`TestWorkflowEnvironment` capture, 4 levels routed) + replay-determinism test (3× `log.info` → exactly 3 records on replay) + `weekly_digest.star` smoke regression.

## Project Constraints (from CLAUDE.md)

CLAUDE.md directives that constrain this plan:

- **Tech stack fixed:** Go 1.25.x + Starlark + Temporal. No alternative DSLs. The plan MUST NOT introduce a new template language for log message interpolation — only the existing `${ctx.expr}` desugarer (D4.1-22 carve-out) is sanctioned.
- **Architecture:** Strict parse/execute separation. The `log.<level>(...)` builtin runs at parse time and produces a `*dag.LogStep` node; NO slog records, NO `workflow.GetLogger` calls, NO I/O at parse time. The walker runs at workflow execute time.
- **Determinism:** Parsed DAG must be deterministic (replay-safe). Walker MUST use `workflow.GetLogger(ctx)` only — never `slog.Default()`, never a captured logger pointer at construction time. Attrs-dict iteration MUST use `*starlark.Dict.Items()` (insertion order; replay-safe).
- **No string compilation carve-out:** Per D4.1-22, `${ctx.expr}` interpolation desugars to a `lambda ctx: ...` at parse time. No new runtime template engine. The plan reuses `desugarInterpolation` verbatim.
- **`go.temporal.io/sdk` v1.42.0 fixed.** `workflow.GetLogger` returns a `log.Logger` interface (Debug/Info/Warn/Error) — NOT a `*slog.Logger`. The walker must call `logger.Info(msg, keyvals...)` shape, not `logger.LogAttrs(...)`.
- **Library root has no cobra/charm-log dependency.** The walker lives in `pkg/interpreter` (library); the renderer suppression lives in `pkg/cli` (allowed). The `kind=log` filter in `pkg/cli/progress_static.go` does NOT cross the firewall.
- **GSD workflow enforcement:** Phase work goes through `/gsd:execute-phase`; no direct edits outside the workflow. Quality > speed.

## Summary

Phase 7.2.1 adds a first-class `log.<level>(...)` step type to Skytime's DSL by composing six existing primitives that the codebase already ships:

1. **Parse-time builtin registration** in `newParseTimeGlobals` (a `*starlarkstruct.Module` of four `starlark.NewBuiltin` factories — same shape as `core.cron`).
2. **Per-level builtin factories** mirroring `builtinScript` (≈60 lines each) — kwarg unpacking, msg-literal type assertion, `desugarInterpolation` for `${ctx.expr}`, `captureLambda` for the optional `attrs=` lambda, `wrapNode` for the result.
3. **A new `*dag.LogStep` sealed Node** in `pkg/dag/control.go` carrying `Pos`, `Level string`, `Msg string`, `MsgFn *CapturedLambda` (`json:"-"`), `AttrsLambdaID string`. Sibling shape to `*dag.Script` minus `OutputAlias`.
4. **A new walker `walkLog`** in `pkg/interpreter/walk_log.go` (≈80 lines) that mirrors `walkScript`: emit `step_dispatch kind=log` → eval msg interpolation lambda (if any) → eval attrs lambda (if any) → call `workflow.GetLogger(ctx).<Level>(resolvedMsg, attrs...)` → emit `step_complete kind=log` via deferred named-return. Wired into `pkg/interpreter/workflow.go::walkNode` switch (`case *dag.LogStep:`).
5. **Render-side suppression** in `pkg/cli/progress.go` / `pkg/cli/progress_static.go` — Bazel-style renderer filters `kind=log` dispatch/complete; the user-message record (no `event` attr) passes through to the wrapped charm-log handler with a `[skytime/log]` decoration. Counter `[N/M]` denominator excludes log steps.
6. **Migration of `weekly_digest.star`** + a corpus audit (only one `print() or {...}` callsite found; verified) + walkthrough doc update.

Replay safety is delegated to the Temporal SDK's `ReplayLogger` (verified in `internal/log/replay_logger.go`): `workflow.GetLogger(ctx).Info(...)` only emits when `!isReplay || enableLoggingInReplay`. The walker NEVER captures the logger at construction; it ALWAYS calls `workflow.GetLogger(ctx)` per step.

**Primary recommendation:** Implement as a copy-and-trim of `walkScript` (walker), `builtinScript` (factory), `*dag.Script` (DAG node), with a one-line wire-up in `walkNode` and a 20-line filter in the progress handler. The contract for everything load-bearing — replay safety, determinism, error attribution — is already enforced by upstream code. The phase's only original engineering is (a) attrs-dict semantic validation (reserved keys, ≤32 attrs, identifier-shaped keys), (b) the kind=log render filter, (c) the module-scope-rejection check (not currently enforced for any other builtin — must be added).

### Pattern 2: builtin factory mirroring `builtinScript`

The exact template to copy is `pkg/parser/builtins.go::builtinScript` (lines 1094-1143). Example for `builtinLogInfo`:

```go
// Source: pkg/parser/builtins.go::builtinScript (template at lines 1094-1143)
// Adapted for log.info — minus output_alias kwarg, plus optional attrs lambda.
func (p *Parser) builtinLogInfo(thread *starlark.Thread, fn *starlark.Builtin, args starlark.Tuple, kwargs []starlark.Tuple) (starlark.Value, error) {
    var (
        msgVal   starlark.Value
        attrsVal starlark.Value
    )
    if err := starlark.UnpackArgs("log.info", args, kwargs,
        "msg", &msgVal,
        "attrs?", &attrsVal,
    ); err != nil {
        return nil, p.wrapBuiltinError("log.info", thread, err)
    }
    pos := callerPosition(thread)

    // D-7.2.1-17: msg MUST be a string literal at parse time.
    msgStr, ok := msgVal.(starlark.String)
    if !ok {
        return nil, &dag.ParseError{
            Pos: pos,
            Msg: fmt.Sprintf("log.info: msg must be a string literal, got %s", msgVal.Type()),
        }
    }
    msg := string(msgStr)

    // ${ctx.expr} → CapturedLambda via D4.1-22 desugarer (REUSED VERBATIM).
    var msgFn *dag.CapturedLambda
    if strings.Contains(msg, "${") {
        desugared, derr := p.desugarInterpolation(msg, pos)
        if derr != nil {
            return nil, derr
        }
        msgFn = desugared
    }

    // Optional attrs lambda. D-7.2.1-02: lambda ctx: dict.
    var attrsLambdaID string
    if attrsVal != nil && attrsVal != starlark.None {
        captured, cerr := p.captureLambda(thread, "attrs", attrsVal)
        if cerr != nil {
            return nil, cerr
        }
        attrsLambdaID = captured.ID
    }

    return wrapNode(&dag.LogStep{
        Pos:           pos,
        Level:         "info",
        Msg:           msg,
        MsgFn:         msgFn,
        AttrsLambdaID: attrsLambdaID,
    }), nil
}
```

`builtinLogWarn`/`Error`/`Debug` are identical except `"log.<level>"` strings and `Level: "<level>"`. Recommend extracting a private helper `(p *Parser) buildLogStep(thread, level, args, kwargs)` to avoid quadruple duplication.

### Pattern 3: DAG node mirroring `*dag.Script`

The exact template to copy is `pkg/dag/control.go::Script` (lines 38-62). Sibling shape:

```go
// Source: pkg/dag/control.go:38-62 (Script template)
// New type: LogStep — sibling of Script minus OutputAlias plus Level + MsgFn naming.
type LogStep struct {
    Pos syntax.Position

    // Level is one of "info" | "warn" | "error" | "debug" (D-7.2.1-01).
    Level string

    // Msg is the LITERAL template the .star author wrote — including any
    // ${ctx.expr} markers. Cosmetic edits to this string change the
    // file content hash and therefore the (synthesized) MsgFn.ID.
    Msg string

    // MsgFn is the resolved-at-runtime variant of Msg. Populated when
    // Msg contained ${...} markers (D4.1-22 desugarer); the walker
    // evaluates this lambda to produce the rendered message string.
    // Mutually exclusive with literal Msg at the runtime layer (Pos
    // tells the walker which path to take).
    //
    // json:"-" because *CapturedLambda holds a *starlark.Function pointer
    // that does not round-trip through Temporal's JSON serializer
    // (mirrors Script.IDFn precedent).
    MsgFn *CapturedLambda `json:"-"`

    // AttrsLambdaID resolves into WorkflowInput.Lambdas at workflow time.
    // Empty string means no attrs= kwarg was provided.
    AttrsLambdaID string
}

var _ Node = (*LogStep)(nil)

func (*LogStep) Kind() string                  { return "LogStep" }
func (n *LogStep) Position() syntax.Position   { return n.Pos }
func (*LogStep) nodeMarker()                   {}
```

Stable JSON marshal mirrors `scriptJSON` in `pkg/dag/marshal.go:164-179` — fields `kind, level, msg, attrs_lambda_id` (omit Pos for cross-machine stability per the file-header rule on line 19).

```go
// go.temporal.io/sdk@v1.42.0/internal/log/replay_logger.go).
//
// Step protocol (D-7.2.1-12): emits step_dispatch + user message at level
// + step_complete. Renderer (pkg/cli) suppresses dispatch/complete in
// human mode (D-7.2.1-13); JSON-log mode emits all three (D-7.2.1-14).
func (i *interpreter) walkLog(ctx workflow.Context, n *dag.LogStep) (err error) {
    logger := workflow.GetLogger(ctx)
    start := workflow.Now(ctx)
    path := i.currentPath()
    idx, total := i.stepIdx, i.stepTot
    label := "log" // D-7.2.1: synthetic label, no id= kwarg in v1.

    logger.Info("skytime",
        "event", "step_dispatch",
        "kind", "log",
        "label", label,
        "level", n.Level,
        "idx", idx, "total", total, "path", path,
    )
    defer func() {
        status := "ok"
        summary := ""
        if err != nil {
            status = "err"
            summary = err.Error()
        }
        logger.Info("skytime",
            "event", "step_complete",
            "kind", "log",
            "label", label,
            "status", status,
            "duration_ms", workflow.Now(ctx).Sub(start).Milliseconds(),
            "idx", idx, "total", total, "path", path,
            "summary", summary,
        )
    }()

    // 1. Resolve the message — literal or interpolated.
    msg := n.Msg
    if n.MsgFn != nil {
        val, evalErr := i.evalLambda(ctx, n.MsgFn.ID)
        if evalErr != nil {
            return evalErr
        }
        s, ok := val.(starlark.String)
        if !ok {
            return temporal.NewNonRetryableApplicationError(
                fmt.Sprintf("log.%s at %s: msg lambda returned %s, expected string", n.Level, n.Pos, val.Type()),
                "LogMsgTypeError", nil,
            )
        }
        msg = string(s)
    }

    // 2. Resolve attrs — optional dict-returning lambda → []any keyvals slice.
    var keyvals []any
    if n.AttrsLambdaID != "" {
        val, evalErr := i.evalLambda(ctx, n.AttrsLambdaID)
        if evalErr != nil {
            return evalErr
        }
        d, ok := val.(*starlark.Dict)
        if !ok {
            return temporal.NewNonRetryableApplicationError(
                fmt.Sprintf("log.%s at %s: attrs lambda returned %s, expected dict", n.Level, n.Pos, val.Type()),
                "LogAttrsTypeError", nil,
            )
        }
        // D-7.2.1-07: cap.
        if d.Len() > 32 {
            return temporal.NewNonRetryableApplicationError(
                fmt.Sprintf("log.%s at %s: attrs dict has %d entries (max 32)", n.Level, n.Pos, d.Len()),
                "LogAttrsTooLarge", nil,
            )
        }
        // D-7.2.1-05 + D-7.2.1-08 + D-7.2.1-06: iterate Items() (insertion
        // order — replay-safe per Phase 04.1 D4.1-14 precedent).
        keyvals = make([]any, 0, d.Len()*2)
        for _, item := range d.Items() {
            ks, ok := item[0].(starlark.String)
            if !ok {
                return temporal.NewNonRetryableApplicationError(
                    fmt.Sprintf("log.%s at %s: attr key must be string, got %s", n.Level, n.Pos, item[0].Type()),
                    "LogAttrKeyType", nil,
                )
            }
            key := string(ks)
            // D-7.2.1-08: identifier-shaped.
            if !isIdentifierShaped(key) {
                return temporal.NewNonRetryableApplicationError(
                    fmt.Sprintf("log.%s at %s: attr key %q not identifier-shaped (^[a-zA-Z_][a-zA-Z0-9_]*$)", n.Level, n.Pos, key),
                    "LogAttrKeyShape", nil,
                )
            }
            // D-7.2.1-06: reserved.
            if isReservedSlogKey(key) {
                return temporal.NewNonRetryableApplicationError(
                    fmt.Sprintf("log.%s at %s: attr key %q is reserved (slog standard field)", n.Level, n.Pos, key),
                    "LogAttrKeyReserved", nil,
                )
            }
            // D-7.2.1-05: type-aware coercion.
            attr := starlarkValueToSlogAttr(key, item[1]) // helper builds slog.Attr or falls back to slog.Any+bridge.FromStarlarkValue
            keyvals = append(keyvals, attr.Key, attr.Value.Any())
        }
    }

    // 3. Route through workflow.GetLogger at the matching level.
    switch n.Level {
    case "debug":
        logger.Debug(msg, keyvals...)
    case "info":
        logger.Info(msg, keyvals...)
    case "warn":
        logger.Warn(msg, keyvals...)
    case "error":
        logger.Error(msg, keyvals...)
    default:
        // Unreachable: parser fixes Level to one of the four; defense in depth.
        return temporal.NewNonRetryableApplicationError(
            fmt.Sprintf("log: unknown level %q", n.Level),
            "LogUnknownLevel", nil,
        )
    }
    return nil
}
```

The walker MUST NOT call `setOutput` (log is side-channel — no `output_alias`).

**Counter denominator (D-7.2.1-13: `[N/M]` excludes log steps).** The current renderer reads `total` from the slog record's `total` attr, which is set by `walkBody` to `len(body)`. To exclude log steps from M, EITHER:
- **Option A (renderer-side):** the renderer subtracts the count of log siblings from `total`. Requires the renderer to know about the body shape — leaky.
- **Option B (interpreter-side):** `walkBody` computes a `nonLogTotal` and passes that as the `total` attribute on dispatch/complete events for non-log siblings; log steps' dispatch/complete (suppressed in human mode anyway) carry the full total.
- **Option C (walker-side):** in `walkBody` (`pkg/interpreter/workflow.go:171-182`), pre-count `nonLogCount := count of body where _, ok := node.(*dag.LogStep); !ok`, pass that as `stepTot`. Indexing also skips log siblings so `idx` runs 1..nonLogCount.

**Recommendation:** Option C. Log steps still emit their `step_dispatch kind=log` (idx/total don't matter — renderer suppresses in human mode anyway), but non-log siblings' counters reflect the visible denominator. Requires touching `walkBody` to compute the denominator and to advance `i.stepIdx` only on non-log nodes. (See Open Questions §3 for nuance.)

### Anti-Patterns to Avoid

- **DON'T** capture `slog.Default()` or `*slog.Logger` at walker construction — replay safety hinges on per-call `workflow.GetLogger(ctx)`. The Temporal SDK's `ReplayLogger` is the seam that suppresses replay records; bypassing it produces duplicate records on every workflow replay.
- **DON'T** introduce a runtime template engine for message interpolation. The D4.1-22 desugarer (`desugarInterpolation` in `pkg/parser/interpolation.go`) is the only sanctioned mechanism. Anything else violates the "no string compilation" rule (PROJECT.md, CLAUDE.md).
- **DON'T** sort attr keys in the walker. `*starlark.Dict.Items()` already returns insertion order — sorting would (a) change observable order and (b) needlessly add a `sort.Strings` call. Phase 04.1 D4.1-14 locked this convention; replay determinism comes from Starlark's language contract, not Go map ordering.
- **DON'T** add a new firewall rule. Phase 7.2.1 stays within already-permitted packages.
- **DON'T** validate attr key shape / reserved keys / count at parse time. The attrs lambda result is only known at workflow time — semantic validation MUST run in the walker (`walker-side` per CONTEXT.md). The parser only enforces "msg is a string literal" and the module-scope check.
- **DON'T** wire the `[skytime/log]` prefix decoration as a slog handler — the walker emits the prefix directly into the message string, mirroring `[skytime/print]` (D3-22 in `lambda_eval.go:35`).
- **DON'T** call `temporal.NewNonRetryableApplicationError` from a captured lambda's free-var space — these errors must originate in Go code (the walker), not in user lambdas. Lambda-time `fail()` is the user-facing escape hatch.

## Common Pitfalls

### Pitfall 1: `workflow.GetLogger` returns `log.Logger`, NOT `*slog.Logger`

**What goes wrong:** Treating the return value of `workflow.GetLogger(ctx)` as `*slog.Logger` and calling `.LogAttrs(ctx, level, msg, attrs...)` won't compile. The two interfaces are NOT compatible.

**Why it happens:** `slog` is the project's "logging interface" per CLAUDE.md, and `slog.Attr` is the natural type for typed attrs (`slog.String("k", "v")`). It's tempting to assume `workflow.GetLogger` returns a `*slog.Logger`. It does NOT.

**Evidence:** `/Users/mikel/go/pkg/mod/go.temporal.io/sdk@v1.42.0/log/logger.go` lines 3-10:

```go
type Logger interface {
    Debug(msg string, keyvals ...interface{})
    Info(msg string, keyvals ...interface{})
    Warn(msg string, keyvals ...interface{})
    Error(msg string, keyvals ...interface{})
}
```

Only the four-method interface exists. No `LogAttrs`, no level enum.

**How to avoid:** Build a flat `keyvals []any` slice (alternating key string, value any) and pass it as variadic `keyvals...` to `logger.Info(msg, keyvals...)`. The slog handler downstream (set via `setupServerLogging` or the SDK adapter) interprets the keyvals as structured attrs. The walker can still build `slog.Attr` values for type fidelity, then unpack `(attr.Key, attr.Value.Any())` into the keyvals slice.

**Warning signs:** Compile error `logger.LogAttrs undefined (type log.Logger has no field or method LogAttrs)`, or runtime panic on a type assertion `logger.(*slog.Logger)`.

### Pitfall 2: There is NO existing "node value at module scope" check

**What goes wrong:** CONTEXT.md D-7.2.1-18 implementation note says "the builtin returns a `nodeWrap` value; existing 'node at module scope' checks reject it." This is INCORRECT — no such check exists in the codebase today.

**Why it happens:** `step(...)` and other body-only builtins all return `*nodeValue` (boxed `dag.Node`). When called at module scope, Starlark evaluates them as expression statements and discards the value. There is no validation pass that walks top-level expressions to flag orphan node values. (`validateResultPlacement` in `pkg/parser/finalize.go:980-1023` is the closest analogue — it walks flow bodies looking for misplaced `*dag.Result`, but it does NOT check top-level orphans because `result()` only registers in `p.preBuiltResults`, not in any flow body.)

**Evidence:** `grep -rn "module.scope\|orphan.*step\|outside.*flow" /Users/mikel/dev/ai/temporero/pkg/parser/` returns zero matches for an enforcement check; tests for `step()` outside a flow do not exist.

**How to avoid:** The plan must ADD the check explicitly. Options:

- **Option A (preferred):** Add a new finalize pass `validateLogStepPlacement` in `pkg/parser/finalize.go` that walks `p.flows[*].Body` recursively to confirm every `*dag.LogStep` lives inside a flow. AND register a parser-side hook to detect orphan log calls at module scope. Mechanism for the orphan check: capture `*dag.LogStep` values returned from `builtinLog*` in a `p.allLogSteps []*dag.LogStep` set; after parse, walk every `flow.Body` to mark which ones are flow-resident; any unmarked `*dag.LogStep` is module-scope and rejects with the position-aware error.
- **Option B (simpler):** Track the call-stack depth at builtin invocation time. When `builtinLog*` runs, walk `thread.CallStack()` upward; if the closest enclosing `*starlark.Builtin` call is `flow` (parse-time, on the `flow.steps=[...]` list construction), allow. Otherwise reject. This is fragile (depends on Starlark's call-frame shape).
- **Option C (also simpler):** Don't reject at parse time at all — let module-scope `log.info(...)` succeed but be discarded silently. Pragmatic but violates the success criterion #5 contract ("Parser rejects `log.<level>` outside a `flow(...)` body").

**Recommendation:** Option A, modeled on `validateResultPlacement`. The existing finalize-pass infrastructure makes this straightforward.

**Warning signs:** A `.star` file like `log.info("at module scope")` parses without error and silently no-ops at workflow time (because no flow body contains it). Test fixture `tests/fixtures/log_outside_flow.star` should fail parse.

### Pitfall 3: `*starlark.Dict.Items()` insertion order vs Go-map iteration

**What goes wrong:** Iterating attrs via `for _, item := range d.Items() { ... }` is replay-safe; iterating via `for k, v := range goMap { ... }` (e.g., after `bridge.FromStarlarkValue` returns a `map[string]any`) is NOT — Go map iteration order is randomized.

**Why it happens:** It's natural to convert the Starlark dict to a Go map first (single FromStarlarkValue call), then iterate. The conversion drops insertion order.

**Evidence:** Phase 04.1 D4.1-14 locked this convention; `pkg/interpreter/resolve_kwargs.go` and `pkg/interpreter/walk_result.go` both iterate `.Items()` with comment blocks pinning the rule. Replay tests (`pkg/interpreter/replay_determinism_test.go::TestReplay_DictKeyOrderDeterministic`) explicitly assert non-alphabetical key order survives replay.

**How to avoid:** Iterate `d.Items()` directly in the walker. Convert per-value via `bridge.FromStarlarkValue(item[1])` only AFTER materializing each `(key, value)` pair from `.Items()`.

**Warning signs:** Replay test fails intermittently. Two consecutive runs of the same flow produce slog records whose attr order differs. CI is green most of the time.

### Pitfall 4: Lambda `Fn` doesn't round-trip through Temporal serialization

**What goes wrong:** `*dag.CapturedLambda.Fn` is a `*starlark.Function` — not JSON-serializable. If `LogStep.MsgFn` is marshaled directly, it serializes to `null` or panics.

**Why it happens:** Temporal serializes workflow inputs (and re-deserializes on replay / continue-as-new). The `*dag.CapturedLambda` is referenced in `WorkflowInput.Lambdas` by ID — the lambda body is reconstructed from parsed file bytes at worker boot, NOT from JSON.

**Evidence:** `pkg/dag/control.go:51` — `Script.IDFn *CapturedLambda` carries `json:"-"`. Same pattern needed for `LogStep.MsgFn`.

**How to avoid:** Tag `MsgFn *CapturedLambda \`json:"-"\`` on the `LogStep` struct. The DAG JSON shape carries `msg_lambda_id` (string) only, mirroring `failJSON.MessageLambdaID`; the walker resolves the ID via `i.evalLambda(ctx, n.MsgFn.ID)` which looks up `i.parsed.Lambdas[ID]` (rebuilt at worker boot from file content hash).

**Warning signs:** Marshal test produces `"msg_fn": null`; lambda lookup fails on the second worker boot with `"lambda not found in flow ..."`.

### Pitfall 5: `step_dispatch` event without `name` / `pos` attrs may break debugging tools

**What goes wrong:** `walk_step.go:42-46` emits both `name` and `pos` attrs on `step_dispatch` events because Phase 5 D5-D3 added them as a "stable KV for divergence-attribution lookup." `walkScript` does NOT emit them — only walk_step does. The new `walkLog` follows `walkScript`'s precedent (no `name`/`pos`), but if any test framework uses divergence-attribution against log steps, it'll mismatch.

**Why it happens:** Inconsistent emission across walkers. Easy to overlook when copying `walkScript`.

**Evidence:** `pkg/interpreter/walk_step_actionfn_test.go:429-479` asserts `name` and `pos` on dispatch events — but only checks step kind. `walk_script.go` doesn't emit them and has no equivalent test.

**How to avoid:** Decide explicitly: does `walkLog` need `name` / `pos` on dispatch? D5-D3 was about the divergence-attribution path used by `pkg/testing` (Tier-3 test harness). Log steps are side-channels and are unlikely to ever participate in divergence reports. Recommend: omit `name`/`pos` on dispatch (mirror `walkScript`), but add `pos` to `step_complete err` paths if a failure attribution test ever lands.

**Warning signs:** Future Phase 5 test asserts `name` attr on a `kind=log` event; assertion fails. Manageable when it surfaces.

### Pitfall 6: Render-side suppression interaction with `--verbose` mode and JSON-log mode

**What goes wrong:** D-7.2.1-13 says human-mode suppresses; D-7.2.1-14 says JSON-log emits everything. The `progressHandler` only filters `event=*` records to its renderer in `Handle()`; the wrapped charm-log handler (or JSON handler) sees passthrough records. But `step_dispatch` IS an `event=*` record — it goes through `renderBazelLine`, not through the wrapped handler. So in human mode, suppressing in the renderer DOES drop the event. In JSON-log mode, the entire `progressHandler` chain is bypassed (server uses `setupServerLogging` directly, NOT `buildRoutedSlogLogger`) — so `kind=log` `step_dispatch`/`step_complete` records flow through `slog.NewJSONHandler` unfiltered. Good.

**Why it happens:** Two parallel rendering paths (`skytime run` uses `buildRoutedSlogLogger` → `progressHandler`; `skytime server` uses `setupServerLogging` → plain charm-log or JSON handler). The progressHandler filter is a `skytime run`-only behavior. For `skytime server` human mode, the user-message record is rendered by charm-log directly; the dispatch/complete events also flow through charm-log directly (no progressHandler suppression).

**Evidence:** `pkg/cli/server.go:106` calls `setupServerLogging`; `pkg/cli/run.go:88` calls `buildRoutedSlogLoggerWithHandle`. Different chains.

**How to avoid:** The phase needs to define WHICH path's suppression matters. The success criterion #2 anchors on `skytime server` stdout — which uses `setupServerLogging` (no progressHandler). Two options:

- **Option A:** Add the kind=log filter to BOTH paths — `progressHandler` (run subcommand) AND a new tiny wrapper handler around `setupServerLogging`'s charm-log handler (server subcommand). Both wrappers drop `kind=log` `step_dispatch`/`step_complete` events in non-JSON mode.
- **Option B:** Have the WALKER decide whether to emit dispatch/complete based on a config flag. Rejected — that breaks the "JSON log mode emits everything" contract (D-7.2.1-14) and bleeds rendering concerns into the interpreter.

**Recommendation:** Option A. The plan must extend BOTH `progressHandler` (for `skytime run` walkthroughs) AND `setupServerLogging` (for `skytime server` operator stdout). The wrapper around charm-log can be a small `slog.Handler` decorator that checks `kind=log` + presence of `event=step_dispatch|step_complete` and short-circuits.

**Warning signs:** `skytime server` human stdout shows `INFO skytime event=step_dispatch kind=log ...` lines despite the spec requiring suppression. Renderer test passes (only exercises `skytime run` path) but UAT immediately catches it.

### Pitfall 7: Counter denominator `[N/M]` must exclude log steps

**What goes wrong:** `walkBody` (`pkg/interpreter/workflow.go:171-182`) sets `i.stepTot = len(body)`. For a flow with 4 visible steps + 1 log step, `total=5` flows into every dispatch event. Renderer prints `[1/5] ... [4/5] step ✓` but the user expected `[N/4]` (since the log step doesn't render).

**Why it happens:** The walker counts every body node uniformly. Log steps look like any other dag.Node to `walkBody`.

**How to avoid:** Modify `walkBody` to:
1. Count `nonLogTotal := count of body where _, isLog := node.(*dag.LogStep); !isLog`.
2. Track a separate `nonLogIdx` for non-log siblings.
3. For non-log nodes, set `i.stepTot = nonLogTotal`, `i.stepIdx = nonLogIdx`.
4. For log nodes, the dispatch/complete events carry the same counters (suppressed in human mode, visible in JSON mode where exact counter values are less load-bearing).

This requires touching `walkBody` (one block of ~20 lines) and a new walk test for "interleaved log + step counter values are correct."

## Open Questions

1. **No existing module-scope orphan-node check** — see Pitfall 2.
   - What we know: `step()` returns `*nodeValue` and is silently allowed at module scope today (no enforcement).
   - What's unclear: whether the plan should add a generic "orphan node values at module scope are an error" check (catching `step()` outside flow as a side-effect) OR a log-specific check.
   - Recommendation: implement a log-specific check first (`validateLogStepPlacement` finalize pass) for minimal blast radius. A generic orphan-node-at-module-scope rule would be a separate phase (it would break existing tests/fixtures that may rely on the silent-allow behavior). Document the asymmetry in the plan.

2. **Renderer suppression: server vs run path** — see Pitfall 6.
   - What we know: `skytime server` uses `setupServerLogging` (no progressHandler); `skytime run` uses `buildRoutedSlogLogger` (progressHandler).
   - What's unclear: whether the kind=log filter should live in BOTH paths or only in `setupServerLogging`'s wrapped charm-log handler. The success criteria all anchor on `skytime server`, so server suppression is mandatory; `skytime run` is less critical.
   - Recommendation: implement the filter as a small reusable `slog.Handler` decorator (`logKindFilterHandler`) and wire it into BOTH paths. ~20 LoC; tests in both `pkg/cli/render_test.go` and `pkg/cli/server_test.go`.

3. **Counter denominator `[N/M]` excludes log steps — exact mechanism** — see Pitfall 7.
   - What we know: `walkBody` sets `stepTot = len(body)` indiscriminately.
   - What's unclear: whether `walkBody` should pre-count non-log siblings (touching the walker, affects every walker), OR whether the renderer should re-count by inspecting the suppressed-dispatch events (renderer-side, leaks DAG knowledge into pkg/cli).
   - Recommendation: walker-side. Modify `walkBody` to compute `nonLogTotal` and advance `stepIdx` only for non-log nodes. Add `walkBody` test verifying counters with interleaved log + non-log siblings.

4. **`step_dispatch` `name`/`pos` attrs on log events** — see Pitfall 5.
   - What we know: `walkStep` emits `name`/`pos`; `walkScript` does not.
   - What's unclear: whether log dispatch should include them (for future divergence-attribution use cases).
   - Recommendation: omit them v1 (mirror `walkScript`); revisit if Phase 5 test integration ever needs them. Cheap to add later.

5. **Source/JSON shape of `LogStep`** in `pkg/dag/marshal.go`:
   - What we know: Phase 7 trigger marshaling carries `map_lambda_id` / `idempotency_lambda_id` strings; `failJSON` carries `message_lambda_id`.
   - Recommendation: `logStepJSON` carries `kind`, `level`, `msg`, `msg_lambda_id` (omitempty), `attrs_lambda_id` (omitempty). Mirror `failJSON` exactly. No need for golden-file infrastructure — existing marshal_test.go pattern covers it.
