## LogStep type signature (final form)

```go
type LogStep struct {
    Pos           syntax.Position
    Level         string           // "info" | "warn" | "error" | "debug"
    Msg           string           // literal template, may carry ${ctx.expr}
    MsgFn         *CapturedLambda  `json:"-"`
    AttrsLambdaID string
}

var _ Node = (*LogStep)(nil)

func (*LogStep) Kind() string                { return "LogStep" }
func (n *LogStep) Position() syntax.Position { return n.Pos }
func (*LogStep) nodeMarker()                 {}
```

## JSON shape (logStepJSON)

```json
// Literal-only:
{"kind":"LogStep","level":"info","msg":"hello"}

// With interpolation lambda + attrs lambda:
{"kind":"LogStep","level":"warn","msg":"${ctx.x}","msg_lambda_id":"lam_abc","attrs_lambda_id":"lam_xyz"}
```

Field order in JSON output: `kind`, `level`, `msg`, `msg_lambda_id` (when MsgFn != nil), `attrs_lambda_id` (when AttrsLambdaID != ""). Both lambda IDs use `omitempty`.

## Decisions Made

- **Plain-string Level field (no Go enum type).** Keeps pkg/dag free of parser-level concerns; the parser is the level gate and rejects non-`info/warn/error/debug` values at parse time per D-7.2.1-02. This matches the existing pattern where pkg/dag holds data shapes and pkg/parser owns validation rules.
- **logStepJSON shape mirrors failJSON verbatim.** Same `kind`/payload/`*_lambda_id` (omitempty) pattern. Chosen over `scriptJSON`'s shape because `Script.OutputAlias` is mandatory in its JSON but LogStep has no output alias.
- **MsgFn excluded via custom MarshalJSON, not just json:"-" tag.** Both are necessary — `json:"-"` covers the default-encoder path but a custom MarshalJSON is required to (a) emit a stable lowercase `kind` discriminator and (b) hoist the lambda's opaque ID up to a top-level `msg_lambda_id` key for downstream consumers (Plan 04 renderer, Phase 3 lambda registry).
