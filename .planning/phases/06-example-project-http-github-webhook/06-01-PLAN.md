    Create the file `examples/http-github-webhook/.skytime-credentials.example` with EXACTLY this content (verbatim from RESEARCH.md § 6 plus the locked TOML schema from CONTEXT.md D-CREDS-FORMAT — the four credential entries demonstrate every supported type):

    ```toml
    # .skytime-credentials.example — copy to ~/.skytime-credentials and edit.
    #
    # IMPORTANT: chmod 600 ~/.skytime-credentials after copying. The credfile
    # resolver warns on world/group-readable files (mode bits & 0o044 != 0)
    # by default, and refuses to load them in strict mode.
    #
    # Schema (D-CREDS-FORMAT): each [credentials.<id>] table declares one
    # credential. The `type` tag is required and must be one of:
    #   - "bearer"  — Authorization: Bearer <token> (GitHub PAT, OAuth, webhook URL)
    #   - "basic"   — Authorization: Basic base64(username:password)
    #   - "apikey"  — header NAME (key) + header VALUE (value)

    [credentials.github_token]
    type = "bearer"
    token = "ghp_REPLACE_WITH_YOUR_PAT"

    [credentials.basic_id]
    type = "basic"
    username = "your-username"
    password = "your-password"

    [credentials.apikey_id]
    type = "apikey"
    key = "X-API-Key"
    value = "your-api-key-secret"

    [credentials.webhook_url]
    type = "bearer"
    token = "https://webhook.site/REPLACE_WITH_YOUR_TOKEN"
    ```

    Notes (do NOT include the notes in the file body itself, only the comments shown above):
    - The `webhook_url` entry uses `type = "bearer"` because the webhook extension treats the URL ITSELF as the secret (D-WEBHOOK-HOST). The webhook extension's `post` op extracts the URL via `cred.(*extension.BearerCredential).Token.Reveal()`.
    - The `apikey_id` entry maps TOML `key` → Go `extension.APIKeyCredential.HeaderName` and TOML `value` → Go `extension.APIKeyCredential.Key` (the Secret-typed field). This mapping is locked by RESEARCH.md § 2 "Schema clarification".
    - The placeholder strings (`ghp_REPLACE_WITH_YOUR_PAT`, `https://webhook.site/REPLACE_WITH_YOUR_TOKEN`, `your-username`, etc.) are intentionally obvious so a reader who forgets to edit the file gets a clear "wrong token" error from GitHub/webhook.site rather than a successful but mis-targeted call.

    The file MUST be checked in — it is the template the reader copies + edits. Do NOT mark it `.gitignore`d.
  </action>
