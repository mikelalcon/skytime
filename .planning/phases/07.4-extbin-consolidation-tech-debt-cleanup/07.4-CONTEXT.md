**Gathered:** 2026-05-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Make "build your own binary" visibly tiny and close v1.42.0 audit's API-surface debt in one focused phase.

Three new options land in `pkg/cli` and `pkg/testing`:
- `cli.WithCredfile(path string)` — lifts `lazyCredfileHandler` from `examples/http-github-webhook/cmd/extbin/main.go` into `pkg/cli`; convenience wrapper over the existing `cli.WithCredentialHandler`
- `cli.WithBuildID(string)` — lets custom binaries set the worker Build ID without `-ldflags` injection
- `pkg/testing.WithCredentialHandler(h)` — threads a credential handler into the Tier-3 test harness

`pkg/cli/test.go` threads `cfg.credHandler` (in addition to the existing `cfg.exts`) to `pkg/testing.RunCLI`. With those landed, `extbin/main.go` collapses to ≤30 lines.

Plus three bookkeeping items folded in:
- INTRP-03/04/05 traceability checkbox flip in `REQUIREMENTS.md`
- Add a parse-only `http.*`-using flow so HTTP extension registration matches usage
- Lift `TestLazyCredfileHandler_*` tests with the handler

**Out of scope** (deferred to later phases): live runtime tests for `pr_to_webhook` + `weekly_digest`; Phase 04.3 HUMAN-UAT items; XDG/`os.UserConfigDir()` migration of credfile path.

<decisions>
## Implementation Decisions

### WithCredfile API edges

- **D-7.4-01 — Env var policy:** `SKYTIME_CREDFILE_PATH` is the runtime env-var fallback, used only when `cli.WithCredfile("")` was passed empty. Explicit `cli.WithCredfile("/path")` always wins over the env var. Standard Unix precedence (explicit > env > default).

- **D-7.4-02 — Option interaction:** `cli.WithCredfile` and `cli.WithCredentialHandler` are both Option closures that mutate `cfg.credHandler`; **last call wins** (silent), matching the standard Go option idiom and consistent with how `WithExtensions` stacking is documented. No construction-time error if both are passed.

- **D-7.4-03 — Single resolution chain (consolidation):** Keep the `--credfile` CLI flag on `skytime server` and `skytime cron-plan` AND the `SKYTIME_CREDFILE_PATH` env var. Both surfaces feed the **same** option-installed handler's resolution chain:

  ```
  --credfile flag > SKYTIME_CREDFILE_PATH env var > cli.WithCredfile(arg) > built-in default ($HOME/.skytime-credentials)
  ```

  No scattered `SetCredfilePath` plumbing per subcommand; the option's handler owns the precedence. Planner picks the cleanest implementation seam (one suggestion: handler exposes a single setter that the cobra subcommand invokes before first `Resolve()`; another: env-var lookup happens inside the handler at `Resolve()` time, flag override path also goes through the same hook).

- **D-7.4-04 — Option location:** `WithCredfile` declaration in `pkg/cli/options.go` (alongside `WithExtensions`, `WithCredentialHandler`, `WithScheduleClientFactory`). The lifted lazy handler implementation (~120 lines) can live in its own file (`pkg/cli/credfile.go` is the natural pick) — that's a planner-level layout call, not a user-visible API decision.

- **D-7.4-05 — Default credfile path stays `$HOME/.skytime-credentials`.** No migration to `os.UserConfigDir()` / XDG conventions. Considered and rejected: minimum-surprise wins over portability for credfile users (mostly devs on macOS/Linux who already have the dotfile). If the path ever changes in a future phase, the migration path is hard-switch with a documented `mv` command (no fallback log).

### Tech-debt scope

- **D-7.4-06 — INTRP-03/04/05 checkbox flip is IN.** 30-second `REQUIREMENTS.md` edit + commit; one checkbox each for INTRP-03, INTRP-04, INTRP-05; trace table moves from `Pending` to `Phase 03` for each. Removes a hanging audit item. (Audit said "auto during `/gsd:complete-milestone`" — doing it earlier doesn't break that contract.)

- **D-7.4-07 — Add a parse-only `http.*`-using flow** to `examples/http-github-webhook/`. The HTTP extension is currently registered by extbin but no `.star` flow calls `http.endpoint(...)` — registration without usage is the audit gap. New flow lives alongside the existing five (`public_repo_check`, `pr_to_webhook`, `issue_triage`, `batch_label_issues`, `weekly_digest`); covered by `flows_test.go`'s parse-shape assertions. **Live runtime test** for the new flow is out of scope (matches the rest of the corpus's parse-only coverage).

- **D-7.4-08 — Live runtime tests for `pr_to_webhook` + `weekly_digest` DEFERRED.** Reason: each adds ~30-60s of CI smoke wall-clock and needs `gh webhook forward` mock plumbing or full Schedule fire-and-wait. Doubles smoke complexity. Track in `deferred-items.md`; resurface as its own future phase.

- **D-7.4-09 — Phase 04.3 HUMAN-UAT items OUT.** The 5 doc-rendering checks (GitHub UI render, cross-link traversal, prose readability) belong to a `/gsd:verify-work 04.3` invocation, not 7.4's API-surface scope.

### pkg/testing handler integration

- **D-7.4-10 — Ship `NewFakeCredentialHandler(map[string]extension.Credential)` helper** alongside `pkg/testing.WithCredentialHandler(h)`. Tests stub credentials in one line:

  ```go
  testing.WithCredentialHandler(testing.NewFakeCredentialHandler(map[string]extension.Credential{
      "gh-token": fakeToken,
  }))
  ```

  Saves boilerplate; the helper is a thin map-backed shim (~15 lines).

- **D-7.4-11 — `OnActivity(...)` bypass preserved (additive behavior).** The Temporal testsuite's `OnActivity(...)` mocks short-circuit *before* any `CredentialHandler.Resolve(ctx, id)` call, exactly as today. The handler installed via `WithCredentialHandler` is invoked **only** by activities that aren't mocked. This lets test authors do partial mocking: real handler resolves real creds for some actions, `OnActivity` mocks the network for others. Zero regression for existing tests.

- **D-7.4-12 — `pkg/cli/test.go` threads `cfg.exts` + `cfg.credHandler` to `pkg/testing.RunCLI`.** Minimal, two-field threading — not a whole-`cfg` snapshot. Future options (e.g., `WithBuildID`) get threaded one-by-one as concrete tests demand them. No premature struct.

### extbin/main.go target shape

- **D-7.4-13 — ≤30 lines incl. doc comments** (matches CLI-12 verbatim). Room for a short package doc-comment (1-3 lines pointing at `pkg/cli` for the canonical pattern + a one-line credfile location note) plus the actual code: extension registration + `cli.NewRootCommand(WithExtensions(...), WithCredfile(os.Getenv("SKYTIME_CREDFILE_PATH")), WithBuildID(...)).ExecuteContext(ctx)` + signal handling + error rendering.

- **D-7.4-14 — Move "build your own binary" teaching block to `pkg/cli/doc.go`.** The current heavy doc-comment in `extbin/main.go`'s package header (subcommand list, credfile location, override patterns) is library-level knowledge, not example-specific. Promotes to godoc on `pkg/cli` so library users discover it without reading the example. extbin keeps a one-liner: `// See pkg/cli for the build-your-own-binary pattern.`

- **D-7.4-15 — Lift `TestLazyCredfileHandler_*` tests with the handler.** All current tests in `examples/http-github-webhook/cmd/extbin/main_test.go` target the lazy handler. They migrate to `pkg/cli/credfile_test.go` (or wherever the handler lands). `extbin/main_test.go` shrinks to whatever (if anything) still tests extbin-specific wiring; a thin smoke test that builds extbin and invokes `--help` is a reasonable retention if the planner finds value, otherwise the file goes.

## Existing Code Insights

### Reusable Assets

- **`pkg/cli/options.go`** — Established Option pattern (`type Option func(*config) error`). All three new options (`WithCredfile`, `WithBuildID`, `WithCredentialHandler`-for-testing) drop in as additional closures. No struct refactor needed.

- **`pkg/extension/credfile.New(opts ...Option)`** + **`credfile.WithPath(p)`** — Already do the heavy lifting. The lifted handler in `pkg/cli` is a thin lazy wrapper: capture path → on first `Resolve()`, call `credfile.New(WithPath(captured))` → cache result + error. Matches what `extbin/main.go:96-128` does today.

- **`pkg/worker/build_id.go::defaultBuildID`** — Package-level `var`; `pkg/worker/client.go:28,57,75` already does `coalesce(opts.Identity, "skytime/"+defaultBuildID)`. `cli.WithBuildID(s)` sets `worker.WorkerOptions.BuildID = s` at the seam where `pkg/cli/run.go` (and `pkg/cli/server.go`) construct `worker.Options`. **`pkg/worker/options_test.go:53-58` already has a `BuildID: "v42"` test that asserts the field flows through** — that's the testing model for the `WithBuildID` test.

- **`pkg/cli/test.go:53`** — Current pattern `testingpkg.WithExtensions(cfg.exts...)`. Add `testingpkg.WithCredentialHandler(cfg.credHandler)` symmetric line. Two-field thread, not a refactor.

- **`pkg/extension/schedules.NewFakeScheduleClient`** — Precedent for shipping a `Fake*` constructor in a non-test file so it's reachable from test packages across modules. Pattern to follow for `pkg/testing.NewFakeCredentialHandler`.

### Established Patterns

- **Options scope is per-`NewRootCommand`-invocation, no globals** (D-7.2-09 from Phase 7.2). All three new options follow this — nothing new to design.

- **Option closures may return error** but in practice all five existing ones (`WithExtensions`, `WithCredentialHandler`, `WithScheduleClientFactory`, plus the two new ones) just mutate config and return nil. Reserve the error path for legitimate construction-time validation (e.g., reject `WithBuildID("")` if we want non-empty enforcement — planner decides).

- **Lazy initialization with mutex** (`extbin/main.go:79-128`) — the pattern being lifted. `sync.Mutex` + `initialized bool` + cached error. Idiomatic; no rethink needed.

- **Type assertion for optional handler capabilities** (`pkg/cli/server.go:169` `cfg.credHandler.(interface{ SetCredfilePath(string) error })`) — current pattern. D-7.4-03 lets us simplify because the option-installed handler always implements the setter; type assertion stays for the case when a fully custom `WithCredentialHandler` is installed.

### Integration Points

- **`pkg/cli/run.go` + `pkg/cli/server.go` + `pkg/cli/cron_plan.go`** — three subcommand files that currently consume `cfg.credHandler`. After 7.4, none of them need to know whether the handler was installed via `WithCredfile` or `WithCredentialHandler` — they just resolve through the interface.

- **`pkg/cli/server.go` `cmd.Flags().StringVar(&credfilePath, "credfile", ...)`** (line 435) and the parallel registration in `pkg/cli/cron_plan.go:102` — kept per D-7.4-03; the `RunE` block that does the type-assertion + setter call (server.go:156-174, cron_plan.go:48-55) gets replaced with a single call into the handler's setter (planner picks the exact seam).

- **`docs/reference/cli.md`** — only doc-edit needed if the `--credfile` flag's user-visible behavior changes. Per D-7.4-03 it doesn't (flag still exists, same precedence in the chain), so likely a small refresh for clarity rather than a row deletion.

## Specific Ideas

- The user explicitly used the phrase **"sounds good to have one flag and one ENV_VAR that actuates the same option"** — D-7.4-03 reflects this. The planner should treat "one resolution chain, one handler" as a hard contract; multi-handler / per-flag plumbing is a regression of intent.

- The user **considered and rejected** moving the credfile default to `os.UserConfigDir()` / XDG paths (D-7.4-05). Don't reopen this design in planning; the trade-off was explicit (minimum-surprise > portability for the dotfile users).

- The user explicitly **prefers `NewFakeCredentialHandler` shipped alongside the option** (D-7.4-10), not "just the option." Planner should not collapse this back to the minimal-surface variant.

- The user explicitly chose **pkg/cli/doc.go** as the new home for the "build your own binary" teaching block (D-7.4-14), over keeping it in extbin or moving to a markdown file. The intent is godoc discoverability for library users.
