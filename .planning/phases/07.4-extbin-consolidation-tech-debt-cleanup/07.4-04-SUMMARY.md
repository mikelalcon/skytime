## Decisions Made

- **WithBuildID omitted from extbin (line budget call):** The plan explicitly allowed this — "the example does not pass -ldflags SHA injection in CI, so omitting WithBuildID lets the worker fall back to defaultBuildID (\"dev\"). The CONTEXT block in Plan 02 mentions this is fine for the headline demo." Including WithBuildID would have pushed the file to 31+ lines (it adds one Option-arg line, plus potentially an env var lookup). The teaching block in pkg/cli/doc.go DOES document the Option, so library users discover the full surface via godoc — the example binary just doesn't exercise that third Option.

- **NewRootCommand call collapsed to a single line (137 chars):** The plan's draft used a 4-line format (opening paren + two indented Options + closing paren). Compressing to one line saved 3 lines — exactly what was needed to land at 30. gofmt tolerates long single-line calls (no automatic wrapping), so the file remains gofmt-clean. Trade-off: less diff-friendly, but the D-7.4-13 budget is verbatim.

- **Doc-comment compressed to exactly one line:** The plan's draft had a 4-line doc-comment ("extbin is..." + "See pkg/cli for..." + "/credfile resolution chain..." + "and the inherited subcommand list..."). I compressed to `// extbin: http-github-webhook example custom CLI; see pkg/cli for the build-your-own-binary pattern.` to save 3 lines. The "See pkg/cli" text required by D-7.4-14's pointer pattern is preserved (and the grep-c check passes). All the detail the original 4-line draft would have communicated now lives in pkg/cli/doc.go where library users actually look.

- **Import block landed in gofmt-alphabetical order across all module imports:** The plan's draft had three visual groups (stdlib / pkg/cli + builtin / examples-prefixed). gofmt only enforces grouping when there's a blank-line separator between groups; with all module imports in one block separated only by a blank from stdlib, gofmt sorts them alphabetically by import path. The resulting order — skygh / skyweb / pkg/cli / skycore / skyhttp — is correct gofmt-clean form. I considered preserving the original three-group structure but it would have added 2 lines (two blank separators), pushing the file to 32. The alphabetical single-group form is the minimal correct shape.

- **Task 3 (verification gate) committed nothing:** Per the plan's explicit instruction ("DO NOT modify any source file in this task — it's a pure verification gate"), Task 3 only ran tests and recorded their PASS state in this SUMMARY. No regression surfaced, so no fix was needed in Task 2's main.go.

That isn't acceptable gofmt-clean structure for Go conventions (stdlib comes first). Restored the blank line between stdlib and module groups; gofmt then alphabetizes within each group while preserving the two-group structure. Final shape is correct.
