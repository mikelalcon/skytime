## Decisions Made

- **Zero validation in WithBuildID closure (CLI-09 + WithExtensions/WithCredentialHandler precedent):** Empty string is accepted as a no-op rather than rejected. Per CONTEXT.md Code Insights, the planner explicitly notes "Reserve the error path for legitimate construction-time validation … planner decides" — and for v1.43 the established precedent (5 existing Options, 0 with validation) wins. This is the right call: it lets callers pass `cli.WithBuildID(os.Getenv("BUILD_ID"))` without an outer if-guard, which is what extbin (Plan 04) will want.
- **Insertion position (between WithExtensions and WithCredentialHandler, NOT at the bottom):** Groups WithBuildID with the other plain-config-field Options at the top of the Option list, rather than near WithScheduleClientFactory (test seam) or WithCredfile (convenience wrapper). Reading top-down in options.go now goes: registration-shape (WithExtensions → WithBuildID → WithCredentialHandler) → test seams (WithScheduleClientFactory) → convenience wrappers (WithCredfile from Plan 01). Improves readability for future Option authors looking for a precedent to mimic.
- **UseBuildIDVersioning NOT touched:** The plan was explicit about this and the worker-side `TestWorkerOptions_VersioningOptIn` test pins the two-step opt-in (register compatibility set on task queue first, THEN flip versioning). CLI-09 sets BuildID; versioning stays false. Production deployers explicitly opt in later, manually, after registering their compatibility set. This decision matters because auto-enabling versioning when BuildID is set would cause silent workflow-hang behavior on task queues without a registered Build ID set (as the worker-side test docstring spells out).
- **Test split rationale (closure-level vs flow-level):** Task 1 = 3 tests pin the Option closure contract (set, empty, last-wins). Task 2 = 2 tests pin the flow-to-WorkerOptions contract (value reaches cfg.buildID; absence leaves it empty). Combined with the existing worker-side `TestWorkerOptions_ExplicitOverrides` (which pins `BuildID: "v42"` → `applyDefaults` → `o.BuildID == "v42"`), this covers Option → config → WorkerOptions → applyDefaults end-to-end without needing to construct a real Temporal client in pkg/cli tests. The `grep -c 'BuildID:.*cfg.buildID' pkg/cli/{run,server}.go` source-grep is the source-level pin for the field assignment at the construction site.
