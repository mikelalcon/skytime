# Phase 04.1 Plan 03: Parser builtin extension for action_fn / block_fn / name / interpolation Summary

**`step(action_fn=...)` / `step(block_fn=...)` / `step(name="${ctx.x}...")` / `flow(name="${ctx.x}...")` / `script(id="${ctx.x}...")` now compile end-to-end through the existing capture/desugar machinery; string action kwargs (e.g., `gh.get(path="/repos/${ctx.repo}")`) round-trip as `*StarlarkLambda` inside `ActionRef.Kwargs`; the D4-02 ctx walker validates every captured lambda surface against the lexically-visible state schema, so typos surface as `*dag.ValidationError` at parse time.**

## Accomplishments

- **pkg/extension/schema.go::assignStarlarkToGo** carves out a `*dag.StarlarkLambda` early-return: accept the wrapper for string-typed fields (Go zero value left for runtime resolveKwargs to fill), reject loudly for any other Kind with the canonical "lambda not allowed for non-string field (got lambda kwarg, declared type is %s)" message. Touches one switch in one helper; no API churn for existing callers.
- **pkg/parser/builtins.go::builtinStep** gains 3 new kwargs (action_fn / block_fn / name) and unifies the action/block mutual-exclusion check into a 4-way count. Canonical error verbiage is verbatim across "got 0" and "got 2+" cases. action_fn / block_fn captured via existing `captureLambda`. name routed through `desugarInterpolation` — literal name lands on `Step.Name`, ${...}-bearing name lands on `Step.NameFn`.
- **pkg/parser/builtins.go::desugarActionRefKwargs** (new helper) walks each ActionRef's kwargs *Dict; when any string value contains `$`, rebuilds the dict with `${...}` strings replaced by `*StarlarkLambda` wrappers (or de-escaped `$$`-only strings replaced by their literal). Always-rebuild approach handles the http extension's freeze-on-construction invariant.
- **pkg/parser/builtins.go::builtinFlow** accepts ${...} interpolation in `name` (D4.1-16). Flow.Name keeps the literal template (D-15 duplicate-detection key); Flow.NameFn carries the synthesized *CapturedLambda when interpolation is present.
- **pkg/parser/builtins.go::builtinScript** accepts ${...} interpolation in `id` (D4.1-02 / W9). Script.ID keeps the literal template; Script.IDFn carries the synthesized lambda when ${...} is present. Bonus: id kwarg switched from `string` to `starlark.Value` so non-string id (`script(id=123, ...)`) surfaces as a *dag.ParseError citing `script.id: expected string, got int`.
- **pkg/dag/control.go::Script** gains `IDFn *CapturedLambda` field — same shape as Step.NameFn / Flow.NameFn. JSON-marshals as `-` (Phase 3 lambda serialization story unchanged).
- **pkg/parser/state_schema.go::walkBodyForCtxValidation** extended for *dag.Step: validates `ActionFn` / `BlockFn` / `NameFn` lambdas + every `*StarlarkLambda` inside `ActionRef.Kwargs` against the lexically-visible state set. Required because action_fn/block_fn lambdas + interpolation lambdas live on Step (not on Script/IfCond), so the walker's old Step-no-op branch left them unverified.
- **18 new tests** — 5 schema (lambda for required-string OK; lambda for non-string Errors; round-trip lambda inside frozen dict; assignStarlarkToGo lambda→string; regression on plain string), 11 builtinStep (literal name; ActionFn capture; BlockFn capture; action+action_fn rejection; block+block_fn rejection; canonical action+block message; name interpolation populates NameFn; literal name leaves NameFn nil; no-action-form rejection; action kwarg ${} → *StarlarkLambda; action_fn ctx.<typo> → ValidationError), 4 builtinFlow (NameFn populated; literal nil; duplicate literal still rejected; literal vs template-shape allowed), 3 builtinScript (IDFn populated; literal nil; non-string id rejected), 1 dag (TestScript_HasIDFn). ## Decisions Made

- **desugarActionRefKwargs always-rebuilds when any value contains $.** Necessary because the http extension freezes its output dict before returning the ActionRef; mutating in place would surface as "cannot insert into frozen hash table" against the e2e fixtures. Always-rebuild keeps the http freeze invariant intact AND yields a fresh unfrozen dict for downstream finalize / activity-side dispatch to handle freeze when appropriate.
- **D4-02 walker extension for *dag.Step (Rule 2 add).** The plan's D4.1-09 explicitly says "Parse-time validation of action_fn / block_fn lambdas: D-19 free-var lint, D-20 lambda-time globals, D4-02 ctx.<name> walker against state schema". Without the walker visiting Step.ActionFn / Step.BlockFn / Step.NameFn / ActionRef.Kwargs lambdas, action_fn ctx.tyop typos slip through. Test 11 (TestBuiltinStep_ActionFn_CtxTypoRejected) pins this; the e2e TestInterpolation_TypoRejected proves the same path for ${...} inside action kwargs.
- **starlark.Value-typed kwargs over typed kwargs.** action_fn / block_fn declared as starlark.Value (not *starlark.Function) so the builtin gates pass cleanly when consultants pass non-functions and the error messaging stays builtin-local. name / id declared as starlark.Value (not string) so type errors and interpolation desugaring both run before UnpackArgs would have type-coerced.
- **TestStep_MutuallyExclusive + TestStep_NeitherActionNorBlock updated to D4.1-06 canonical wording.** The Phase 1 messages ("exactly one of action or block, got both" / "must provide action or block") were dropped because the new 4-way message is strictly more informative. Pinning the exact verbiage downstream protects against future drift.
- **Un-skipped Plan 02 deferred tests instead of moving them to tests/.** Plan 02 left TestInterpolation_TypoRejected + TestInterpolation_NoTypo with `t.Skip("requires Plan 04.1-03 to wire desugarInterpolation into builtinStep")`. The plan's verifier-friendly path was to leave them inline and let Plan 03 un-skip when the wiring lands. Done — both tests pass against the fixtures with httpExtensionForTest registering the http extension.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] desugarActionRefKwargs in-place mutation broke against frozen kwargs dict**

- **Found during:** Task 4 (e2e test wiring)
- **Issue:** Plan's `<action>` block sketched in-place SetKey on `ar.Kwargs.Items()` entries. Worked against `fakeExtension` (no freeze) but failed against the production `http` extension's frozen output dict with "cannot insert into frozen hash table" — a *dag.ParseError that would have surfaced to consultants in Phase 6.
- **Fix:** Switched to always-rebuild: detect whether any value needs rewriting (first pass), and when needed, construct a brand-new starlark.NewDict and copy-with-substitution (second pass), reassigning ar.Kwargs to the fresh dict.
- **Files modified:** pkg/parser/builtins.go::desugarActionRefKwargs
- **Commit:** a27f84e

**2. [Rule 2 - Critical functionality] D4-02 walker extension to *dag.Step**
