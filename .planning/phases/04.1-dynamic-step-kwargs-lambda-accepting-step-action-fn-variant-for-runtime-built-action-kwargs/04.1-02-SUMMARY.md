## Accomplishments

- **scanInterpolation** is a ~190-LOC 4-state scanner (text/expr/expr-str) handling `$$` escape, nested `{[(])`/`}` bracket counting, embedded `"..."`/`'...'`/`"""..."""` literals with `\`-escapes, and the three error modes (empty/unterminated/multi-line). Position arithmetic is newline-aware so each `${`'s reported Pos lands at the right line+col within multi-line raw strings.
- **desugarInterpolation** is the full pipeline: `scan → ParseExpr-validate each expr (with user-source attribution) → buildLambdaSource → cache synthetic source under "<interp:<file>:<line>:<col>>" in p.fileBytes → starlark.ExecFileOptions on a clean sub-thread (with bridge.LambdaTimeGlobals as predeclared) → pluck globals["result"] as *starlark.Function → captureLambdaAtPosition with userPos + bodyPos`. Returns `(nil, nil)` for the no-interpolation case so callers can short-circuit.
- **buildLambdaSource + starlarkQuote** render the synthesized source as `lambda ctx: "a" + str(ctx.x) + "b" + str(ctx.y) + "c"` with minimal escaping (`\`, `"`, `\n`, `\r`, `\t`) — D4.1-04's unconditional `str()` wrap is in the source string itself so `${ctx.n}` with `ctx.n` of any Starlark type round-trips to a string at lambda call time.
- **captureLambdaAtPosition** is the synthetic-lambda variant of captureLambda — accepts a pre-compiled `*starlark.Function`, the user's `userPos` (for D-18 ID hash against the user file's bytes + Pos field), and the synthetic `bodyPos` (for BodyPos field). Synthesized lambdas have empty + frozen FreeVars; D-19 free-var lint is intentionally skipped per RESEARCH §Pitfall 3.
- **BodyPos-aware ctx.<name> walker** — `checkLambdaCtx` now prefers `captured.BodyPos` over `captured.Pos` when valid. Hand-written lambdas (BodyPos zero) fall back to Pos exactly as before — backward-compatible, all existing TestFinalize_CtxAccess_* tests stay green. When the access lives in a synthetic file (`<interp:...>` filename prefix), the resulting ValidationError's Pos is remapped back to `captured.Pos` so `<interp:...>` never leaks into user-facing error output (RESEARCH §Pitfall 1).
- **19 tests added** — 10 scanner tests covering all 10 documented behaviors (Test 1-10 from the plan), 9 desugar tests covering no-marker short-circuit, basic eval-roundtrip via starlarkstruct, D-18 stable ID format, Pos+BodyPos attribution, lambdas-map registration, fileBytes synthetic-source caching, str()-wrap on ints, inner-expr syntax error attribution; 2 BodyPos walker tests covering synthetic + hand-written paths. 2 e2e tests SKIPPED with explicit reason (Plan 03 dependency).

## Decisions Made

- **lambdaTimeGlobalsForDesugar delegates to bridge.LambdaTimeGlobals** — single source of truth for the D-20 locked subset. The synthesized lambda only ever uses `+` and `str(...)`, so the full 20-key dict is overkill — but using it ensures parity if a future extension reroutes a hand-written lambda through the desugar path.
- **BodyPos col offset is a constant `len("result = ") + 1` = 10** — the synthesized source prefix is fixed, so the col of the `lambda` keyword in the synthetic file is computable without re-parsing. Dynamic computation would require parsing the synthetic file just to find what we already know.
- **Synthesized lambda has empty + frozen FreeVars** — RESEARCH §Pitfall 3: `${ctx.foo}` only references the lambda's own `ctx` parameter, so there are no closures and `validateFreeVars` would return empty anyway. Skipping the call avoids the D-19 `binding.Pos.Filename() == filename` check that would mis-fire for the synthetic file.
- **Filename-prefix detection (`<interp:`) for error remap** — keeps CapturedLambda struct shape unchanged from Plan 01 (no new bool field) and confines the remap to a single `if strings.HasPrefix(...) { errPos = captured.Pos }` in checkLambdaCtx.
- **Save-and-restore commit splitting for parallel mode** — see Patterns Established below; needed because all 3 tasks transitively touch interpolation.go + interpolation_test.go and per-task atomic commits required temporary file-level rollback rather than git index staging.
