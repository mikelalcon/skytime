## Decisions Made

- **json:"-" on lambda fields** — Step.{NameFn, ActionFn, BlockFn} and Flow.NameFn are json-skipped because Phase 3 re-parses lambdas on workflow start; only LambdaIDs cross history. Matches existing CapturedLambda.FreeVars handling. omitempty on Name (string) keeps the marshaled JSON shape unchanged for unset fields, preserving TestStep_TaskQueueRoundTrip and the existing golden files.
- **BodyPos zero-value sentinel** — RESEARCH §Pattern 2 recommended adding a separate bool or *syntax.Position. Picked zero-value sentinel (`!BodyPos.IsValid()` = "fall back to Pos") because it keeps hand-written lambdas working with one-line struct literals (no per-callsite churn) and the test (TestCapturedLambda_BodyPosZeroValueDocumented) pins the contract.
- **StarlarkLambda in pkg/dag (not pkg/parser)** — Confirmed RESEARCH §Pattern 4 final-paragraph recommendation. pkg/interpreter must unwrap StarlarkLambda inside resolveKwargs (D4.1-14) WITHOUT importing pkg/parser (which depends on interpreter through bridge.CallLambda — moving the type to pkg/dag avoids the cycle).
- **Fixtures live directly under tests/fixtures/** (not the existing valid/ or invalid/ subdirs). Plan's verify command and downstream-wave fixture-loaders use the verbatim path `tests/fixtures/<name>.star`. Existing `tests/fixtures/{valid,invalid}/01-*.star..11-*.star` corpora (Phase 1 / Phase 2) are undisturbed.
