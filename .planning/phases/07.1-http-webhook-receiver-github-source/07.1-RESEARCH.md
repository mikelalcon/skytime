## User Constraints (from CONTEXT.md)

### Locked Decisions

**Source factory namespaces & shapes:**

- **D-7.1-01: Generic HTTP webhook lives at `http.webhook(...)`.** Extends `pkg/extension/builtin/http` alongside the existing `http.endpoint(...)`. Asymmetric naming (endpoint=outbound, webhook=inbound) but one coherent package with full HTTP both directions. Same Go package, same Starlark namespace `http.*`. `New()` returns the same `Extension`; `Initialize()` adds `webhook` as a second module attribute.
- **D-7.1-02: GitHub webhook lives at `github.webhook(events=, secret_credential=)`.** Already locked in Phase 7 D-07-08. Added to `examples/http-github-webhook/extensions/github/`. The factory is a module attribute returning a `*githubWebhookSource` value satisfying `extension.TriggerSource`.
- **D-7.1-03: `http.webhook` signature scheme is fully configurable.** Kwargs: `path: str` (required), `method: str` (required, e.g. "POST"), `secret_credential: str|None` (optional — `None` mounts unsigned), `signature_algo: str` (optional, default `"sha256"`, allowed: `"sha256"|"sha1"|"sha512"`), `signature_header: str` (optional, default `"X-Signature"`). Algo is rejected at parse time if not in the allowed set. Future-proofs for Stripe, GitLab, generic provider patterns.
- **D-7.1-04: GitHub webhook signature is locked.** HMAC-SHA256 against `X-Hub-Signature-256` (TRIG-09; not user-configurable). Source kwargs: `events: list[str]` (optional, defaults to `[]` meaning "all events"), `secret_credential: str|None` (optional; when omitted, no signature validation — useful for local `gh webhook forward` testing without real secrets).
- **D-7.1-05: `req.payload` and `req.headers` are the only `req` fields HTTP sources expose.** Each `TriggerSource.ReqSchema()` returns `["payload", "headers"]` for `http.webhook` and `github.webhook`. `req.payload` is the JSON-parsed body as a `*starlarkstruct.Struct` (recursive Go-map → Struct conversion already shipped in `pkg/bridge`). `req.headers` is a flat `dict[str, str]` (case-preserving key as received). For non-JSON bodies (form-encoded, raw text), `req.payload` is `None` and the lambda must use `req.headers["Content-Type"]` to dispatch — Phase 7.1 ships JSON-first; broader content-type handling deferred.

**HTTP routing:**

- **D-7.1-06: Fan-out routing is the universal rule.** Each (source_kind, path, method) tuple maps to exactly ONE HTTP handler mount. When the boot registry walks triggers, it groups them by mount key; the resulting handler dispatches each delivery to ALL matching triggers in deterministic sorted order. Multiple `trigger(...)` calls subscribing to the same mount each fire their own independent workflow — N triggers → 0..N workflows per delivery. Idempotency keys (D-7.1-08) keep them disambiguated. Matches GitHub's reality: one webhook URL, many subscribers.
- **D-7.1-07: GitHub event filtering happens inside the shared handler.** GitHub webhooks all hit `POST /webhook/github`. The handler reads the `X-GitHub-Event` header and dispatches to triggers whose `events=` list contains the event (case-sensitive match against GitHub's documented event names). An empty `events=[]` list means "match all events". Triggers with non-matching events are silently skipped (no log spam — only one structured log line per delivery; see D-7.1-14). If NO triggers match, return 200 OK with body `{"status":"event filtered"}`.
- **D-7.1-08: Idempotency key includes per-trigger identity.** The user-provided `idempotency_key=lambda req: ...` returns a STRING that becomes part of the Temporal `WorkflowID`. The full WorkflowID is composed: `{flow_name}/{trigger_pos_hash}/{user_key}` where `trigger_pos_hash` is a stable short hash of the trigger's `<file>:<line>:<col>` position. Two triggers fanning out from the same delivery with the same user-key produce DIFFERENT WorkflowIDs (won't collide on `REJECT_DUPLICATE`); but two redeliveries of the same webhook (same `X-GitHub-Delivery`) for the same trigger DO collide (correct dedup behavior). Document the composition in `pkg/bridge/doc.go` and surface in Tier-3 test scaffolding.
- **D-7.1-09: Path conflicts are not possible by definition.** Since fan-out collapses (source_kind, path, method) to one mount, two triggers binding the same tuple subscribe to the same mount instead of conflicting. Different tuples mount different paths — also no conflict. The only error worth raising at parse-finalize is method mismatch on the same path: e.g., `http.webhook(path="/x", method="POST")` and `http.webhook(path="/x", method="GET")` — these get different mounts (one per method), no conflict. Document this in the receiver code; no error path needed.

**Server lifecycle:**

- **D-7.1-10: Boot order is worker-first.** Sequence inside `skytime server`: (1) parse rootdir → flow + trigger registries; (2) `connectClient(cfg)` → Temporal client; (3) register workflows + activities with the SDK worker; (4) start the worker (poll task queue); (5) NOW mount HTTP listener on `--addr`. Steps 2-3 fail-fast on bad config — listener never binds if Temporal unreachable. K8s readinessProbe is a TCP connect to `--addr` and is honest: port open ↔ everything ready. Initial-connect retry is Claude's discretion per Phase 7 D-07-19; recommend bounded exponential backoff (10s total budget by default, configurable later) but the planner can defer if scope pressure.
- **D-7.1-11: Shutdown order is listener-first.** On SIGTERM/SIGINT: (1) call `http.Server.Shutdown(drainCtx)` with `drainCtx` that has `--drain-timeout` deadline; this immediately refuses new requests but lets in-flight HTTP requests finish (which means in-flight `ExecuteWorkflow` dispatch calls finish — the workflow itself is now durable on the Temporal server). (2) After listener.Shutdown returns (or its ctx expires), call `worker.Stop()` which begins the worker drain — Temporal SDK semantics: stop polling new tasks, finish in-flight activity executions. (3) Wait for worker drain or `--drain-timeout`, whichever first. (4) Exit 0 if clean drain, exit 1 + timeout-message if drain budget consumed (consistent with Phase 7 D-07-16). Second signal at any stage forces `os.Exit(1)` immediately (Phase 7 D-07-15).
- **D-7.1-12: Listener uses `net/http.Server` with reasonable defaults.** `ReadHeaderTimeout: 10s`, `ReadTimeout: 30s`, `WriteTimeout: 30s`, `IdleTimeout: 60s`, `MaxHeaderBytes: 64*1024`. Body size limit per request: 25MB (matches GitHub's webhook payload max). Limits enforced via `http.MaxBytesReader`. These are Claude's discretion — adjust during planning if a specific source needs larger payloads, but defaults match the 95% case.
- **D-7.1-13: Phase 7's 4 skipped signal-loop tests get unskipped.** `pkg/cli/server_test.go` has `TestServerCmd_DrainOnSIGTERM`, `TestServerCmd_DrainTimeoutExpiry`, `TestServerCmd_SecondSignalForceExit` (and a fourth) marked `t.Skip("TODO(phase-7.1)")`. Phase 7.1 introduces the `worker.WithSDKFactory` Option (or equivalent test seam) that lets `pkg/cli` black-box tests substitute a fake SDK worker, dropping the skips. The receiver-side tests (signature, idempotency, fan-out, dispatch) live in `pkg/extension/receiver` (or wherever the dispatcher lands) with their own httptest fixtures.

**Failure paths + observability:**

- **D-7.1-14: HTTP status code mapping is locked.**
  - **200 OK on success** — body: `{"workflow_id":"<composed_id>"}` (single trigger) or `{"workflow_ids":["a","b"]}` (fan-out). Returns ONLY after all dispatched workflows have been started by Temporal — synchronous dispatch confirmation, NOT synchronous workflow completion (webhook semantics: receiver confirms enqueue, not completion).
  - **200 OK on REJECT_DUPLICATE collision** — body: `{"status":"duplicate; skipped","workflow_id":"<existing_id>"}`. Distinct from a brand-new success but same status code so source providers (GitHub) don't retry.
  - **200 OK on event-filter no-match** — body: `{"status":"event filtered"}` (D-7.1-07).
  - **400 Bad Request** — malformed body (JSON parse error when `Content-Type: application/json`). Body: `{"error":"bad_request","detail":"<safe_message>"}`. Never echo the payload.
  - **401 Unauthorized** — signature mismatch OR missing signature header when `secret_credential` is configured. Body: `{"error":"unauthorized"}`. NO detail (don't leak whether the secret is wrong vs missing).
  - **500 Internal Server Error** — `map` lambda panic OR `idempotency_key` lambda panic. Body: `{"error":"internal","detail":"<error_class>"}`. Detail is the error class only (e.g., "starlark eval error") — never the user's payload, never the lambda source, never the resolved Secret.
  - **502 Bad Gateway** — `client.ExecuteWorkflow` returned a network/connection error (Temporal unreachable from receiver). Body: `{"error":"upstream","detail":"temporal_unavailable"}`. Source providers WILL retry on 502, which is correct.
- **D-7.1-15: Structured per-request log line.** One log line per request, emitted after the response is written. Fields: `method`, `path`, `status`, `duration_ms`, `source_kind` (e.g., `"github.webhook"`), `event` (e.g., `"issues"` for GitHub; absent for non-GitHub), `flows_dispatched` (list of flow names that fired, possibly empty), `workflow_ids` (list, possibly empty), `error_class` (string, present iff status ≥ 400). charm-log default: `[skytime] POST /webhook/github 200 12ms source=github.webhook event=issues flows=[issue_triage] workflow_ids=[issue_triage/abc/2026-...]`. `--json-log`: structured JSON record with same fields. NO request body, NO response body, NO header values (only header NAMES if useful), NO secrets. The `error_class` is a stable taxonomy: `signature_mismatch | bad_request | lambda_panic | dispatch_failed | event_filtered | duplicate_skipped | ok`.

**Crash-recovery demo:**

### Claude's Discretion

The planner has flexibility on these (defaults captured during discussion; deviate only if a stronger reason emerges during planning):

- **Receiver code location.** Strawman: `pkg/extension/receiver/` for the HTTP dispatcher (signature validation + lambda eval + dispatch). Alternative: `pkg/server/receiver/` if a top-level `pkg/server` package emerges. Pick consistent with where the listener bind code lives.
- **Receiver Initialize() shape.** When `boot.go` collects triggers, it needs to ask each `TriggerSource` "what HTTP route do you mount?". Strawman: extend `TriggerSource` with an `HTTPRoute() (path, method string, ok bool)` method (HTTP-shaped sources return ok=true; cron sources will return false in 7.2). Alternative: type-assert against an `HTTPMounter` sub-interface in the receiver package. Pick whichever keeps the `extension.TriggerSource` core seal cleaner.
- **Connection retry on initial Temporal connect.** Phase 7 D-07-19 punted this. Strawman for 7.1: bounded exponential backoff, 10s budget, 1s/2s/4s/... Alternative: rely entirely on k8s readinessProbe to retry the pod. Implement-and-test if it fits scope; defer otherwise.
- **`gh webhook forward` flag specifics in walkthrough.** Strawman: `gh webhook forward --repo=user/test-repo --events=issues --url=http://localhost:8080/webhook/github --secret=$GITHUB_WEBHOOK_SECRET`. Verify the exact flag names against current `gh` CLI documentation during planning (the gh webhook subcommand evolved through gh 2.x).
- **Worker drain + listener drain race.** In D-7.1-11 the listener.Shutdown returns BEFORE worker.Stop() is called. But what if `--drain-timeout` is so short the listener.Shutdown itself can't complete? Strawman: `drainCtx` is shared between listener and worker; if it expires during listener.Shutdown, force-kill listener and exit 1 with the timeout message. Edge case; planner finalizes.
- **Body decoder negotiation.** Strawman for non-JSON content-types: if `Content-Type` is `application/json` → parse to `*starlarkstruct.Struct`; else → set `req.payload = None` and let the lambda handle via `req.headers["Content-Type"]`. Alternative: hardcode JSON-only (return 415 Unsupported Media Type otherwise). 415 is cleaner; pick during planning based on which the demo flow needs (GitHub always sends JSON when configured for it).

## Project Constraints (from CLAUDE.md)

- **Tech stack fixed:** Go 1.25 + `go.starlark.net` + `go.temporal.io/sdk@v1.42.0` — no alternative DSLs, expression languages, or orchestrators. **Stdlib `net/http` only** for any HTTP code (no chi, gorilla/mux, echo, gin). `net/http.Server` + `net/http.ServeMux` (or per-handler manual dispatch) only.
- **Architecture:** Strict parse/execute separation. Source factories perform NO I/O at parse time — they build immutable `TriggerSource` values. Listener mount happens at boot time (post-parse).
- **Quality > speed.** This is foundational infrastructure; correct boundaries are hard to fix retroactively.
- **Determinism:** Handler dispatch order across fan-out is sorted `(flow_name, trigger_position)`. Failures in one trigger's `ExecuteWorkflow` do NOT block sibling triggers.
- **Security:** Credentials NEVER serialized. Resolver is invoked just-in-time inside the request handler. State holds only credential IDs. The resolved `extension.Secret` is unwrapped via `.Reveal()` for HMAC computation only, never logged, never passed to `ExecuteWorkflow`'s input.
- **Compatibility:** Temporal Cloud + self-hosted must both work. The receiver does not depend on cloud-only or self-hosted-only features. `client.ExecuteWorkflow` works identically across variants (Phase 7 D4-08 routing gives us a single client).
- **GSD Workflow Enforcement:** All file edits must go through a GSD command; planning artifacts and execution context stay in sync.

## Summary

Phase 7.1 attaches an HTTP receiver to Phase 7's already-shipped `skytime server` shell. The shape is well-constrained:

1. Two new source factories — `http.webhook(...)` (generic, configurable signature) and `github.webhook(...)` (HMAC-SHA256 + X-Hub-Signature-256 locked) — each implementing `extension.TriggerSource` with `Kind()`, `ReqSchema() = ["payload","headers"]`, `MarshalJSON()` (credential-ID-only), and a (new) `HTTPMount() (path, method string, ok bool)` capability that the receiver type-asserts.
2. A new `pkg/extension/receiver/` (recommended) package containing the dispatcher: walks `worker.Triggers().All()`, groups triggers by `(source_kind, path, method)`, mounts ONE handler per group with `net/http.ServeMux`. Each handler runs the signature-validate → JSON-decode → fan-out → eval map+idempotency lambdas → `client.ExecuteWorkflow` pipeline, with locked HTTP status code mapping (D-7.1-14) and one structured log line per request (D-7.1-15).
3. Threading into `pkg/cli/server.go`: HTTP listener mounts AFTER `worker.Start()` (worker-first boot, D-7.1-10); `http.Server.Shutdown(drainCtx)` runs BEFORE `worker.Stop()` on SIGTERM (listener-first drain, D-7.1-11). The four signal-loop tests in `pkg/cli/server_test.go` get unskipped via a new `worker.WithSDKFactory` Option that lets pkg/cli black-box tests substitute a fake SDK worker.
4. Crash-recovery walkthrough wiring: a new `webhook_demo.star` (comment → 30s sleep → label) demonstrates Temporal's durability across `Ctrl-C + restart`. Walkthrough docs in two locations (5-min in `examples/http-github-webhook/README.md`, full in `docs/walkthroughs/github-webhook.md`).

**Primary recommendation:** Build the receiver as a small in-process dispatcher with stdlib-only HTTP. Treat `extension.TriggerSource`'s HTTP-mount capability as a NEW sub-interface (`HTTPMounter`) in `pkg/extension/receiver/` — type-asserted at boot-walk time. Keeps the core sealed `TriggerSource` interface unchanged (already locked in Phase 7) while introducing the routing capability cleanly.

### Alternatives Considered

| Instead of | Could Use | Tradeoff |
|------------|-----------|----------|
| stdlib `net/http.ServeMux` | gorilla/mux, chi, echo | Project rule (stdlib HTTP only). Stdlib's mux handles exact-path matching, which is all we need — fan-out is per-mount not per-glob. |
| `http.MaxBytesReader` | manual `io.LimitReader` + length check | MaxBytesReader handles the response writing on overflow correctly (returns 413 to client) and consumes-and-discards the rest of the body to avoid HTTP/1.1 connection reuse confusion. |
| `errors.As` for WorkflowExecutionAlreadyStarted | string-matching the error message | `errors.As` is the idiomatic stdlib pattern AND the SDK doc explicitly says "use errors.As". String matching breaks across SDK versions. |
| Per-source pattern matching for kind | `switch source.(type)` in receiver | Type-asserting to a generic `HTTPMounter` interface keeps the receiver agnostic of github vs http kinds. The kind discriminator stays for marshaling and logging. |

### Pattern 1: HTTPMounter sub-interface (boot-walk type-assertion)

**What:** A new sub-interface in `pkg/extension/receiver/http_mounter.go` that HTTP-shaped TriggerSource concrete types implement. The receiver's mount loop type-asserts on this interface, leaves cron / non-HTTP sources alone (they'll get their own mount story in 7.2).

**When to use:** The clean way to extend `TriggerSource` capabilities without modifying the sealed core interface (Phase 7 Plan 02 locked it).

**Example:**
```go
// pkg/extension/receiver/http_mounter.go
package receiver

// HTTPMounter is implemented by TriggerSource concrete types that mount
// an HTTP handler. The receiver type-asserts at boot-walk time: HTTP-
// shaped sources return ok=true; cron sources (Phase 7.2) return ok=false
// (or simply do not implement the interface).
type HTTPMounter interface {
    HTTPMount() (path, method string)
}

// pkg/extension/builtin/http/webhook.go
type httpWebhookSource struct {
    path             string
    method           string
    secretCredID     string  // empty when unsigned
    signatureAlgo    string  // "sha256" (default), "sha1", "sha512"
    signatureHeader  string  // "X-Signature" (default)
}
func (s *httpWebhookSource) HTTPMount() (path, method string) { return s.path, s.method }
```

### Pattern 2: One-handler-per-mount with deterministic fan-out

**What:** When `bootRegistry` finishes, walk `worker.Triggers().All()`, group by `(source_kind, path, method)` tuple, and mount ONE handler per group. Each handler closes over a sorted `[]*dag.Trigger` slice (sorted by `(FlowName, Pos.String())`). On request, iterate the slice in order; failures in one trigger's `ExecuteWorkflow` do NOT short-circuit later triggers.

**When to use:** Universal — handles N=1 (single subscriber) and N>1 (fan-out) identically. Mirrors GitHub's "one URL, many subscribers" reality.

**Example:**
```go
// pkg/extension/receiver/receiver.go
func Mount(mux *http.ServeMux, w *worker.Worker, c client.Client, credHandler extension.CredentialHandler, logger *slog.Logger) {
    groups := map[mountKey][]*dag.Trigger{}  // (kind, path, method) → triggers
    for _, t := range w.Triggers().All() {
        m, ok := t.Source.(HTTPMounter)
        if !ok { continue }  // cron sources etc. skip HTTP mount
        path, method := m.HTTPMount()
        key := mountKey{kind: t.Source.Kind(), path: path, method: method}
        groups[key] = append(groups[key], t)
    }
    for key, trigs := range groups {
        sort.SliceStable(trigs, func(i, j int) bool {
            if trigs[i].FlowName != trigs[j].FlowName {
                return trigs[i].FlowName < trigs[j].FlowName
            }
            return trigs[i].Pos.String() < trigs[j].Pos.String()
        })
        mux.HandleFunc(key.path, makeHandler(key, trigs, c, credHandler, logger))
    }
}
```

### Pattern 3: Listener-first graceful drain (extends Phase 7's signal loop)

**What:** Add `http.Server.Shutdown(drainCtx)` to the existing `pkg/cli/server.go` signal loop. The listener stops accepting BEFORE `worker.Stop()` is called. In-flight requests finish (their `ExecuteWorkflow` calls return; the workflow itself is now durable on Temporal's server). Then worker.Stop() drains in-flight activity tasks.

**When to use:** Always. Phase 7's signal loop already has the structure; 7.1 inserts one new step.

**Example:**
```go
// pkg/cli/server.go (after Plan 7.1 changes — pseudo-code)
srv := &http.Server{Addr: addr, Handler: mux, ReadHeaderTimeout: 10*time.Second, ...}
go func() { _ = srv.ListenAndServe() }()  // bind AFTER w.Start() per D-7.1-10

<-sigCh
hookStage("signal_received")
drainCtx, cancel := context.WithTimeout(context.Background(), drainTimeout)
defer cancel()

// LISTENER-FIRST: stop accepting; let in-flight finish.
hookStage("listener_shutdown_started")
shutdownErr := srv.Shutdown(drainCtx)
hookStage("listener_shutdown_complete")  // returns when in-flight done OR drainCtx fires

// NOW worker drain.
go func() {
    stopOnce.Do(func() {
        hookStage("drain_started")
        w.Stop()  // blocks up to WorkerStopTimeout
        close(done)
    })
}()
select {
case <-done:                hookStage("drain_completed"); return nil
case <-sigCh:               hookStage("drain_forced");    testForceExit(1); return nil
case <-drainCtx.Done():     hookStage("drain_timeout");   return errSilent
}
```

### Pattern 4: Per-request structured log line via `defer`

**What:** Capture start time at handler entry; emit one log record at handler exit via `defer`, after the response is written. Fields per D-7.1-15. NO request body, NO response body, NO secrets, only header NAMES.

**When to use:** Every webhook handler. Matches Phase 7's `setupServerLogging` reuse.

**Example:**
```go
func makeHandler(key mountKey, trigs []*dag.Trigger, c client.Client, credHandler extension.CredentialHandler, logger *slog.Logger) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        rec := requestRecord{method: r.Method, path: r.URL.Path, sourceKind: key.kind, ...}
        defer func() {
            rec.durationMs = time.Since(start).Milliseconds()
            logger.Info("webhook delivery",
                "method", rec.method, "path", rec.path, "status", rec.status,
                "duration_ms", rec.durationMs, "source_kind", rec.sourceKind,
                "event", rec.event, "flows_dispatched", rec.flowsDispatched,
                "workflow_ids", rec.workflowIDs, "error_class", rec.errorClass)
        }()
        // ... handler body, mutating &rec ...
    }
}
```

### Anti-Patterns to Avoid

- **`bytes.Equal(sig, expected)` for signature comparison.** Vulnerable to timing attacks. ALWAYS use `hmac.Equal`.
- **`fmt.Sprintf("%+v", trig.Source)` in error rendering.** D-07-10 firewall would catch it (Phase 6 plan 07-06's AST walker), but it's worth banning explicitly in receiver code review. Use `t.Source.Kind()` for log lines.
- **Logging request body or response body.** D-7.1-15 explicitly forbids. Only header NAMES if useful.
- **Calling `c.Close()` between SIGTERM and `srv.Shutdown`.** The HTTP handler is mid-flight calling `c.ExecuteWorkflow` when the shutdown ctx fires; closing the client first races with the in-flight start RPC. Order: srv.Shutdown → w.Stop → c.Close (defer at the top of RunE handles it).
- **Using `signal.NotifyContext` for the second-signal escalation.** Already a Phase 7 pitfall (Plan 05). NotifyContext is single-shot. Use `signal.Notify(sigCh, SIGINT, SIGTERM)` with a buffered size-2 channel.
- **String-matching `serviceerror.WorkflowExecutionAlreadyStarted` via `strings.Contains(err.Error(), "already started")`.** Use `errors.As(err, &alreadyStarted)`. The SDK explicitly recommends this and it survives version drift.
- **Forgetting `WorkflowExecutionErrorWhenAlreadyStarted: true` on `StartWorkflowOptions`.** Without this flag, ExecuteWorkflow returns a WorkflowRun pointing at the existing run with NO error — the receiver cannot distinguish a brand-new dispatch from a deduplication. **This is the easy-to-miss SDK detail.** Verified against `go.temporal.io/sdk@v1.42.0/internal/client.go:920-930`.

## Common Pitfalls

### Pitfall 1: Forgetting `WorkflowExecutionErrorWhenAlreadyStarted: true`
**What goes wrong:** Set `WorkflowIDReusePolicy=REJECT_DUPLICATE` only; receiver calls `ExecuteWorkflow` with a colliding WorkflowID; SDK returns a `WorkflowRun` pointing at the EXISTING run with `err == nil`. The receiver thinks it just dispatched a brand-new workflow.
**Why it happens:** The default `WorkflowExecutionErrorWhenAlreadyStarted` is `false`. The flag's documentation is buried in `StartWorkflowOptions` (verified at `$HOME/go/pkg/mod/go.temporal.io/sdk@v1.42.0/internal/client.go:920-930`). The Ruby/Python SDKs default differently; copy-paste from those examples breaks here.
**How to avoid:** Always set BOTH on the StartWorkflowOptions:
```go
opts := client.StartWorkflowOptions{
    ID: composedWorkflowID,
    TaskQueue: cfg.TaskQueue,
    WorkflowIDReusePolicy: enumspb.WORKFLOW_ID_REUSE_POLICY_REJECT_DUPLICATE,
    WorkflowExecutionErrorWhenAlreadyStarted: true,  // CRITICAL
}
```
**Warning signs:** Receiver's `flows_dispatched` log line shows the same workflow ID twice on a redelivery (instead of `duplicate_skipped`). The "second" workflow appears in `client.ListWorkflow` output.

### Pitfall 2: HMAC body source — must be raw bytes, not parsed JSON
**What goes wrong:** Decode JSON body → re-encode → HMAC the re-encoded bytes. Signature mismatch even with the right secret.
**Why it happens:** GitHub computes HMAC over the EXACT body bytes it sent. JSON re-encoding rearranges keys, normalizes whitespace, escapes characters differently. Any byte-level change breaks the HMAC.
**How to avoid:** Read the body ONCE into a `[]byte`, HMAC against that byte slice FIRST, then `json.Unmarshal(bodyBytes, &payload)` after signature passes. Use `http.MaxBytesReader` followed by `io.ReadAll` to capture the bytes.
**Warning signs:** `hmac.Equal` returns false on every legitimately-signed request. `gh webhook forward` deliveries that should pass return 401.

### Pitfall 3: `srv.Shutdown` returning before in-flight handlers actually finish
**What goes wrong:** Receiver thinks listener.Shutdown completed, calls `worker.Stop()`. In-flight handler is mid-`ExecuteWorkflow`. The worker.Stop blocks on workflow tasks. Confused logs.
**Why it happens:** `http.Server.Shutdown(ctx)` returns when `ctx` fires OR when all in-flight handlers return — whichever is FIRST. If drainTimeout is too short relative to handler runtime, ctx wins.
**How to avoid:** Use a SHARED `drainCtx` for both listener.Shutdown and worker.Stop. If the listener phase consumed most of the budget, the worker phase has less remaining. The handler MUST honor `r.Context().Done()` (which `srv.Shutdown` cancels) — but our handlers wrap `c.ExecuteWorkflow(r.Context(), ...)` so SDK-side context propagation handles cancellation. Document this contract.
**Warning signs:** Drain time exceeds `--drain-timeout` substantially. Logs show `listener_shutdown_complete` in milliseconds but `drain_completed` taking the full budget.

### Pitfall 4: Lambda panics escape the handler goroutine
**What goes wrong:** `bridge.CallLambda` returns `error` for `*starlark.EvalError`, but a Go-level panic (e.g., nil-deref in unsupported `req.payload` type) crashes the request goroutine. Net/http catches goroutine panics with a default 500 (Go 1.13+), but the per-request log line never gets emitted (the deferred logger is in the panicking frame).
**Why it happens:** Trigger-time bridge returns errors for normal lambda failure (`fail("...")`), but a malformed value passed to `bridge.ToStarlarkStruct` could panic if a nested type isn't supported.
**How to avoid:** Add a `defer recover()` at the top of `makeHandler` returning 500 + `error_class=lambda_panic`. The structured log line emits with `recovered` field. Also: validate `req.payload` shapes — `ToStarlarkStruct` already returns errors for unsupported types, so passing the JSON-decoded body directly is safe (`map[string]any`, `[]any`, `string`, `float64`, `bool`, `nil` — all supported per `pkg/bridge/struct.go`).
**Warning signs:** Stack-trace pages from `net/http` default panic-handler in test logs. Missing structured log line for failed requests.

### Pitfall 5: Credential resolved with wrong context (workflow ctx leaking into receiver)
**What goes wrong:** Pass `r.Context()` for normal handler operations BUT a stale `context.Background()` to `credHandler.Resolve`. Cancellation doesn't propagate. Slow resolver hangs the request past `ReadTimeout`.
**Why it happens:** Easy mistake — `extension.CredentialHandler.Resolve(ctx, id)` takes any context; passing the wrong one is a silent error.
**How to avoid:** Always use `r.Context()` for resolver calls inside the handler. Document: "the receiver passes the HTTP request's context to all I/O; lambdas use a derived context with the trigger-time globals."
**Warning signs:** Slow webhook deliveries that should have timed out at request level are still running in the resolver after server shutdown.

### Pitfall 6: REJECT_DUPLICATE error type detection — `errors.As` requires pointer-to-pointer
**What goes wrong:** `if errors.As(err, &serviceerror.WorkflowExecutionAlreadyStarted{})` doesn't compile. `if errors.As(err, serviceerror.WorkflowExecutionAlreadyStarted{})` panics at runtime. Using `errors.Is` doesn't match because the error type isn't a sentinel.
**Why it happens:** `errors.As` takes a pointer to a typed nil variable. `serviceerror.WorkflowExecutionAlreadyStarted` is a struct value; the SDK returns `*WorkflowExecutionAlreadyStarted`.
**How to avoid:** Use:
```go
var alreadyStarted *serviceerror.WorkflowExecutionAlreadyStarted
if errors.As(err, &alreadyStarted) {
    // alreadyStarted.RunId is the existing workflow's run ID
    // Return 200 OK with {"status":"duplicate; skipped","workflow_id": composedID}
    return statusDuplicate
}
```
**Warning signs:** Test for redelivery dedup fails — second delivery returns 200 OK but logs `error_class=ok` not `duplicate_skipped`, OR returns 502 because err passes through to dispatch_failed branch.

### Pitfall 7: Fan-out failure mode — one trigger's ExecuteWorkflow error short-circuits siblings
**What goes wrong:** Loop calls ExecuteWorkflow for each trigger; first one's Temporal connection error (502) returns immediately, second trigger's workflow never gets dispatched.
**Why it happens:** Naive `for _, t := range trigs { id, err := dispatch(t); if err != nil { return 502 } }` short-circuits.
**How to avoid:** Accumulate results across all triggers; classify errors per-trigger; pick the WORST status code as the response (502 > 401 > 500 > duplicate > ok); list ALL successful workflow_ids in `flows_dispatched`. Document: "a 502 response for a fan-out delivery means at least one dispatch failed; the source provider's retry will redeliver, and successful workflows from this delivery dedup via REJECT_DUPLICATE on retry."
**Warning signs:** Mixed-success fan-out tests show only the first trigger's status; later triggers silently skipped.

### Pitfall 8: `gh webhook forward` requires `gh extension install cli/gh-webhook` first
**What goes wrong:** Reader follows walkthrough, runs `gh webhook forward --repo=...` — gets `unknown command "webhook"`. Frustrating fail-fast at start of demo.
**Why it happens:** `gh webhook` is a separately-installed gh extension (the binary is `cli/gh-webhook`), not a built-in subcommand of `gh`.
**How to avoid:** Walkthrough's prerequisites section lists explicitly:
```bash
gh extension install cli/gh-webhook
gh webhook forward --help  # confirms install
```
**Warning signs:** First-time walkthrough runners report `unknown command` on step 3.

### Pitfall 9: Listener bind failure mid-Start (e.g., port already in use)
**What goes wrong:** `worker.Start()` succeeds; HTTP listener.ListenAndServe returns "address already in use"; receiver crashes after worker started; logs are confusing.
**Why it happens:** `net.Listen` on a busy port returns an error that, in a goroutine via `go srv.ListenAndServe()`, gets lost unless the goroutine reports it.
**How to avoid:** Pre-bind via `net.Listen("tcp", addr)` synchronously BEFORE spawning the listener goroutine; pass the listener to `srv.Serve(ln)`. Errors surface inline before `worker.Start()` chain. Defensive but cheap.
**Warning signs:** k8s readiness probe lights green (worker started) but webhook deliveries get connection-refused. Log line "ListenAndServe: address already in use" appears AFTER startup banner instead of replacing it.

## Code Examples

### Example 1: HMAC-SHA256 signature validation (GitHub)

```go
// Source: GitHub webhook validation pattern (https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries)
// + Skytime constraint: hmac.Equal (not bytes.Equal); sha256= prefix handled.
package receiver

import (
    "crypto/hmac"
    "crypto/sha256"
    "encoding/hex"
    "errors"
)

// validateGitHubSignature compares the provided header value against an HMAC-SHA256
// over body using secret. The header value MUST be of the form "sha256=<hex>".
// Returns nil on match, an opaque error on mismatch or malformed header.
func validateGitHubSignature(headerValue string, body, secret []byte) error {
    const prefix = "sha256="
    if len(headerValue) < len(prefix) || headerValue[:len(prefix)] != prefix {
        return errors.New("signature_mismatch")
    }
    providedHex := headerValue[len(prefix):]

    mac := hmac.New(sha256.New, secret)
    mac.Write(body)
    expectedHex := hex.EncodeToString(mac.Sum(nil))

    // hmac.Equal is constant-time; bytes.Equal is NOT.
    if !hmac.Equal([]byte(providedHex), []byte(expectedHex)) {
        return errors.New("signature_mismatch")
    }
    return nil
}
```

### Example 2: WorkflowID composition + REJECT_DUPLICATE collision detection

```go
// Source: Skytime D-7.1-08 + go.temporal.io/sdk@v1.42.0 (verified internal/client.go:920-930)
package receiver

import (
    "context"
    "crypto/sha256"
    "encoding/base64"
    "errors"

    "go.temporal.io/api/serviceerror"
    enumspb "go.temporal.io/api/enums/v1"
    "go.temporal.io/sdk/client"

    "github.com/mikelalcon/skytime/pkg/dag"
)

// composeWorkflowID returns "{flow_name}/{trigger_pos_hash}/{user_key}".
// trigger_pos_hash = base64url(sha256(trigger.Position.String()))[:8]
func composeWorkflowID(t *dag.Trigger, userKey string) string {
    sum := sha256.Sum256([]byte(t.Pos.String()))
    posHash := base64.RawURLEncoding.EncodeToString(sum[:])[:8]
    return t.FlowName + "/" + posHash + "/" + userKey
}

// dispatchOne dispatches one trigger and classifies the result. Returns one
// of three logical outcomes: {ok, duplicate, error}.
type dispatchResult struct {
    workflowID    string
    duplicate     bool
    networkErr    error // non-nil → 502
    transientErr  error // non-nil → 500 (lambda or other)
}

func dispatchOne(ctx context.Context, c client.Client, t *dag.Trigger, taskQueue, userKey string, input map[string]any) dispatchResult {
    workflowID := composeWorkflowID(t, userKey)
    opts := client.StartWorkflowOptions{
        ID:                                       workflowID,
        TaskQueue:                                taskQueue,
        WorkflowIDReusePolicy:                    enumspb.WORKFLOW_ID_REUSE_POLICY_REJECT_DUPLICATE,
        WorkflowExecutionErrorWhenAlreadyStarted: true, // CRITICAL — without this, collision is silent.
    }
    _, err := c.ExecuteWorkflow(ctx, opts, "SkytimeWorkflow", input)
    if err == nil {
        return dispatchResult{workflowID: workflowID}
    }

    // Check for REJECT_DUPLICATE collision — idiomatic errors.As pattern.
    var alreadyStarted *serviceerror.WorkflowExecutionAlreadyStarted
    if errors.As(err, &alreadyStarted) {
        return dispatchResult{workflowID: workflowID, duplicate: true}
    }

    // Network / Temporal-unreachable errors — return 502.
    // (No exact SDK type for "connection refused"; pragmatic check on the
    // gRPC-level status, or simply: treat any unclassified error as 502
    // since we already excluded the legitimate REJECT_DUPLICATE case.)
    return dispatchResult{networkErr: err}
}
```

### Example 3: ServeMux mount loop with fan-out grouping

```go
// Source: Skytime Phase 7.1 D-7.1-06 (fan-out routing) + Phase 7 Plan 04 worker.Triggers().All()
package receiver

import (
    "net/http"
    "sort"

    "github.com/mikelalcon/skytime/pkg/dag"
    "github.com/mikelalcon/skytime/pkg/worker"
    "go.temporal.io/sdk/client"
)

type mountKey struct {
    kind, path, method string
}

// Mount walks the worker's trigger registry, groups HTTP-shaped triggers by
// (kind, path, method), and registers one handler per group on the mux. The
// returned http.Handler is mux itself (caller wires it onto an http.Server).
func Mount(mux *http.ServeMux, w *worker.Worker, c client.Client, deps Deps) {
    groups := map[mountKey][]*dag.Trigger{}
    for _, t := range w.Triggers().All() {
        m, ok := t.Source.(HTTPMounter)
        if !ok {
            continue // cron sources etc.
        }
        path, method := m.HTTPMount()
        key := mountKey{kind: t.Source.Kind(), path: path, method: method}
        groups[key] = append(groups[key], t)
    }
    for key, trigs := range groups {
        // Stable sort by (FlowName, Pos) per D-7.1-06.
        sort.SliceStable(trigs, func(i, j int) bool {
            if trigs[i].FlowName != trigs[j].FlowName {
                return trigs[i].FlowName < trigs[j].FlowName
            }
            return trigs[i].Pos.String() < trigs[j].Pos.String()
        })
        mux.HandleFunc(key.path, methodGate(key.method, makeHandler(key, trigs, c, deps)))
    }
}

// methodGate returns 405 Method Not Allowed for non-matching methods.
// Stdlib net/http.ServeMux does NOT method-dispatch; we layer it ourselves.
func methodGate(want string, next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        if r.Method != want {
            http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
            return
        }
        next(w, r)
    }
}
```

```go
// Source: Skytime Phase 7.1 D-7.1-11 + Phase 7 Plan 05 signal loop pattern
// Locked stage names extended: existing 6 + listener_shutdown_started + listener_shutdown_complete

func (s *serverState) runWithListenerDrain(rootCtx context.Context, drainTimeout time.Duration) error {
    sigCh := make(chan os.Signal, 2)
    signal.Notify(sigCh, syscall.SIGINT, syscall.SIGTERM)
    defer signal.Stop(sigCh)

    ln, err := net.Listen("tcp", s.addr) // synchronous bind error before goroutine
    if err != nil {
        return fmt.Errorf("listener: %w", err)
    }
    srv := &http.Server{
        Handler:           s.mux,
        ReadHeaderTimeout: 10 * time.Second,
        ReadTimeout:       30 * time.Second,
        WriteTimeout:      30 * time.Second,
        IdleTimeout:       60 * time.Second,
        MaxHeaderBytes:    64 * 1024,
    }
    go func() {
        if err := srv.Serve(ln); err != nil && err != http.ErrServerClosed {
            s.logger.Error("listener exited unexpectedly", "err", err)
        }
    }()
    s.hookStage("listener_started")

    <-sigCh
    s.hookStage("signal_received")

    drainCtx, cancel := context.WithTimeout(rootCtx, drainTimeout)
    defer cancel()

    // PHASE 1: listener stops accepting; in-flight handlers finish.
    s.hookStage("listener_shutdown_started")
    if err := srv.Shutdown(drainCtx); err != nil {
        s.logger.Warn("listener shutdown returned error", "err", err)
    }
    s.hookStage("listener_shutdown_complete")

    // PHASE 2: worker drain.
    done := make(chan struct{})
    var stopOnce sync.Once
    go func() {
        stopOnce.Do(func() {
            s.hookStage("drain_started")
            s.worker.Stop()
            close(done)
        })
    }()

    select {
    case <-done:
        s.hookStage("drain_completed")
        return nil
    case <-sigCh:
        s.hookStage("drain_forced")
        s.testForceExit(1)
        return nil
    case <-drainCtx.Done():
        s.hookStage("drain_timeout")
        return errSilent
    }
}
```

### Example 6: Body-size-limited request reading

// Source: Go stdlib pattern; D-7.1-12 25MB cap matches GitHub's webhook payload max.
package receiver

import (
    "fmt"
    "io"
    "net/http"
)

const maxBodyBytes = 25 * 1024 * 1024 // 25MB — matches GitHub webhook payload cap.

func readBody(w http.ResponseWriter, r *http.Request) ([]byte, error) {
    r.Body = http.MaxBytesReader(w, r.Body, maxBodyBytes)
    body, err := io.ReadAll(r.Body)
    if err != nil {
        // MaxBytesError is a typed error; on overflow, http.MaxBytesReader
        // also writes a 413 Request Entity Too Large to w if the response
        // hasn't started.
        return nil, fmt.Errorf("read body: %w", err)
    }
    return body, nil
}
