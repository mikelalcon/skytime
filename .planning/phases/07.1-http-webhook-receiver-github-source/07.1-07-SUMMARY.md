## Accomplishments

### EX-05: Crash-recovery demo flow shipped (D-7.1-16)

The new `examples/http-github-webhook/webhook_demo.star` declares one trigger + one flow that together demonstrate Temporal's headline durability story end-to-end against a real provider (GitHub) without tunnels or OAuth app registration:

1. Open an issue in the test repo — `gh webhook forward` delivers to `POST /webhook/github`.
2. `gh.add_comment("received, processing...")` runs immediately.
3. Reader kills `extbin server` with Ctrl-C BEFORE the second step fires.
4. Reader restarts the server with the same command.
5. `gh.add_label("processed")` fires shortly after restart — Temporal's event history recorded step 1's completion; restart picks up at step 2.

The shape is locked via the .star file's module docstring (the canonical walkthrough copy lives next to the code). Plan 08's README quickstart and `docs/walkthroughs/github-webhook.md` long-form will reference this language verbatim.

### Trigger lambdas: nested chain + subscript access tolerated

```python
trigger(
    flow = "webhook_demo",
    source = github.webhook(
        events = ["issues"],
        secret_credential = "github_webhook_secret",
    ),
    map = lambda req: {
        "repo": req.payload.repository.full_name,    # nested DotExpr — only .payload validated
        "issue_number": req.payload.issue.number,    # same
    },
    idempotency_key = lambda req: req.headers["X-GitHub-Delivery"],  # IndexExpr on .headers
    credential = "github_webhook_secret",
)
```

The parser walker (`pkg/parser/req_walk.go::findFreeVarAccesses` lines 39-89) only validates direct `req.<attr>` references — nested chains pass through and resolve at runtime. Verified during planning by reading the walker source.

## Decisions Made

- **Honored the locked NO-sleep shape** — Plan 07 iteration 1 already downscoped D-7.1-16's "30-second sleep" suggestion because the bridge's `triggerTimeGlobals` exposes lambda-time globals only (NOT `workflow.Sleep`). Two-activity cross-activity continuation achieves the durability demonstration without inventing a placeholder primitive. Future phases may add `core.sleep(seconds=N)` if desired.
- **Used `step(action_fn=lambda ctx: gh.add_comment(...))`** rather than the static `step(action=...)` form because the action references int-typed `ctx.issue_number` and string-typed `ctx.repo.split("/")[N]` derivations — the static-action path cannot resolve typed ctx values (D4.1 lambdas are the right shape for typed-input mappings; this matches the issue_triage.star then-branch pattern from Phase 6).
- **Added `TestWebhookDemo_BootsCleanly` as a separate test function** (not a parametric expansion of `TestFlows_ParseAll`) so a regression that drops the trigger surfaces with a precise failure message at the trigger-registration assertion.
