### TRIG-06 fully satisfied: HTTP listener bind + receiver mount + drain

`skytime server` now boots a real HTTP listener on `--addr` AFTER worker.Start succeeds, mounts the receiver dispatcher onto the http.ServeMux via `receiver.Mount`, and runs `srv.Serve(ln)` in a goroutine. The boot order is locked by D-7.1-10 (worker first, then listener) so K8s readinessProbe = TCP connect to `--addr` is honest.

```text
1. range-validate drainTimeout
2. setupServerLogging
3. credfile sanity check
4. connectClient(cfg) → c
5. worker.NewWorker(c, opts, testWorkerOptions...) → w
6. printStartupBanner — emits flows + triggers (with mount paths for HTTP sources)
7. signal.Notify(sigCh, SIGINT, SIGTERM)
8. w.Start() → hookStage("worker_started")
9. mux := http.NewServeMux(); receiver.Mount(mux, w, deps)
10. ln := net.Listen("tcp", addr)              ← pre-bind synchronously (Pitfall 9)
11. srv := &http.Server{Handler: mux, ...timeouts...}
12. go srv.Serve(ln) → hookStage("listener_started")
13. <-sigCh → hookStage("signal_received")
14. drainCtx, cancel := context.WithTimeout(...)
15. hookStage("listener_shutdown_started")
16. srv.Shutdown(drainCtx)                      ← listener-first drain (D-7.1-11)
17. hookStage("listener_shutdown_complete")
18. go { hookStage("drain_started"); w.Stop(); close(done) }
19. select { done | sigCh | drainCtx.Done() }
```

### D-7.1-12 HTTP server defaults locked

```go
srv := &http.Server{
    Handler:           mux,
    ReadHeaderTimeout: 10 * time.Second,  // slowloris defense
    ReadTimeout:       30 * time.Second,  // full request
    WriteTimeout:      30 * time.Second,  // full response
    IdleTimeout:       60 * time.Second,  // keep-alive ceiling
    MaxHeaderBytes:    64 * 1024,         // header DoS defense
}
```

Body-size limit (25MB) is enforced per-handler via `http.MaxBytesReader` inside `receiver.makeHandler` (Plan 04b). Server-level body caps would conflict with the per-source GitHub 25MB ceiling and prevent extension authors from raising the limit for non-GitHub sources.

`TestServerCmd_HTTPServerDefaults` source-greps server.go and asserts each of the 5 literals is present. Regression-prevention against a careless constant swap.

### Listener-first shutdown (D-7.1-11)

The shared `drainCtx` (with `--drain-timeout` deadline) caps total drain budget across BOTH the listener and worker stages:

1. `srv.Shutdown(drainCtx)` runs FIRST — refuses new requests immediately and lets in-flight HTTP requests finish (which means in-flight ExecuteWorkflow dispatch calls finish — the workflow itself is now durable on the Temporal server).
2. `worker.Stop()` runs second — Temporal SDK semantics: stop polling new tasks, finish in-flight activity executions.
3. If `drainCtx` expires during EITHER stage, the select's `<-drainCtx.Done()` case fires, RunE returns errSilent with the timeout message, and Temporal's event history records the partial state for replay on next boot.

`TestServerCmd_DrainTimeoutExpiry` proves this: with `--drain-timeout=1s` and a fake worker.Stop that blocks 5s, the empty mux's Shutdown completes instantly leaving the full drain budget for the worker; `drain_timeout` fires and RunE returns errSilent.

### Pitfall 9: synchronous bind error surface

`net.Listen("tcp", addr)` runs on the FOREGROUND RunE goroutine BEFORE the `go srv.Serve(ln)` goroutine spawns. If the bind fails (port in use), `net.Listen` returns an error and RunE returns `errSilent` immediately — no race window where the listener goroutine swallows the error in a delayed log line. Tests that race two processes on the same port get a deterministic failure path.
