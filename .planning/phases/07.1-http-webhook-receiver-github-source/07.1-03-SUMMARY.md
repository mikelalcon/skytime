## Accomplishments

### TRIG-07: github.webhook source factory shipped

The `github.webhook(events=[...], secret_credential="...")` Starlark factory now constructs a `*githubWebhookSource` value satisfying both `extension.TriggerSource` (sealed) and `receiver.HTTPMounter`. The signature scheme is hardcoded — users cannot override the algo or header — matching D-7.1-04. The locked path is `/webhook/github`, the locked method is `POST`, and both are returned by `HTTPMount()` so Plan 04's mount loop discovers them via type assertion.

```python
# Authored .star example (resolves at parse time):
trigger(
    flow="webhook_demo",
    source=github.webhook(
        events=["issues"],                              # case-sensitive allowlist; [] = all events
        secret_credential="github_webhook_secret",      # ID string only — never the resolved Secret
    ),
    map=lambda req: {"repo": req.payload.repository.full_name},
    idempotency_key=lambda req: req.headers["X-GitHub-Delivery"],
    credential="github_webhook_secret",
)
```

### ShouldDispatch event filter (D-7.1-07)

```go
func (s *githubWebhookSource) ShouldDispatch(eventName string) bool {
    if len(s.events) == 0 {
        return true              // empty list = match all events
    }
    for _, e := range s.events {
        if e == eventName {      // case-sensitive against GitHub's docs
            return true
        }
    }
    return false
}
```

Plan 04's handler reads `X-GitHub-Event` once per delivery and calls `source.ShouldDispatch(eventName)` per trigger before dispatching ExecuteWorkflow.

### TRIG-09 lock firewall

`TestGithubWebhook_HardcodedAlgoAndHeader` reads `webhook.go` bytes and asserts:
- `"sha256"` literal present (the locked algo)
- `"X-Hub-Signature-256"` literal present (the locked header)
- `"signature_algo"` literal absent (no kwarg exposure)
- `"signature_header"` literal absent (no kwarg exposure)

Any future drift adding a `signature_algo` kwarg trips this test. The locked semantics are bytes-level enforced.

### MarshalJSON contract (D-07-09 + D-07-10 firewall)

```json
{"kind":"github.webhook","config":{"events":["issues"],"credential_id":"my-secret-id"}}
```

`omitempty` on both fields:
- Empty events list → `events` key omitted entirely.
- Empty credential ID → `credential_id` key omitted entirely.

`TestGithubWebhook_NoSecretInConfig` round-trips both shapes and asserts the keys are/aren't present accordingly. NEVER does a `extension.Secret`-typed value reach the marshaled bytes — the resolver is invoked JIT inside Plan 04's request handler, not here.
