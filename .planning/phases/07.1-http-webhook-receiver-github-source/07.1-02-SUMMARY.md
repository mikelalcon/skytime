## Decisions Made

- **TriggerSourceSeal embeddable carrier** — chose this over alternatives (exporting the marker; moving concrete types into pkg/extension). Embedding is greppable, preserves the seal's intent (downstream packages must explicitly `import pkg/extension` to opt in via `extension.TriggerSourceSeal`), and required only ~30 LOC + a `var _ extension.TriggerSource = (*T)(nil)` assertion in each concrete type. FakeTriggerSource keeps its in-package marker declaration; embedding is also optional for in-package types (would work either way).
- **Tests-via-minimal-module helper for Task 1, Initialize-via-production-path test for Task 2** — TDD atomicity: Task 1 failures surface as factory bugs, Task 2 failures surface as Members-map bugs. The `TestExtension_StarFileCallsHttpWebhook` test in Task 2 is the integration gate.
- **Factory unmarshaler receives inner config bytes only** — corrected from the plan's pseudocode (which had the factory parsing the full `{kind, config}` envelope). The dispatcher (`extensionTriggerUnmarshaler`) peels the envelope and passes only the config bytes; the factory is simpler and the kind check is redundant (the dispatcher already verified it).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing Critical Functionality] Added `extension.TriggerSourceSeal` embeddable carrier to satisfy seal across package boundary**

- **Found during:** Task 1 (initial compilation of *httpWebhookSource)
- **Issue:** The plan's `<interfaces>` block claimed: "wrapping is INSIDE pkg/extension/builtin/http (a sub-package of pkg/extension), so the seal is reachable directly. No outer wrapper needed." This is **incorrect** — Go scopes unexported method names to the declaring package, so `pkg/extension/builtin/http` (a separate Go package despite the directory hierarchy) cannot declare a method named `triggerSourceMarker()` that satisfies `pkg/extension.TriggerSource`. The compile-time error is: "*httpWebhookSource does not implement extension.TriggerSource (unexported method triggerSourceMarker)". This is the same contradiction `pkg/extension/triggersource_fake.go` documents (line 33: "Go does NOT permit sub-packages to satisfy a parent-package unexported-method seal"), but Phase 7's documentation also explicitly says sources live under their owning extension's namespace (D-07-08, codified in `pkg/extension/trigger.go` line 11). Without resolution, this would block ALL future concrete TriggerSource types — `http.webhook` (this plan), `github.webhook` (Plan 03), and any downstream user extension.
- **Fix:** Added `TriggerSourceSeal` zero-sized struct to `pkg/extension/trigger.go` with a value-receiver `triggerSourceMarker()` method. Concrete types in any package embed `extension.TriggerSourceSeal` as a struct field; Go's method promotion routes the unexported marker onto the embedding type. The seal's intent is preserved: downstream packages must explicitly import `pkg/extension` and embed the carrier — drive-by satisfaction (declaring an unexported method on a foreign type) is still impossible. Updated the `TriggerSource` doc comment to mandate embedding in foreign packages and added a usage example.
- **Files modified:** `pkg/extension/trigger.go`
- **Verification:** `var _ extension.TriggerSource = (*httpWebhookSource)(nil)` compile-time assertion in webhook.go; `go test ./pkg/extension/...` green; FakeTriggerSource's existing in-package marker declaration still works (the embedding is additive, not replacing).
- **Committed in:** `0ad6500` (Task 1 commit)

**2. [Rule 1 — Bug] Factory unmarshaler signature corrected to receive config bytes, not full envelope**

- **Found during:** Task 1 (TestHttpWebhook_RegisterFactoryRoundTrip RED)
- **Issue:** Plan's pseudocode had the registered factory parsing the full `{"kind": "http.webhook", "config": {...}}` envelope and verifying the kind discriminator. But `pkg/extension/trigger_unmarshal.go::extensionTriggerUnmarshaler` already peels the envelope and dispatches by kind — the factory only ever receives the inner config bytes. With the original signature, the test failed with: "expected kind \"http.webhook\", got \"\"".
- **Fix:** Changed the factory body to parse only the inner config object (path/method/signature_algo/signature_header/credential_id); removed the redundant kind check.
- **Files modified:** `pkg/extension/builtin/http/webhook.go`
- **Verification:** `TestHttpWebhook_RegisterFactoryRoundTrip` GREEN.
- **Committed in:** `0ad6500` (Task 1 commit, alongside the original code)
