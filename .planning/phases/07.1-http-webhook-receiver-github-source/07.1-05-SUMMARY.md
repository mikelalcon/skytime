### worker.SDKFactory + worker.Option + worker.WithSDKFactory (Task 1)

Three new exports in `pkg/worker/options.go`:

```go
// SDKFactory mirrors sdkworker.New's signature exactly.
type SDKFactory func(c client.Client, taskQueue string, opts sdkworker.Options) sdkworker.Worker

// Option is the functional-options surface for NewWorker.
type Option func(*workerOptions)

// workerOptions is the internal mutable state (distinct from user-facing
// WorkerOptions which carries production config).
type workerOptions struct {
    sdkFactory SDKFactory
}

// WithSDKFactory overrides the SDK worker constructor for ONE NewWorker
// call. Per-call scope: does NOT mutate the package-level sdkWorkerNew var.
func WithSDKFactory(f SDKFactory) Option {
    return func(o *workerOptions) { o.sdkFactory = f }
}
```

`NewWorker`'s signature gained a variadic `...Option` tail:

```go
func NewWorker(c client.Client, opts WorkerOptions, options ...Option) (*Worker, error) {
    if err := opts.applyDefaults(); err != nil { return nil, err }

    var optState workerOptions
    for _, opt := range options { opt(&optState) }

    // ... boot, dispatch build, sdkOpts construction ...

    factory := SDKFactory(sdkWorkerNew)
    if optState.sdkFactory != nil { factory = optState.sdkFactory }
    sdkW := factory(c, opts.TaskQueue, sdkOpts)

    // ... register workflow + activity, return *Worker ...
}
```

Plus a compile-time assertion above NewWorker:

```go
var _ SDKFactory = sdkWorkerNew
```

This catches future SDK signature drift at build time — if `sdkworker.New`'s signature changes, the assignment fails to compile and the SDKFactory type must be updated to match.

### signal.Notify hoisted before worker_started hook (Task 2)

Before this plan, server.go installed `signal.Notify` AFTER `hookStage("worker_started")`. That left a race where the test process could receive SIGTERM (sent by tests via `syscall.Kill`) before the handler was active — terminating the test process.

The fix moves signal.Notify to BEFORE `w.Start()` and `hookStage("worker_started")`:

```go
// 7. Two-signal escalation via signal.Notify ...
sigCh := make(chan os.Signal, 2)
signal.Notify(sigCh, syscall.SIGINT, syscall.SIGTERM)
defer signal.Stop(sigCh)

// 8. Start (non-blocking per D3-18).
if err := w.Start(); err != nil { ... }
hookStage("worker_started")  // signal handler is now LIVE
```

Production behavior is unchanged — signal handling still triggers identical drain semantics. The reorder makes `worker_started` a true sync point that black-box tests can rely on.

### `stageRecorder` thread-safe drain stage capture

```go
type stageRecorder struct {
    mu     sync.Mutex
    stages []string
    ch     chan string  // buffered; non-blocking sends
}

func (r *stageRecorder) record(stage string) { ... }
func (r *stageRecorder) waitFor(target string, deadline time.Duration) bool { ... }
func (r *stageRecorder) snapshot() []string { ... }
```

`record` appends to the slice under a mutex AND non-blocking-sends to the channel. `waitFor` first polls the slice (fast path: stage already recorded) then blocks reading the channel until the target stage lands or the deadline elapses. `snapshot` returns a defensive copy.

This pattern is reusable for any signal-loop test where stages arrive asynchronously and the test needs to both observe individual stages (waitFor) and assert the final sequence (snapshot).

## Decisions Made

- **Variadic ...Option tail rather than NewWorkerWithOptions constructor.** Existing callers (pkg/cli/run.go, pkg/cli/server.go, embed_integration_test.go, pkg/worker/doc.go example) compile unchanged with zero source modification. A separate constructor would have required touching every call site.
- **Per-call closure scope rather than package-var swap.** Pointer-equality assertion in TestNewWorker_OptionDoesNotAffectGlobalSdkWorkerNew proves the package-level `sdkWorkerNew` is byte-identical before and after a WithSDKFactory call. Safe for parallel test runs.
- **Compile-time SDKFactory assertion.** `var _ SDKFactory = sdkWorkerNew` catches future SDK signature drift. If `sdkworker.New` evolves, the assignment breaks at build time and SDKFactory must be updated.
- **signal.Notify hoisted before worker_started hook.** Originally Phase 7's server.go installed signal.Notify AFTER hookStage("worker_started"), leaving a race window where test-side `syscall.Kill(SIGTERM)` could terminate the test process before the handler was live. The reorder makes worker_started a deterministic sync point. Production semantics unchanged.
- **Real syscall.Kill over in-process signal mocking.** The plan considered an exported `sigCh` test seam but the cleaner path is to exercise `signal.Notify` itself — that's what production code uses. The buffered `sigCh` (size 2 in server.go) handles two signals deterministically; the recorder + waitFor pattern handles asynchrony.
- **stageRecorder kept local to server_test.go.** Could be extracted to a helper file but keeping it inline keeps the test file self-contained. If Phase 7.1 Plan 06 (listener bind tests) needs the same pattern, factor at that point.
- **fakeReceivingWorker is a separate stub from worker_test.go's fakeSDKWorker.** They live in different packages and test different things. Duplicating ~40 lines of interface methods is cheaper than introducing a shared `pkg/worker/testing` subpackage just for this.
