## Decisions Made

- **`MTLSReloader` typed struct, not a closure-returning function** — the cloud snippets return `client.Credentials` directly because the SDK owns the per-RPC fetch lifecycle. mTLS rotation owns its own lifecycle (initial dial + signal-driven re-dial + final Close), so a struct with explicit methods (`Current`, `Close`) is more honest about what the caller has to manage. Trade-off: the user MUST call `reloader.Close()` at shutdown; the caller-site example documents this via `defer reloader.Close()`.
- **`atomic.Pointer[client.Client]` + `sync.Mutex` combined** — atomic.Pointer makes `Current()` lock-free for the hot RPC path; the Mutex serializes back-to-back SIGHUPs so the `LoadX509KeyPair` + `os.ReadFile` + `client.Dial` sequence is atomic with respect to other reload() invocations. Without it, two rapid SIGHUPs could race and leak a client.
- **Re-dial after reload (not in-place tls.Config mutation)** — `client.Options.ConnectionOptions.TLS` is consumed by `client.Dial` once; the gRPC connection's transport credentials are bound at that point. Mutating the tls.Config after Dial does nothing for new connections (and is unsafe for active ones). The pattern is: build a fresh `tls.Config` → `client.Dial(new options)` → swap → Close old. Documented in the prose preamble.
- **Stderr for reload-failure logging (not slog)** — production code uses slog with a structured handler, but the snippet keeps it to `fmt.Fprintf(os.Stderr, ...)` to avoid pulling slog into the snippet's import surface (one less line of context for the reader; the comment explicitly calls out 'Production: log via slog' so readers know the substitution).
- **`kill -HUP $(pgrep my-worker)` shown as the manual trigger** — gives the reader a concrete way to test the pattern without wiring cert-manager + Vault locally. The Assumes bullet explicitly names cert-manager and Vault as the production rotation tools; the manual trigger is the bridge for adoption.
- **Cross-link to `pkg/worker/client.go::NewSelfHostedClient`** — anchors the snippet against skytime's own use of the same `client.Options.ConnectionOptions.TLS` shape. Important context: skytime's `NewSelfHostedClient` is short-lived (CLI invocations like `skytime run`); the snippet's reload loop is the addition long-running custom binaries need. Avoids accidentally implying skytime does cert reload internally (it does not).
- **`MTLSReloader` exported (capital M); `newMTLSReloader` unexported (lowercase)** — matches the Plans 02-04 convention where the constructor is unexported. The type has to be exported so callers can name it in their own struct fields / function signatures (no equivalent need in the cloud snippets, which return the SDK's already-exported `client.Credentials` interface).
- **No `go mod tidy`** — all imports are stdlib + `go.temporal.io/sdk/client` (already present from Plan 01). `go.mod` and `go.sum` unchanged. Cleaner than the cloud snippets which each added 1-2 module requires + transitives. The build + vet + test verification in Task 1 confirmed no missing imports.
