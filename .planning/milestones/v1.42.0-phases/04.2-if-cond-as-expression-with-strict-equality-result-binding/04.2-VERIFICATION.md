# Phase 04.2: if_cond as expression with strict-equality result binding — Verification Report

**Phase Goal:** Replace the purely procedural `if_cond` with an EXPRESSION-shaped variant where each branch may end with `result(value={...})` and the `if_cond` itself binds a typed value back into workflow state under a new `output_alias`. Strict structural equality across branches is enforced at parse time (no LUB; explicit casts widen). Add a top-level `fail("msg")` node-builtin enabling asymmetric branch shapes. Implementation is parser-side; runtime semantics of `walkIfCond` add minimal extension for two new last-node cases (`*dag.Result` binds to ctx; `*dag.Fail` raises NonRetryableErr). Coexistence is ADDITIVE — `output_alias` is opt-in.
