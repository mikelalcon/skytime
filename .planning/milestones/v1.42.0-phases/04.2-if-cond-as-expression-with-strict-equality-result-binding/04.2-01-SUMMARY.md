## Decisions Made

- **Result.Types is map[string]any (not map[string]TypeInfo)** — pkg/dag MUST NOT import pkg/parser; the cross-package marker convention with a documented type-assertion contract preserves layering. Plan 03 validator type-asserts back; interpreter never reads Types.
- **Strict no-LUB Equal()** — int ≠ float at compile time; Opaque vs concrete returns false. Branch-equality validator (plan 03) detects opaque-on-either-side BEFORE calling Equal and defers explicitly; Equal stays compile-time strict to keep the seal honest.
- **stateSet → stateSchema rename preserves the D4-02 walker's visibility API** verbatim — has/clone/sortedKeys keep their names; add() takes (name, TypeInfo); addUntyped() is the visibility-only shortcut. typeFromHint() maps Inputs hint strings to seed TypeInfo (int/float/bool/string scalars; list/array → list[opaque]; dict/object/map → dict; unknown → opaque).
- **Wave 0 RED scaffolding chooses 'fail loudly with deliberate plan-naming message' over t.Skip** — keeps the RED → GREEN signal visible in `go test -run ...` output throughout plans 02-05; the failure messages explicitly name "RED until plan 02 ships builtinResult" so engineers know exactly what makes them GREEN.
- **inferType stub signature locked at `(e syntax.Expr, schema stateSchema, firstParam string) TypeInfo`** — plan 02 drops in the real body without touching `parseInferExpr` test helper or any call site.
- **Pos-exclusion JSON convention extended verbatim** — Result and Fail marshal-time shapes deliberately exclude Pos for cross-machine golden stability. Values + Types also excluded in v1 (lambda IDs are content-hash-suffixed and unstable across cosmetic edits; TypeInfo encoding with kind discriminators is out of scope for v1 goldens — Pitfall 8 deferred).

## Deviations from Plan

The plan referenced a `nodeJSONWrap` discriminator wrapper to extend; the actual codebase pattern is per-type `MarshalJSON()` methods on each Node implementation (verified by `grep -rn 'nodeJSONWrap' pkg/dag/` returning zero matches). The new `*Result.MarshalJSON` and `*Fail.MarshalJSON` methods integrate via Go's default `[]Node` encoder, which calls each element's `MarshalJSON()` automatically. No further dispatch wrapper needed; the marshal extension matches the existing pattern verbatim. **Documented as a documentation-vs-codebase discrepancy in the plan, not a deviation in implementation.**

Otherwise: **None — plan executed exactly as written.**
