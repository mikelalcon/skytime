## Branch-coverage rule (sub-question of state-binding)

| Option | Description | Selected |
|--------|-------------|----------|
| Both required, parse-time error | Setting output_alias requires else_ present and last node = result() in each branch. | (refined) |

**User's reply:** "else can omit only if and ONLY if the other branch ends in error. do we have error()?"

**Resolution path:** User's ask required a parse-time-visible "fatal branch" primitive. Today only `fail()` lambda-time global exists (raises at runtime; not parse-time-visible without fragile lambda-body walking). Took asymmetric-branch question into a follow-up.

## Asymmetric branch primitive (one returns value, the other fails)

| Option | Description | Selected |
|--------|-------------|----------|

**User's reply:** "can we just use fail? and actually, can we use string interpolation there? (VERY IMPORTANT!). If no...then we add error"

**Resolution path:** Confirmed (a) `fail` could be reused at top-level — different predeclared environment, no Starlark collision; (b) `${ctx.expr}` interpolation works regardless of name (parser-time desugaring per D4.1-01, with `MessageFn` field mirroring `Step.NameFn`). Re-asked the naming question explicitly with interpolation confirmed.

## `result(...)` shape disambiguation

| Option | Description | Selected |
|--------|-------------|----------|
| Static keys, expression values | `result(value={"healthy": ctx.healthy, ...})` — literal-string keys; per-value expressions captured as per-key synthesized lambdas; type-inferred. | ✓ |
| Fully literal (no ctx access) | `result(value={"healthy": True})` — no expressions allowed. Limits expression mode to selecting among pre-computed sentinels. | |
| Kwargs-as-keys | `result(healthy=ctx.healthy, repo=ctx.repo)` — variadic kwargs are the keys. | |

**User's choice:** Static keys, expression values.
**Notes:** Each dict value captured via the same desugaring infrastructure as D4.1-01 interpolation. Parser type-infers each value (literals → known type; ctx.X → state-schema lookup; operators by Starlark semantics; locked-vocab calls by known return types).

| Option | Description | Selected |

| Scalars + dicts only | Stricter; defers list shapes. | |

**User's choice:** Permissive — defer-to-runtime for opaque exprs.
**Notes:** Strict equality applies where both sides are inferable; opaque values pass. Keeps strict-equality posture for the structural shape (keys must match exactly) while pragmatically accepting limits on value-expression analysis. No widening (`int` ≠ `float`) — explicit casts handle widening.
