## Conceptual Blocks (~80 words each)

### ${ctx.expr} Interpolation

Quoted snippet:
```python
fail("invalid user_id: '${ctx.user_id}'")
```
Explanation: at parse time, the `${ctx.user_id}` marker desugars into a synthesized lambda equivalent to `lambda ctx: "invalid user_id: '" + str(ctx.user_id) + "'"`. The lambda evaluates inside the workflow at fail-time (so the message reflects the actual runtime user_id). Cite D4.1-01 + D4.1-22 (the carve-out — this is parse-time syntactic sugar, NOT runtime template evaluation).

### Expression-Mode if_cond

Quoted snippet:
```python
if_cond(
    output_alias = "user",
    cond = lambda ctx: ctx.user_id != "",
    then = [result(value = {"id": ctx.user_id, "ok": True})],
    else_ = [fail("invalid user_id: '${ctx.user_id}'")],
)
```
Explanation: when `output_alias` is non-empty, `if_cond` becomes a value-producing expression. Each branch must end in `result()` or `fail()`. The bound value lands at `ctx.<alias>` for downstream steps. Cite DSL-14 + D4.2-09.

### result() Binding to ctx

Quoted snippet:
```python
then = [result(value = {"id": ctx.user_id, "ok": True})],
```
Explanation: each value in the dict-literal is captured as a parse-time lambda; at workflow-execute time, the lambdas evaluate against the live ctx (so `ctx.user_id` resolves to the input). The resulting dict is bound to `ctx.user` (per output_alias). Downstream steps read `ctx.user.id` etc. Cite DSL-15 + D4.2-13 (typed state schema).

### fail() with Interpolation

Quoted snippet:
```python
else_ = [fail("invalid user_id: '${ctx.user_id}'")],
```
Explanation: top-level `fail()` is a parse-time builtin that emits a workflow-failure node. At runtime it raises a NonRetryableApplicationError with the interpolated message at the .star callsite — visible in the renderer's "flow_failed" line. Distinct from the lambda-time `fail()` global available inside lambda bodies. Cite D4.2-05 + D4.2-07 + the dual-fail pkg/parser/doc.go reference.
