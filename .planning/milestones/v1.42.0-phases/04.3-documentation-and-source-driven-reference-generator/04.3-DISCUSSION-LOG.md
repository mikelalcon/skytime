## Docs format and hosting

| Option | Description | Selected |
|--------|-------------|----------|
| Plain markdown in /docs | GitHub renders out-of-the-box; no build pipeline; contributors edit one file. Easiest start, can upgrade later. | ✓ (with augmentation — see below) |
| mkdocs-material site | Generated site with search, nav sidebar, code-copy buttons. Adds Python tooling + GitHub Action to publish to gh-pages. | |
| Docusaurus site | React/Node tooling, versioned docs, MDX. Heaviest infra; overkill for a v1 library. | |

**User's choice:** Plain markdown sgtm — but with a source-driven reference guide like Copybara generates from Java annotations.
**Notes:** This pivot expanded scope significantly: `cmd/skytime-docgen` tool added as in-scope. User asked whether Go has an annotation-equivalent. Answer: no annotations, but `go/parser` + `go/ast` + structured doc comments + AST walking is the canonical approach. `gomarkdoc` exists for package-level docs but doesn't know about Starlark builtin shapes — building Skytime-specific docgen is justified.

## Marker syntax

| Option | Description | Selected |
|--------|-------------|----------|
| Block with key=value pairs | `// skytime:doc summary="..." returns="..."` — easy to write, parse, grep. Mirrors gomarkdoc + Go test convention. | ✓ |
| Multi-line block with --- separator | `/* skytime:doc\n  summary: ...\n  returns: ...\n*/` — YAML-flavored, more verbose. | |
| Free-form prose + minimal structure | Just regular Go doc comment above builtin. First sentence is summary. | |

**User's choice:** Block with key=value pairs
**Notes:** Multi-line values via repeated `// skytime:doc` lines with same key (newline-joined). Quoted strings handle special characters.
