## skytime run — Connection Variant Routing (cite pkg/cli/connect.go)

- `--api-key` set → cloud (NewCloudClient: API key + TLS)
- `--tls-cert + --tls-key + --tls-ca` set → self-hosted mTLS (NewSelfHostedClient)
- Partial mTLS (1 or 2 of 3) → friendly error before any client construction
- Otherwise → dev-server (TLSDisabled=true, NewDevClient)

    ## skytime run

    ### Synopsis

        skytime run <file.star> --flow <name> [--input <json>] [persistent flags]

    Source: `pkg/cli/run.go`.

    ### Motivation

    `skytime run` is the single command that takes a `.star` file from
    your laptop to a workflow execution on a Temporal cluster. It
    statically validates first (D4-07: validation failures NEVER reach
    a partially-started workflow), connects via the appropriate variant
    (`--api-key` → cloud, mTLS triplet → self-hosted, otherwise → dev),
    starts an embedded transient worker, dispatches the workflow, and
    streams progress back to your terminal — Bazel-style colored output
    by default, static line-per-event under `--verbose` or non-TTY.

    For production deployments where the worker runs as a long-lived
    daemon (not embedded in `skytime run`), import `pkg/worker` and
    write your own service binary. See [docs/cli-binary.md](../cli-binary.md)
    for the custom-CLI pattern that registers your extensions.

    ### Flags

    | Flag | Default | Purpose |
    |------|---------|---------|
    | `--flow` | (required) | Name of the flow to execute (must match a `flow(name=...)` declaration) |
    | `--input` | `{}` | JSON-encoded inputs map (parsed against the flow's `inputs={...}` schema) |

    Plus all persistent flags above. The connection variant is selected
    automatically:
    - `--api-key` set → Temporal Cloud (TLS implied per SDK v1.39+)
    - `--tls-cert + --tls-key + --tls-ca` all three set → self-hosted mTLS
    - Partial mTLS (1 or 2 of 3) → friendly error before any client construction
    - Otherwise → dev-server (TLSDisabled=true)

    Source: `pkg/cli/connect.go`.

    ### Exit Codes

    - `0` — workflow completed successfully
    - `1` — error rendered to stderr (parse error, validation error,
      workflow failed via top-level `fail(...)` or non-retryable
      activity error, connection failure)
    - `2` — usage error (missing `--flow`, malformed `--input` JSON)

    Errors render in Starlark-first format (`<file>:<line>:<col>:
    <message>`); `--debug` is the only path to Go internals (D4-18).

    ### Example

        skytime run examples/skeleton/expression_if.star \
            --flow check_user --input '{"user_id":"42"}'

    Renders as a multi-line live progress block while the workflow
    runs; collapses to a final summary line at completion. See
    [docs/getting-started.md](../getting-started.md) for the canonical

    - Architecture: [`docs/architecture.md`](../architecture.md) — parse/execute split
