## walkBody modifications (final form)

```go
func (i *interpreter) walkBody(ctx workflow.Context, body []dag.Node) error {
    savedIdx, savedTot := i.stepIdx, i.stepTot
    // Pre-count non-log siblings (Pitfall 7 / D-7.2.1-13).
    nonLogTotal := 0
    for _, node := range body {
        if _, isLog := node.(*dag.LogStep); !isLog { nonLogTotal++ }
    }
    i.stepTot = nonLogTotal
    defer func() { i.stepIdx, i.stepTot = savedIdx, savedTot }()
    nonLogIdx := 0
    for _, node := range body {
        if _, isLog := node.(*dag.LogStep); !isLog {
            nonLogIdx++
            i.stepIdx = nonLogIdx
        }
        // Log node: stepIdx unchanged (kind=log frames are suppressed in human mode).
        if err := i.walkNode(ctx, node); err != nil { return err }
    }
    return nil
}
```

## NonRetryableErr type-code taxonomy (new)

| Type code               | Trigger                                        | Position attribution        |
| ----------------------- | ---------------------------------------------- | --------------------------- |
| `LogMsgTypeError`       | MsgFn lambda returned non-string               | LogStep `n.Pos`             |
| `LogAttrsTypeError`     | attrs lambda returned non-dict                 | LogStep `n.Pos`             |
| `LogAttrsTooLarge`      | attrs dict has >32 entries                     | LogStep `n.Pos`             |
| `LogAttrKeyType`        | attrs dict key is non-string                   | LogStep `n.Pos`             |
| `LogAttrKeyShape`       | attrs dict key not identifier-shaped           | LogStep `n.Pos`             |
| `LogAttrKeyReserved`    | attrs dict key in `{level,msg,time,source}`    | LogStep `n.Pos`             |
| `LogAttrValueConvert`   | non-scalar value fails `bridge.FromStarlarkValue` | LogStep `n.Pos`          |
| `LogUnknownLevel`       | Defense-in-depth — unreachable in practice     | LogStep `n.Pos`             |

All seven codes are `temporal.NonRetryableApplicationError`; none retry. Position attribution always uses `n.Pos` (the source-level `log.<level>(...)` call site) — error attribution is at the consultant's call, not at the attrs lambda's def-site (mirrors `walkScript` precedent).

## Decisions Made

- **Helpers inlined in `walk_log.go`** rather than a separate `walk_log_helpers.go`. The total file is ~215 LOC and the helpers (`starlarkValueToSlogAttr`, `reservedSlogKeys`, `identifierShapeRe`, `maxLogAttrs`) are tightly coupled to the walker — splitting them would force readers to context-switch between two files to follow validation flow. Reverse the decision later if log-step needs grow beyond ~400 LOC.
- **`TestWalkLog_InterpolatedMsg` uses string input** rather than int. Temporal testsuite roundtrips InitState through JSON which coerces `int64` → `float64`; the desugarer's unconditional `str()` wrap then produces `"42.0"` for what would conceptually be `"42"`. This is testsuite-JSON behavior, not a walker bug. The int-coercion path through `starlarkValueToSlogAttr` is exercised separately by `TestWalkLog_AttrsScalarCoercion` which inspects the value AFTER walker coercion (state goes through `bridge.toStarlarkValue` → `starlark.MakeInt64` → walker reads as `starlark.Int` → coerced back to `int64`), not after JSON roundtripping.
- **Counter exclusion test inspects step_dispatch records directly** rather than the rendered human output. Plan 04's filter already suppresses kind=log frames in human mode, so a render-level test would conflate "exclusion in counter" with "exclusion in display." Producer-side inspection (asserting `total=2` and `idx={1,2}` on the script dispatches) cleanly separates the two concerns.
