## Accomplishments

- **Four `log.<level>` parse-time builtins** (`builtinLogInfo` / `builtinLogWarn` / `builtinLogError` / `builtinLogDebug` in `pkg/parser/builtins_log.go`) sharing a private `buildLogStep` helper. Each produces a `*dag.LogStep` carrying `Pos`, `Level`, `Msg`, optional `MsgFn` (from `desugarInterpolation` reuse), and optional `AttrsLambdaID` (from `captureLambda` reuse).
- **`assertLogMsgLiteralAt`** — re-parses cached file bytes via `defaultFileOptions().Parse`, locates the call by `positionsEqual(call.Lparen, callPos)`, and rejects when the first positional arg is not `*syntax.Literal` with `Token == syntax.STRING`. Required because `starlark.UnpackArgs` already evaluated the argument by the time the builtin runs — identifier-bound strings (`MSG = "hi"; log.info(MSG)`) cannot be distinguished from string literals from the `starlark.Value` alone, but the D4.1-22 `${ctx.expr}` desugarer needs the source-level template bytes.
- **`log` namespace registration** in `newParseTimeGlobals` (`pkg/parser/globals.go`) as a `*starlarkstruct.Module` carrying four attributes. Slotted alongside the existing 6 DSL primitives + `trigger` + `result` + `fail`. No collision with any existing extension namespace (`grep -rn "\"log\"" pkg/extension/builtin/` returns 0 hits).
- **`Parser.allLogSteps`** accumulator field added to the `Parser` struct in `pkg/parser/parser.go`. Populated by `buildLogStep` at construction time; consumed by the finalize pass.
- **`validateLogStepPlacement`** finalize pass in `pkg/parser/finalize.go`. Builds a `map[*dag.LogStep]bool` of nodes reached by walking `p.flows[*].Body`, then iterates `p.allLogSteps` and rejects any unclaimed entry as a module-scope orphan. Wired into the finalize chain at slot 5.6 (immediately after `validateResultPlacement`, before `validateIfCondExpressionShape`).
- **`walkBodyForLogSteps`** package-level helper that recurses into `IfCond.Then`, `IfCond.Else`, and `ForEachParallel.Steps` — confirmed via direct inspection of `pkg/dag/control.go` that these are the only Node kinds nesting bodies that could contain a `LogStep` (Step/Script/Result/Fail/CallFlow are leaf-like for this purpose).
- **15 sub-tests** added across two new test functions in `pkg/parser/builtins_log_test.go` and four new functions in `pkg/parser/finalize_test.go`:
  - Accept: literal × 4 levels (4 sub-tests), interpolated msg (1), with attrs lambda (1), empty msg (1), multi-line msg (1)
  - Reject: non-literal msg × 4 levels (4 sub-tests), malformed interpolation × 2 shapes (2)
  - Placement: module-scope rejection × 4 levels (4), inside-flow accept (1), inside-if_cond accept (1), inside-for_each_parallel accept (1)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Source-level string-literal enforcement**

- **Found during:** Task 1 RED phase
- **Issue:** The plan's `buildLogStep` sketch relied only on the `starlark.UnpackArgs` type-check (`msgVal.(starlark.String)`) to reject non-literal msg. That check is necessary but not sufficient: an identifier bound to a string (`MSG = "hello"`) reaches the builtin as a `starlark.String` — indistinguishable from a true literal at the `starlark.Value` boundary. The test `TestBuiltinLog_RejectNonLiteralMsg` (which the plan explicitly required) cannot pass without an AST-level check, because the D-7.2.1-17 contract is source-level ("msg must be a string literal"), not value-level.
- **Fix:** Added `assertLogMsgLiteralAt` to `pkg/parser/builtins_log.go` — re-parses cached file bytes via `defaultFileOptions().Parse` and asserts the first positional arg of the call is `*syntax.Literal{Token: syntax.STRING}`. Same shape as `block_fn_lint.go::classifyBlockFn` and `builtins.go::findResultValueArg` (both established re-parse patterns). Called from `buildLogStep` immediately after the type-level check.
- **Files modified:** `pkg/parser/builtins_log.go`
- **Commit:** `620f2ff` (folded into the Task 1 GREEN commit)

No other deviations. The plan's predicted shape — newTestParser test helper, `IfCond.Then/Else` + `ForEachParallel.Steps` recursion fields, marker-shape one-per-line convention — all matched the existing codebase exactly. No name collisions with extension namespaces (`grep -rn "\"log\"" pkg/extension/builtin/` returned 0 hits).
