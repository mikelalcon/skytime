## AST Walker — Both *ast.SelectorExpr AND *ast.Ident Coverage

Confirmed at `tests/firewall_execute_workflow_test.go::collectCallSites` (line ~176): the inner `switch fun := ce.Fun.(type)` has a case for each AST shape. The qualifier field is `""` (sentinel) for *ast.Ident and the package-qualifier name (e.g., `"flowlaunch"`, `"env"`) for *ast.SelectorExpr. The BuildWorkflowInput firewall filter accepts both:

```go
switch {
case cs.qualifier == "flowlaunch":
    filtered = append(filtered, cs)
case cs.qualifier == "" && cs.rel == "pkg/cli/server/web/flowlaunch/launch.go":
    // *ast.Ident in-package internal call — load-bearing third site
    filtered = append(filtered, cs)
}
```

Plus `require.Len(t, filtered, 3, ...)` locks the kind-by-site contract: if a future refactor moves the internal call OUT of the flowlaunch package (turning Ident into SelectorExpr, or vice versa), the count drops and the test fails loudly.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] AST walker matched testsuite env.ExecuteWorkflow as a third production site**
- **Found during:** Task 3 (first test run failed with `pkg/interpreter/replay_helper.go:374` as unexpected site)
- **Issue:** The plan said "AST walks every non-test .go file under pkg/ and cmd/, counts CallExprs whose Fun is a SelectorExpr with Sel.Name == 'ExecuteWorkflow'". This matched `env.ExecuteWorkflow` on `*testsuite.TestWorkflowEnvironment` inside `pkg/interpreter/replay_helper.go::RunOnceCapturing` — a Phase 5 D5-D1 replay-determinism helper that uses the Temporal SDK testsuite. That is NOT a `client.Client.ExecuteWorkflow` dispatch; it is the test environment's same-named method on a different type. The plan acknowledged "filter only SelectorExpr" as a load-bearing detail for BuildWorkflowInput but didn't anticipate this name collision for ExecuteWorkflow.
- **Fix:** Added a 3-line qualifier-name filter at the top of the `TestExecuteWorkflow_CallSiteCount` loop:
  ```go
  if cs.qualifier == "env" {
      continue  // *testsuite.TestWorkflowEnvironment.ExecuteWorkflow — not a client.Client dispatch
  }
  ```
  Documented in the test's docstring + inline comment. The same filter is applied in the defense-in-depth `seen` loop so the "site is missing" check works correctly.
- **Files modified:** tests/firewall_execute_workflow_test.go (Task 3 commit)
- **Verification:** Test passes; production seam still pinned at exactly 2 sites (run.go + launch.go). The filter is robust because the Temporal SDK testsuite docs canonically bind the receiver to `env` (mirrored across `pkg/interpreter/replay_helper.go`, `pkg/interpreter/*_test.go`, and Temporal docs).
- **Committed in:** 5f63ab9 (Task 3 commit)
