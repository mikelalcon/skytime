## Accomplishments
- New pkg/testing API surface: `WithCredentialHandler(h extension.CredentialHandler) Option` + `NewFakeCredentialHandler(map[string]extension.Credential) extension.CredentialHandler` constructor. Test authors can now do partial-mock testing — real handler resolves real creds for some actions, `OnActivity(...)` mocks the network for others. The Resolve() path under test matches production exactly.
- runConfig gains a `credHandler` field; mirrors the existing `exts` field pattern (Option closure → field assignment, consumed by harness when wired).
- pkg/cli/test.go now nil-guards and threads `cfg.credHandler` to `testingpkg.RunCLI` via `WithCredentialHandler(cfg.credHandler)`. Binaries built with `cli.WithCredentialHandler(h)` — or, post-Plan 01, `cli.WithCredfile(path)` — see their handler reach the `skytime test` subcommand without code changes. Cred-less binaries continue to work (nil guard preserves behavior).
- Five unit tests pin the contracts: Option-closure assignment, known-ID happy-path lookup, unknown-ID `errors.Is(err, extension.ErrUnknownCredential)` parity with `credfile.Resolver`, defensive map copy, and race-safe concurrent reads (100 goroutines under `-race`).
- D-7.4-11 OnActivity bypass preserved by NOT modifying the harness short-circuit logic — this plan only adds the surface; the handler is invoked ONLY by un-mocked activities (same as today). Existing tests that rely on `OnActivity` short-circuit see zero behavior change.

## Decisions Made

- **Defensive map copy at NewFakeCredentialHandler construction** (Task 1). Detaches handler from caller-side map mutations; pinned by `TestNewFakeCredentialHandler_DefensiveMapCopy`. No mutex needed because the handler is immutable after construction.
- **errors.Is parity with credfile.Resolver** via `fmt.Errorf("%w: %s (fake credential handler)", extension.ErrUnknownCredential, id)`. Pinned by `TestNewFakeCredentialHandler_UnknownIDWrapsErrUnknownCredential`. This is the key correctness guarantee: the activity classifier (`pkg/activity/classify.go`) treats the fake handler's unknown-ID failure as `NonRetryable` exactly as it does for the real `credfile.Resolver`. Production-vs-test error shapes match.
- **Unexported fakeCredentialHandler type**. The constructor `NewFakeCredentialHandler` is the only surface; tests can't bypass the safe path. Mirrors the `pkg/extension/schedules.FakeScheduleClient` precedent (exported because cross-package tests need it) — but here, the constructor returns the interface, not the concrete type, so the type itself can stay private.
- **Nil-guarded thread in pkg/cli/test.go**. When `cfg.credHandler` is nil (binary not built with `cli.WithCredentialHandler` / `cli.WithCredfile`), the `WithCredentialHandler` Option is NOT appended to the opts slice. This preserves zero behavior change for cred-less binaries — they continue to work exactly as before.
- **D-7.4-12 minimal threading honored**. Only `cfg.exts` and `cfg.credHandler` are threaded — NOT a whole-cfg snapshot. Future Options (e.g., `WithBuildID` from Plan 02) thread one-by-one as concrete tests demand them. No premature struct.
- **Optional Step 3 from Task 2 NOT taken**. The runConfig.credHandler field is defined and threaded but the runner's harness call sites (runOneFile / runOneFileCLI) are NOT yet wired to consume it. Per the plan's explicit guidance ("DO NOT re-architect the harness for this plan"), the API surface is the deliverable here; consuming-side wiring is deferred to a follow-up when a concrete partial-mock E2E test demands it. The 5 unit tests directly pin the surface contract without requiring the consumer-side wiring change.
- **D-7.4-11 OnActivity bypass preserved**. This plan only ADDS surface (Option + field + threading). The harness's existing `OnActivity(...)`-first dispatch is untouched, so existing tests that rely on the short-circuit see zero behavior change. The handler is invoked ONLY by un-mocked activities, exactly as today.
