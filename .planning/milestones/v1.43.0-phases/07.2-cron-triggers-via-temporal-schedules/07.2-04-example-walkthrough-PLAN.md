    ## Workflow ID format

    Cron-fired workflows have IDs shaped `{flow_name}/{trigger_pos_hash}-<timestamp>`:
    - `flow_name` — the trigger's flow.
    - `trigger_pos_hash` — first 8 chars of base64url-SHA256 of the trigger's source position in the .star file. Stable across boots.
    - `<timestamp>` — appended by Temporal Schedules itself for uniqueness (Pitfall 2 in our research notes).

    This means two backfilled runs at the same scheduled time DO NOT collide; Temporal generates a unique suffix per fire.

    ## Troubleshooting

    ### `core.cron: invalid 5-field POSIX cron "@hourly"`
    Macros (`@hourly`, `@daily`, etc.) are intentionally rejected. Use the explicit 5-field form: `0 * * * *` for hourly, `0 0 * * *` for daily.

    ### `core.cron: invalid timezone "Amrica/New_York"`
    IANA timezone name typo. Use `America/New_York` (note the spelling). Run `ls /usr/share/zoneinfo/` for the full list (or `timedatectl list-timezones` on Linux).

    ### `cron-reconcile failed: rpc error: code = PermissionDenied`
    The Temporal user/API key lacks `temporal:schedules:*` IAM permission. Grant the IAM role/policy on the namespace or use a higher-privilege credential.

    ### Schedule exists but no workflows fire
    Check that the worker is actually polling the same task queue the Schedule action references. `temporal schedule describe ...` shows the action's TaskQueue; verify it matches your `--task-queue` flag.

    ### `cron-reconcile applied: 0 creates, 0 updates, 0 deletes` but the cron config changed
    You probably edited the cron schedule but not the trigger position. The Schedule ID is computed from the trigger's `.star` line:col position; if the trigger declaration's position hasn't moved AND the canonical config bytes match, no Update fires. Try adding a blank line above the trigger declaration to force the position to shift, OR verify via `temporal schedule describe` that the canonical Memo matches your expected config.

    ## What this walkthrough did NOT cover

    - **Backfills.** Temporal supports `temporal schedule backfill` for catching up missed runs. Skytime's reconciler does NOT trigger backfills automatically — operator's call.

    - **Multi-replica reconciliation.** Set `--cron-reconcile` on ONLY one replica in your deployment. The flag IS the leader-election mechanism (D-7.2-10).

        fi

            cat "$SMOKE_ROOTDIR/server.log" || true
            exit 1
        fi
    done

        exit 1

                | grep -q 'smoke_cron'; then

            echo "[smoke] cron fired; workflow execution visible (waited ${i}s)"
            break
        fi
        sleep 1
    done
    if [[ -z "$FIRED" ]]; then
        echo "[smoke] FAIL: no workflow execution observed within 80s"
        temporal workflow list --address localhost:7233 || true
        exit 1
    fi

    echo "[smoke] PASS: cron trigger -> Schedule -> workflow execution end-to-end"
    exit 0
